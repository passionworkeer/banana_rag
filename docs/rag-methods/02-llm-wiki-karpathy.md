# 02 LLM Wiki（卡帕西 / Obsidian）

## 定义

Andrej Karpathy 提出的个人知识库工作流。Markdown 笔记 + AI 持续整理、学习、进化知识。核心思想是"知识复利"：问 → 答 → 答案变成新知识 → 下次问得更准。

## 关键特征

- 本地优先：所有笔记是本地 Markdown 文件，离线、免费、数据归己。
- 持续整理：每次新增素材时 AI 主动更新相关页面、生成摘要、补交叉引用。
- 复利效应：传统 RAG 是"问→答→结束"，LLM Wiki 是"问→答→沉淀→下次更准"。
- 图谱视图：Obsidian 自带图谱视图，可以直观看到知识之间的连接。

## 适用

- 个人或小团队知识管理。
- 100-200 篇文章规模（卡帕西原话）。
- 文章之间有交叉引用、概念复用价值。
- 长期持续积累的资料库。

## 局限

- 不适合海量文档：超过几千篇时维护成本剧增。
- Token 消耗高：一次 Ingest 5000 字文档约 500 tokens（包括生成摘要和更新相关页面），但 Query 也需要约 70k tokens，因为要给 LLM 足够上下文做推理。
- 依赖 Obsidian 工作流：要在 Obsidian 里查看和编辑。
- 自动化能力有限：知识整理仍需要 AI 定期触发，不是被动进化。

## 最小实现

1. 安装 Obsidian 并打开本地文件夹（如 `D:\mywork\self_obsidian`）。
2. 准备 `raw/` 目录，所有原始资料扔进去。
3. 用 Claude Code 进入目录并启用 Karpathy gist 的工作流。
4. 让 AI "读取 `raw/` 中所有文件，编译为一个 wiki"。
5. 打开 Obsidian 图谱视图查看连接。
6. 后续新资料扔到 `raw/`，重复步骤 4-5。

## 与传统 RAG 的本质区别

| 维度 | 传统 RAG | LLM Wiki |
|------|----------|----------|
| 知识状态 | 静态，文档进向量库就完了 | 动态，AI 持续整理 |
| 复用价值 | 每次问答独立 | 答案沉淀为新知识 |
| 关系 | 隐式，仅靠相似度 | 显式，AI 建立交叉引用 |
| 检索方式 | 相似度匹配 | 相似度 + 关联图谱 |
| 适合规模 | 海量 | 100-200 篇 |
