# 03 模型训练与对齐

## 1. 介绍一下 SFT 的核心流程，以及如何构建高质量、多样化的数据集

核心回答：

> SFT 是监督微调，用人工标注或高质量构造的指令-回复数据，让模型学会按目标任务输出。流程一般是：确定任务目标、准备数据、清洗去重、格式化成 instruction / response、训练、验证、迭代。

流程：

1. 定义要学什么能力。
2. 收集原始样本。
3. 清洗、去噪、去重。
4. 构造输入输出对。
5. 训练和验证。
6. 持续补坏例和困难样本。

数据集质量要点：

- 覆盖不同问题类型。
- 答案标准一致。
- 避免模板化重复。
- 增加难例和边界例。
- 保留任务真实分布。

## 2. SFT 的 loss 怎么写？为什么要 shift right？

核心回答：

> Causal LM 的训练目标是预测下一个 token，所以输入和标签要错位。模型看到前面的 token，去预测后面的 token，这就是 shift right / label shift 的原因。

直觉：

- 输入：`x1 x2 x3`
- 目标：预测 `x2 x3 x4`
- 模型在位置 `t` 只用前文信息预测 `t+1`

如果不 shift：

- 模型会“看答案做题”。
- 会破坏自回归训练目标。

## 3. LoRA 的原理是什么？秩 r 怎么选？推理时要不要挂 Adapter？

核心回答：

> LoRA 的核心是冻结原模型权重，只在部分线性层上增加低秩矩阵 `A` 和 `B` 来学习增量更新。这样只训练少量参数，就能完成领域适配或任务微调。

公式：

```text
W' = W + BA
```

其中：

- `W` 冻结
- `A` 和 `B` 可训练
- `r` 是低秩维度

怎么选 r：

- r 小：参数少、显存低，但表达能力可能不足。
- r 大：适配更强，但训练成本上升。
- 一般从小值开始做消融，再看效果和成本平衡。

推理时：

- 可以挂 Adapter 推理，也可以把 LoRA 合并回主权重。
- 如果追求部署简洁和低延迟，常见做法是 merge。

## 4. 全量微调和 LoRA 的显存差异怎么估算？

核心回答：

> 全量微调不仅要存模型权重，还要存梯度、优化器状态和激活值，显存开销很大。LoRA 冻结大部分参数，只训练少量低秩矩阵，显存压力小很多。

一般来说：

- 全量训练显存主要花在：
  - 参数
  - 梯度
  - optimizer state
  - activation
- LoRA 省掉了大部分参数梯度和优化器状态。

面试表达：

> 全量微调最贵的不只是参数本身，而是训练过程里的梯度和 Adam 状态。LoRA 通过冻结主干权重，把训练显存大幅降下来，所以更适合资源有限或多任务快速适配。

## 5. PPO 和 DPO 的主要区别是什么？KL 在里面起什么作用？

核心回答：

> PPO 是基于奖励模型和策略优化的在线强化学习方法，DPO 则把偏好优化转成直接的监督式目标，不再显式做 rollout 和 value 更新。KL 的作用是约束新策略不要偏离参考模型太远，防止模型训练发散或语言能力退化。

对比：

| 维度 | PPO | DPO |
|------|-----|-----|
| 训练形式 | 在线 RL | 偏好监督 |
| 是否 rollout | 通常需要 | 不需要 |
| 是否 value model | 需要 | 不需要 |
| 稳定性 | 较复杂 | 通常更稳 |
| 工程复杂度 | 高 | 低一些 |

KL 作用：

- 防止策略更新过猛。
- 保留基础语言能力。
- 约束新模型不要偏离参考模型太远。

## 6. 如果没有 Reference Model，做 DPO / RL 会怎样？

核心回答：

> 没有 reference model，训练很容易失去“基座约束”，模型会朝着偏好信号单边漂移，出现语言退化、过度迎合奖励、过拟合偏好数据等问题。

风险：

- 策略漂移太大。
- 生成风格失控。
- 训练容易 reward hacking。
- 泛化能力下降。

## 7. 在什么业务场景下，必须引入 RLHF 或 DPO？

核心回答：

> 当你的目标已经不是“答案对不对”，而是“更符合人类偏好、语气风格、决策边界、对话体验或复杂业务约束”时，就要考虑偏好对齐技术。比如客服语气、助手风格、复杂排序、内容安全和多轮交互体验。

适用场景：

- 回答需要符合偏好而非单一标准答案。
- 存在多种“都算对但体验不同”的输出。
- 需要减少有害、冒犯或不合规输出。
- 需要把人工偏好显式注入模型。

## 8. Reward 是怎么定义的？如何防止 reward hacking？

核心回答：

> Reward 应该尽量对应业务目标，而不是某个单一指标。设计时通常把正确性、格式、完整度、安全性、效率等信号组合起来，并加上约束和人工复核，防止模型钻空子。

reward hacking 常见表现：

- 模型学会讨好奖励模型，但答案不真实。
- 输出格式很好看，但事实错误。
- 为了高分重复关键词。

防止方法：

- 多指标组合。
- 加人工复核。
- 对抗样本和坏例测试。
- 定期更新 reward 规则。

## 9. 训练时出现“模型学歪了”怎么办？

核心回答：

> 先判断是数据问题、reward 问题还是训练超参问题。常见修正包括降低学习率、减少更新步数、加强参考模型约束、提高数据质量、加入难例和负样本。

排查顺序：

1. 检查数据是否有偏。
2. 检查 reward 是否被钻空子。
3. 检查学习率和 batch 是否过激。
4. 检查是否过拟合少量模式。

## 10. 如何构建偏好数据？正负样本怎么来？

核心回答：

> 偏好数据一般由同一个 prompt 对应多个候选回答，再由人工或模型评审选出更好的回答。正样本代表偏好输出，负样本代表不优输出。关键是偏好标准要一致，不能今天按“详细”选，明天按“简洁”选。

来源：

- 人工标注。
- 线上反馈。
- 规则过滤。
- LLM judge 辅助筛选。

注意：

- 正负样本要尽量来自同一问题。
- 负样本不能太烂，否则学不到边界。

## 11. DPO 的损失函数直观是什么意思？

核心回答：

> DPO 的目标是让模型对偏好回答的相对概率高于非偏好回答，同时不要偏离参考模型太多。直观上就是“更喜欢好的，不要过分偏离原来会说话的模型”。

表达方式：

- 提高 chosen response 的相对优势。
- 降低 rejected response 的相对优势。
- 保持对 reference 的约束。

## 12. 在 LoRA 训练里，冻结层是怎么选的？

核心回答：

> 一般冻结主干模型，只在 attention 的投影层和部分 FFN 上加 LoRA。是否加到所有层，要根据任务难度、数据规模和预算决定。数据少时更应保守，数据多且任务复杂时可加大覆盖。

常见策略：

- 先只加 q_proj / v_proj。
- 效果不够再扩到 k_proj / o_proj / FFN。
- 小数据先低秩，必要时调大 r。

## 13. 为什么有时 loss 下降了，但 F1 / acc 不涨？

核心回答：

> loss 是训练目标，F1 / acc 是任务指标，两者不一定完全一致。可能是类别不平衡、阈值没调、标签噪声、过拟合训练分布，或者训练目标和业务指标不一致。

排查：

- 看数据分布是否偏。
- 看评价阈值是否合理。
- 看是否过拟合训练集。
- 看训练目标和最终任务是否一致。

## 14. 数据不均衡会对 F1、acc 这些指标有什么影响？

核心回答：

> 数据不均衡时，accuracy 很容易虚高，因为模型只要猜多数类就能拿到不错的 acc，但 minority 类表现会很差。F1 更关注 precision 和 recall 的平衡，通常比 acc 更能反映真实效果。

建议：

- 看 macro-F1、weighted-F1、per-class recall。
- 必要时重采样或重权重。

## 15. LLM-as-a-Judge 有哪些偏见？怎么缓解？

核心回答：

> LLM Judge 常见偏见包括位置偏见、长度偏见、表述风格偏见和自我偏见。缓解方式是双盲、随机顺序、多裁判投票、规则校验和人工抽检。

偏见：

- 偏爱更长答案。
- 偏爱更流畅的表达。
- 对顺序敏感。
- 与自己风格相似时更容易给高分。

## 16. Ragas 里的 Faithfulness 和 Answer Relevance 怎么理解？

核心回答：

> Faithfulness 看回答是否忠于检索证据，Answer Relevance 看回答是否真正回应了问题。一个偏“是否有根据”，一个偏“是否答题切题”。

区分：

- 证据对但答跑题：Answer Relevance 低。
- 答得像真的但没根据：Faithfulness 低。

## 17. 微调数据怎么保证多样性和质量？

核心回答：

> 多样性靠覆盖不同任务、长度、格式和难度；质量靠去重、人工复核、坏例筛除和标注规范统一。不要只堆“标准答案”，还要有边界样本和困难样本。

## 18. 训练时怎么处理工具响应的 loss mask？

核心回答：

> 工具调用链路里，通常只让模型对需要学习的部分计算 loss，对工具返回原文、系统控制字段或不该学习的内容做 mask，避免模型把外部噪声学进去。

原则：

- 该学的学。
- 不该学的屏蔽。
- 控制字段别污染输出分布。

## 19. 为什么有时要做后训练里的 DPO / RLHF，而不是只做 SFT？

核心回答：

> SFT 解决“会不会做”，DPO / RLHF 解决“更偏好哪种做法”。当多个答案都大致正确，但你希望模型更符合人类偏好、语气、安全边界或业务目标时，后训练更有效。

## 20. 蒙特卡洛、先验概率、参考模型这些概念在训练里怎么理解？

核心回答：

> 蒙特卡洛本质是通过随机采样估计期望；先验概率是训练前对某些结果的初始信念；参考模型则相当于一个稳定基线，用来约束更新方向，防止优化过程把模型带偏。

## 21. 一般怎么判断该用 SFT、DPO 还是 RL？

核心回答：

> 如果任务有明确标准答案，优先 SFT；如果有偏好排序、多个可接受答案，优先 DPO；如果奖励信号稀疏、需要在线探索和长链路决策，才考虑 RL。

## 22. DPO 损失函数可以怎么解释？

核心回答：

> DPO 的目标是让模型在同一个 prompt 下更偏向 chosen，而不是 rejected，同时用 reference model 控制更新幅度。直观上，它优化的是“好回答相对坏回答的概率差”。

常见形式可理解为：

```text
loss = -log sigmoid(beta * [(log pi(chosen)-log pi(rejected))
                            - (log ref(chosen)-log ref(rejected))])
```

解释：

- `pi` 是当前模型。
- `ref` 是参考模型。
- `chosen` 是偏好答案。
- `rejected` 是非偏好答案。
- `beta` 控制偏好强度。

## 23. DPO 训练参数一般关注哪些？

核心回答：

> 重点关注 beta、学习率、batch size、序列长度、正负样本质量、是否 mask 非学习部分，以及 reference model 是否固定。

关注点：

- beta 太大：模型可能过度追求偏好。
- beta 太小：偏好信号弱。
- 学习率太高：模型漂移。
- 序列长度差异大：可能引入长度偏差。

## 24. 为什么选 GRPO？和 PPO 有什么差异？

核心回答：

> GRPO 常用于组内相对比较，通过一组输出之间的相对优势来优化策略，减少对 value model 的依赖。相比 PPO，它在一些大模型后训练场景里工程上更轻。

面试表达：

> 我会说选择 GRPO 的原因不是“更高级”，而是它更贴合相对比较任务，能用同一 prompt 的多条输出做组内排序，工程复杂度也比完整 PPO 链路低一些。

## 25. 如果 RL 每次 rollout 都随机不出正确答案，一直 0 分怎么办？

核心回答：

> 这说明奖励太稀疏或任务太难，模型没有学习信号。可以先用 SFT 打底，降低任务难度，引入分阶段 reward，或者提供部分正确奖励。

处理：

- curriculum learning
- dense reward
- 增加示范轨迹
- 先 SFT 再 RL
- 调整采样温度和候选数量

## 26. 微调 Qwen 时，训练阶段和 loss 函数怎么决定？

核心回答：

> 如果是让模型学任务格式和领域知识，用 SFT 的 causal LM loss；如果是让模型偏好某种回答风格或选择更优答案，用 DPO / RLHF；如果只是轻量适配，用 LoRA 或 QLoRA。

## 27. 蒸馏效果不好可能是什么原因？有没有做量化和加速？

核心回答：

> 蒸馏不好常见原因是 teacher 输出质量不稳定、student 容量不足、训练数据分布和线上不一致、蒸馏目标太难。量化和加速可以用 INT8/INT4、KV cache 优化、batching 和推理框架优化。

## 28. 7B 模型一般用几张卡训练？

核心回答：

> 这取决于训练方式。全量微调 7B 成本很高，通常需要多卡和显存优化；LoRA / QLoRA 则可以在更少显存上完成。面试时不要死背卡数，要说明和精度、序列长度、batch、优化器状态有关。

影响因素：

- FP16/BF16 还是 4bit。
- 全参还是 LoRA。
- sequence length。
- batch size。
- 是否用 ZeRO、FSDP、gradient checkpointing。

## 29. DPO 正反馈样例具体指什么？人工标还是线上来？

核心回答：

> 正反馈样例就是在同一输入下更符合偏好的回答，可以来自人工标注、线上点赞/采纳、专家评审或模型辅助筛选。高质量场景最好有人审，不要完全相信线上隐式反馈。

## 30. 长链路 GUI 任务里正负样本长度不一会有什么影响？

核心回答：

> 长度不一可能导致模型偏好更长或更短的输出，而不是真正偏好更正确的轨迹。需要做长度归一、按步骤比较、mask 无关部分，或者让 judge 明确忽略长度偏差。

## 31. 训练了几版模型？印象最深的 bad case 怎么答？

核心回答：

> 这类题不要只报数字，要讲一次迭代闭环：第一版问题是什么，怎么定位，第二版改了什么，结果有什么变化。bad case 最好选一个能体现你排查能力的例子。

答法：

> 我印象最深的是某类输入下模型格式正确但事实错误。我们先确认检索证据是否命中，再看训练样本里是否有类似模式，最后发现是负样本不足，于是补了对抗样本并调整评估集。

## 32. 看过 AutoGLM 或其他大模型论文吗？怎么回答？

核心回答：

> 面试时不要空泛说“看过很多”，选一篇讲清楚它解决的问题、方法和你能借鉴到项目里的点。AutoGLM 这类工作可以从 GUI Agent、任务自动化、工具调用和长链路执行来讲。

## 附录 A：训练与对齐超详细知识点

### A1. SFT 训练样本格式

一个标准 SFT 样本通常包含：

```json
{
  "instruction": "请解释什么是 RAG",
  "input": "面向企业知识库问答",
  "output": "RAG 是检索增强生成..."
}
```

对 chat model，常见会转成 messages：

```json
[
  {"role": "system", "content": "你是一个面试助手"},
  {"role": "user", "content": "解释什么是 RAG"},
  {"role": "assistant", "content": "RAG 是..."}
]
```

面试重点：

- SFT 学的是“给定输入输出什么”。
- 数据格式和任务边界比盲目堆量更重要。
- 高质量数据通常比低质量大规模数据更值钱。

### A2. Causal LM Loss 和 shift right

假设序列是：

```text
x = [x1, x2, x3, x4]
```

训练目标是：

```text
p(x2|x1), p(x3|x1,x2), p(x4|x1,x2,x3)
```

损失：

```text
L = - \sum_t log p(x_t | x_<t)
```

代码里通常：

```text
shift_logits = logits[:, :-1, :]
shift_labels = labels[:, 1:]
```

### A3. LoRA 参数量和显存

对一个线性层 `W in R^{d_out x d_in}`：

全量训练参数：

```text
d_out * d_in
```

LoRA 参数：

```text
r * d_in + d_out * r = r(d_in + d_out)
```

当 `r` 远小于 `d_in` 和 `d_out` 时，参数量大幅下降。

面试表达：

> LoRA 不是直接改原权重，而是学习一个低秩增量。它假设任务适配所需的权重变化可以落在低维子空间里。

### A4. PPO Clip 机制

PPO 关心新旧策略比值：

```text
r_t(theta) = pi_theta(a_t|s_t) / pi_old(a_t|s_t)
```

Clip 目标：

```text
L = min(r_t A_t, clip(r_t, 1-eps, 1+eps) A_t)
```

直觉：

- 如果新策略比旧策略变化太大，就截断。
- 避免一次更新把模型带偏。
- 提升 RL 训练稳定性。

### A5. DPO 和 PPO 的面试对比

| 维度 | PPO/RLHF | DPO |
|------|----------|-----|
| 需要 Reward Model | 通常需要 | 不显式需要 |
| 需要 Rollout | 需要 | 不需要 |
| 工程复杂度 | 高 | 较低 |
| 稳定性 | 调参复杂 | 相对稳定 |
| 输入数据 | prompt + reward | prompt + chosen/rejected |

一句话：

> PPO 是“先建奖励，再用强化学习优化策略”；DPO 是“直接从偏好对里学习哪个回答更应该被模型偏好”。

### A6. DPO 的 beta 怎么理解

`beta` 控制偏好优化强度：

- beta 太小：模型学不到明显偏好。
- beta 太大：模型可能过度偏向偏好数据，牺牲泛化。

可以这样答：

> beta 类似偏好信号的温度系数，调的是“让模型多强烈地区分 chosen 和 rejected”。

### A7. KL 散度在对齐里的作用

KL：

```text
KL(P || Q) = \sum_i P(i) log(P(i)/Q(i))
```

在对齐中：

- `P` 可以理解为新策略。
- `Q` 可以理解为参考模型。
- KL 越大，说明新模型偏离基座越远。

作用：

- 防止模型为了奖励学偏。
- 保留基础语言能力。
- 减少 reward hacking。

### A8. Reward Hacking 举例

例子：

> 如果奖励函数只奖励“答案包含引用编号”，模型可能学会每句话都加引用编号，即使引用内容并不支持答案。

解决：

- 奖励拆多维。
- 引入事实校验。
- 增加负样本。
- 人工抽检。

### A9. 偏好数据质量判断

高质量偏好数据应满足：

- chosen 和 rejected 差异明确。
- rejected 不是完全垃圾答案。
- 标注标准一致。
- 覆盖真实业务分布。
- 有边界样本。

低质量偏好数据的风险：

- 模型学到长度偏好。
- 模型学到格式偏好。
- 模型没有学到真正质量差异。

### A11. 数据不均衡时为什么 accuracy 会虚高

例子：

- 1000 条样本。
- 950 条是负类。
- 模型全预测负类。

结果：

```text
accuracy = 95%
```

但正类召回为 0，所以要看：

- macro-F1
- per-class recall
- confusion matrix

### A12. 训练排查 Checklist

| 现象 | 排查方向 |
|------|----------|
| loss 不降 | 学习率、数据格式、label mask |
| loss 降但指标不涨 | 指标不匹配、数据不均衡、阈值问题 |
| 输出格式乱 | SFT 样本格式不统一 |
| 幻觉变多 | 偏好数据或 reward 有偏 |
| 长文本变差 | sequence length、位置外推、截断 |
