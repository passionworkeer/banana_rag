一、Embedding 原理与选型

  • 核心思想：文本 → 高维向量，相似度 = 语义相似度
    • 原理：训练模型让"意思相近"的文本在向量空间里距离更近
    • 下游用途：检索（KNN）、聚类、分类、推荐、异常检测
  • 稠密 vs 稀疏：
    • 稠密（Dense）：BGE / M3E / OpenAI Embedding — 语义理解强，能捕捉同义改写
    • 稀疏（Sparse）：BM25 / SPLADE / TF-IDF — 关键词匹配强，OOV 鲁棒，可解释
    • 混合检索：两者加权融合（RRF 倒数排名融合 / 加权求和），效果通常优于单路
  • 主流模型：
    • 中文：BGE-M3（智源，1024 维，多语言）、M3E（MokaHR，开源）、Qwen3-Embedding
    • 英文：OpenAI text-embedding-3-small/large、Cohere embed-v3、e5-mistral-7b
    • 多语言：bge-m3（100+ 语言）、multilingual-e5-large
  • 选型维度：语言支持、向量维度、推理速度、领域适配、私有化能力、license
  • 训练细节：对比学习（InfoNCE / Triplet Loss）+ 难负例挖掘 + in-batch negatives
  • 评估方式：MTEB 榜单（公开 benchmark）+ 业务自建评测集（query-doc 相关性标注）

二、向量化流程

离线阶段把全量文档批量编码入库（耗时但一次完成），在线阶段只对 query 实时编码，然后做 ANN（近似最近邻）检索。优化重点：离线并行、在线 GPU batch 推理、向量库选 HNSW（高召回）或 IVF（低内存）。

三、相似度计算

$$\mathrm{sim}(q, d) = \cos\!\left(E(q),\, E(d)\right) = \frac{E(q) \cdot E(d)}{\|E(q)\| \cdot \|E(d)\|}$$

余弦相似度：把两个向量先 L2 归一化后算点积，范围 [-1, 1]，值越大越相似。检索中 0.7+ 通常算相关。

$$\mathrm{sim}(q, d) = E(q) \cdot E(d) \quad \text{（L2 归一化后等价于内积）}$$

工程优化：向量入库前先 L2 normalize，相似度退化为点积，FAISS / Milvus 都直接用内积做 ANN 检索，速度比余弦快一个数量级。

$$d(q, d) = 1 - \mathrm{sim}(q, d) \quad \text{（距离 = 1 - 相似度）}$$

向量库（FAISS / Milvus）内部把相似度转成距离用，HNSW 图用距离建边，检索时返回 Top-K 最近邻。

训练与微调

$$L = -\log \frac{\exp\!\left(\mathrm{sim}(q, d^{+})\right)}{\sum_{i} \exp\!\left(\mathrm{sim}(q, d_{i})\right)}$$

InfoNCE Loss：让正样本 $d^{+}$ 和 query 的相似度远高于 batch 内其他负样本 $d_{i}$。在 batch 内做负采样（in-batch negatives）可极大提升训练效率。

$$d^{-}_{\text{hard}} = \mathop{\mathrm{arg\,max}}_{d \in D^{-}}\, \mathrm{sim}(q, d) \quad \text{（难负例）}$$

难负例挖掘：随机负样本太"简单"，模型学不到细粒度差异。用 BM25 召回但 Embedding 给低分、或用上一版模型错分的样本当难负例。

微调数据 $= (q, d^{+}, d^{-})$ 三元组

构造方法：① 业务日志挖掘（query + 人工标的相关/不相关 doc）；② 大模型合成（GPT-4 生成 query，doc 库内取正负样本）；③ 对比学习数据集（如 ms-marco、BeIR）。

五、面试 FAQ

Q1：稠密 vs 稀疏怎么选？

A：通用 RAG 场景推荐混合（稠密 + BM25 7:3 起步），专业术语 / 代码搜索加大稀疏权重（5:5 或 4:6），纯语义理解（推荐 / 聚类）只用稠密。融合算法优先 RRF（reciprocal rank fusion），无需调参，效果稳定。

Q2：维度越大越好吗？

A：不一定。768 / 1024 是性价比甜点，更大（如 3072）边际收益递减但存储和计算成本翻倍。原则：MTEB 榜单上同模型不同维度档差距 < 2% 时选小维度。除非做大规模对比学习或极致精度需求，否则 1024 维足够。

Q3：怎么评测 Embedding 质量？

A：双轨评估：① 公开榜单（MTEB / BEIR / C-MTEB）— 看通用能力；② 业务自建评测集（~500 条 query-doc 标注对，含正负样本）— 看业务能力。指标用 NDCG@10 / MRR / Recall@K，最后看端到端 RAG 答案质量是否提升。

Q4：私有化怎么部署？

A：三个组件。① 模型推理：sentence-transformers 加载 BGE / M3E，Triton / vLLM 包装成 gRPC 服务；② 向量库：FAISS（单机）/ Milvus（分布式）；③ API 层：FastAPI 暴露 /embed 和 /search 接口。注意 GPU 显存（7B 模型 ~14GB）和 batch 推理优化。

Q5：Embedding 怎么微调？

A：对比学习（InfoNCE Loss）+ 难负例 + in-batch negatives。构造 (q, d+, d-) 三元组，d+ 是相关 doc，d- 是难负例（BM25 召回但 Embedding 给低分的）。batch size 越大 in-batch negatives 越多，128-512 是常见范围。微调 3-5 epoch，LR 1e-5 到 5e-5。

Q6：多语言场景怎么办？

A：首选多语言预训练模型（bge-m3 支持 100+ 语言，multilingual-e5-large，e5-mistral-7b-instruct）。中英混合场景 bge-m3 是性价比首选。极端多语言（50+）可考虑大模型蒸馏（用 GPT-4 多语言 embedding 蒸馏小模型）。

选型决策清单

选 BGE-M3 的场景

中文为主、需多语言支持（100+）、私有化部署、可接受 1024 维、Apache 2.0 商用免费。中文 RAG 首选，性价比最高。

选 OpenAI Embedding 的场景

云上快速接入、英文为主、对精度有极致要求（text-embedding-3-large 3072 维）、接受 API 成本（$0.13/1M token）、无私有化合规需求。

选 M3E 的场景

中文轻量场景、需 CPU 推理（资源受限）、768 维、速度快于 BGE。适合边缘设备或中小规模 RAG。

选 e5-mistral-7b 的场景

英文为主、追求最高精度（MTEB 榜 top 5）、有 7B 模型推理能力（单卡 A100 80G）、可接受 4096 维。学术和高精度推荐场景。
