Scaling Law：模型怎么变大才划算？

Scaling Law 描述了模型损失与参数量 (N) / 数据量 (D) / 算力 (C) 的幂律关系——Loss ∝ N^−α。Kaplan 2020 → Chinchilla 2022（20 token/参数最优）→ Compute-Optimal 2024 → Test-Time Scaling 2024（o1 开启）。本页把"3 大经典定律 → 涌现 vs 平滑 → Test-Time Scaling → 与推理算力关系 → 面试 FAQ"一次性串清楚。

一、为什么需要 Scaling Law

  • 训练投入巨大：GPT-4 训练成本 $50M+，Llama-3 405B $60M+，错配就是浪费
  • 预测收益：给定算力预算，怎么分配 N / D 才能 Loss 最低？
  • 可解释性：理解大模型为什么"大力出奇迹"——是参数、数据、还是算力驱动
  • 决策依据：① 买多少 GPU？② 训多久？③ 训完还能再 SFT 多大？
  • 2024 范式变化：Test-Time Compute 引入第四维度"推理时算力"，Scaling Law 扩展
一句话核心：Loss 和 N / D / C 呈幂律（Power Law），可预测、可外推；但分配比例不同时效率差异巨大（Chinchilla 修正 Kaplan 2-3x 效率差）。

二、Kaplan 2020 经典 Scaling Law

OpenAI 2020 首次系统化研究 Scaling Law：训练 Transformer 时，Loss 与 N / D / C 呈幂律关系。

核心公式（Kaplan 2020）

L(N) = (Nc / N)αN    αN ≈ 0.076

L(D) = (Dc / D)αD    αD ≈ 0.095

L(C) = (Cc / C)αC    αC ≈ 0.050

Nc, Dc, Cc 是常数（不可约损失 + 模型族相关）。α 是缩放指数，越大代表收益越快。

关键发现：① 模型越大，缩放效率越高（→ 鼓励训大模型）；② 数据 / 算力 也有独立贡献；③ Loss 可外推——训 1/10 规模可预测全规模表现。

三、Chinchilla 2022 修正

DeepMind 2022 严格控制算力实验，发现 Kaplan 结论"参数越多越好"是错的——实际是"算力一定时，N 和 D 要等比增长"。

Chinchilla 最优分配

Nopt ∝ C0.5    Dopt ∝ C0.5

每参数 20 token（最优）：D ≈ 20 × N

含义：模型参数量翻倍，训练数据也要翻倍，否则欠拟合 / 过拟合。

实验：Gopher 280B 用 280B token → Chinchilla 70B 用 1.4T token → 同样算力下 Chinchilla Loss 低 5.6%

结论：① 业界普遍"欠训"——大模型数据不够；② 训练 N 模型需 ≥ 20N tokens；③ GPT-3 175B 用了 300B token 是欠训的（应该 3.5T）。

五、Chinchilla vs Llama-3 的分歧

Llama-3 405B 用 15.6T tokens 训练（35:1 token/参数，远超 Chinchilla 20:1），这违反 Chinchilla 吗？

  • 不违反：Chinchilla 是"给定训练算力 C"的最优；Llama-3 故意"过训"（over-train），因为推理成本远高于训练成本
  • Over-train 的代价：训练时多花 10x 算力，但推理时同规模模型可以服务更多用户
  • Llama-3.1 修正：100M-405B 全系列 15.6T tokens 训练 → 小模型严重过训、大模型恰到好处
  • Qwen 2.5 / DeepSeek 策略：类似，过训 7B-72B 提升推理效率
2024 主流策略：① 早期模型按 Chinchilla 20:1 训；② 2024 后普遍"过训"（Llama-3 35:1、Qwen 2.5 30:1、DeepSeek-V3 60:1 接近）；③ 推理成本主导，过训更划算。Chinchilla 不是绝对真理，是"算力最优"。

六、Scaling Law 曲线与算力预算

横轴是训练算力（FLOPs），纵轴是 Loss。曲线越往后越平——Loss 收益递减，这就是"算力不够再翻倍意义不大"的根因。每 10x 算力降 ~12% Loss。

七、涌现能力（Emergent Ability）

某些能力在模型小到一定规模后"突然"出现，而不是平滑提升。OpenAI 2022 论文提出，2023-2024 引发争议。

支持涌现（Wei et al. 2022）

① 大模型在 BIG-Bench / MMLU 等任务上呈现"阶梯式"提升；② CoT / 推理 / 工具调用在 100B+ 才稳定出现；③ GPT-3 → GPT-4 跨度大、量变到质变。

反对涌现（Schaeffer 2023, "Are Emergent Abilities a Mirage?"）

① 涌现是"评估指标选择"的假象——换连续指标（如 token 编辑距离）后曲线变平滑；② 涌现依赖 strict-match / multiple-choice 指标；③ 模型实际能力是连续提升的。

2024 主流观点：① 大模型确有"质变"——CoT、Reasoning、Tool Use 在 70B+ 才稳定；② 但具体任务看指标选择，strict-match 易出现"阶梯"假象；③ Test-Time Compute（o1/R1）让"小模型 + 多思考"也能涌现推理能力。Scaling Law 仍是核心，但"涌现"被重新理解。

八、Test-Time Compute Scaling（2024 范式扩展）

OpenAI o1 (2024.9) / DeepSeek-R1 (2025.1) 引入第四个维度：推理时算力。给定 7B 模型，思考越久越准——Loss ∝ Inference FLOPs−β。

4 维 Scaling Law（含 Inference）

L(N, D, Ctrain, Ctest) = L0 + a · N−α + b · D−β + c · Ctest−γ

Ctest：推理时算力（CoT 长度、采样数、树搜索深度）

Snell et al. 2024 (OpenAI) 证明：固定训练 FLOPs 时，o1-style 模型可与 14x 训练算力的 GPT-4 持平。

意义：① 模型大小不再是唯一杠杆；② 推理时"慢思考"可补偿训练 FLOPs 不足；③ 部署时可"动态调整算力"——简单题快答，难题慢想。

  • Snell / OpenAI 2024：Test-Time Compute 可换 14x 训练算力（MATH 任务）
  • o1 / o3 (2024.9 / 2024.12)：内化 CoT，APM / CodeForces 显著提升
  • DeepSeek-R1 (2025.1)：开源，GRPO RL 训出内化长 CoT
  • Long CoT (10K-100K token)：难题准确率 5-10x 提升

2. Chinchilla Compute-Optimal (2022)

CoT 稳定：~7B → 13B → 70B 阶梯

Tool Use 稳定：~70B+

Reasoning / Code Competition：~300B+ 或 Test-Time Scaling

十、Scaling Law 实践含义

  • 算力预算决策：C 翻 10x → Loss 降 ~12%；C 翻 100x → Loss 降 ~23%
  • N / D 配比：默认 Chinchilla 20:1；推理主导场景可"过训"到 30-60:1
  • 小模型 + Test-Time：固定 7B 模型可"用思考换能力"（o1-mini 7B 风格）
  • 训练前预测：用小规模实验外推全规模 Loss（1% 算力预测 100% 表现）
  • 数据天花板：高质量数据 < 100T tokens 时不要盲训 1T 模型（数据不够）
  • 评估陷阱：bench 上"涌现"可能是指标选择假象，多用连续指标

十一、项目落地 / 业务场景

  • 算力分配决策：1B 预算训 70B 还是 7B+15T tokens？答：看推理 vs 训练算力比，QPS 100+ 选 7B，QPS 1 选 70B
  • 小模型做大：6B 模型 vs 70B 蒸馏——前者部署成本 1/10、latency 1/5、QPS 10x
  • 数据规模估算：要训 7B → 需要 ≥ 140B tokens；要训 70B → 1.4T+ tokens
  • Test-Time 应用：o1-style 模型用 CoT + Self-Consistency + Tree Search → 难题准度 +20pp

十二、面试 FAQ

Q1：Scaling Law 核心公式？

A：Loss = L∞ + a · N−α + b · D−β。Loss 与 N / D 呈幂律关系，α ≈ 0.076，β ≈ 0.095。每 10x 参数量 / 数据量 → Loss 降 ~12%。

Q2：Kaplan 和 Chinchilla 区别？

A：Kaplan 2020 结论"参数越多越好"，但实验同时变 N 和 D 不可靠。Chinchilla 2022 严格控制算力 → N ∝ D ∝ C0.5 → 20 token/参数最优 → Gopher 280B vs Chinchilla 70B 同算力 Loss 低 5.6%。

Q3：Chinchilla 20:1 比例还适用吗？

A：作为起点适用，但 2024 后普遍"过训"（Llama-3 35:1、Qwen 2.5 30:1）。过训在"推理成本 >> 训练成本"时划算（行业推理 QPS 大）。小模型 20:1，大模型 30-60:1 是 2024-2025 主流。

Q4：Test-Time Compute Scaling 怎么理解？

A：o1 / R1 引入第 4 维度——推理时算力。模型思考越久、采样越多、树搜索越深 → 准确率越高。OpenAI 2024 证明：固定 7B 模型 + Test-Time Compute 可达到 14x 训练算力的 GPT-4 水平（MATH 任务）。

Q5：涌现是真实现还是评测假象？

A：两者部分都对。① 真实现：CoT / Tool Use / Reasoning 在 70B+ 确实质变；② 评测假象：Schaeffer 2023 证明换连续指标后阶梯变平滑。结论：模型能力是连续提升的，但"易用"任务（strict-match）的"涌现"是真的能力跃迁。

Q6：怎么预测训一个 70B 模型需要多少算力？

A：训练 FLOPs ≈ 6 · N · D（每 token 6N FLOPs，N 参 D token）。70B × 1.4T = 6 · 70e9 · 1.4e12 = 5.88e23 FLOPs ≈ 5000 PFLOPs-day。H100 假设 50% MFU → 50000 张 H100 训 4 天 ≈ 200000 GPU-hours。

Q7：Scaling Law 还成立吗？

A：① Pre-training Loss 还在下降（Chinchilla 之外 Llama-3 405B Loss 1.40 vs Chinchilla 70B 1.50）；② 但"能力"维度（reasoning / agent）出现收益递减，需要新方法（Test-Time Compute / RL / Tool Use）；③ 2024-2026 是 pre-training + test-time + RLHF + agent 多维组合。

Q8：为什么大模型能"涌现"小模型做不到的能力？

A：① 参数量大 → 表征空间大，可学更抽象概念；② 数据量大 → 见过更多 pattern，可外推到新场景；③ 训练充分 → 多步推理、组合泛化能力涌现。本质：足够大的网络 + 数据 + 算力 = 通用逼近器。但"涌现"在指标选择下不绝对。

Q9：Train Compute vs Inference Compute 怎么权衡？

A：3 个场景：① QPS 高 / 延迟敏感 → 训大模型（一次成本高，多次摊销）；② QPS 低 / 准确率敏感 → 训小模型 + Test-Time（成本按需）；③ 部署成本敏感 → 蒸馏 + 量化。Snell 2024 实验：固定 QPS，小模型 + Test-Time 比大模型 + 标准推理便宜 2-10x。

Q10：训练数据不够时怎么办？

A：① 数据合成（Teacher 生成 / 改写）；② 数据增强（回译 / 释义）；③ 课程学习（先易后难）；④ 用更强 base + 更少数据（依赖泛化）；⑤ 降模型尺寸（Chinchilla 调整）；⑥ 关键：先看数据质量再扩量，质量 > 数量 1 个数量级时收益更大。

回答模板与加分项

30 秒电梯版

面试开场可以这样讲：Scaling Law 描述 Loss ∝ N−α · D−β，即 Loss 与参数 / 数据呈幂律。Kaplan 2020 开创，Chinchilla 2022 修正为"算力一定时 N 和 D 等比增长，20:1 最优"。2024 主流"过训"（Llama-3 35:1）以节省推理成本。OpenAI o1 开启 Test-Time Compute 范式——推理时算力可换能力，固定小模型 + 慢思考 = 14x 训练算力效果。2024-2026 是 4 维 Scaling（N/D/Ctrain/Ctest）。

5 分钟深入版

从动机（训练投入大 / 需预测收益）→ Kaplan 2020 公式 → Chinchilla 修正（20:1）+ Gopher 实验 → Compute-Optimal 框架 → 2024 过训趋势（Llama-3）→ 涌现 vs 平滑 → Test-Time Compute（o1/R1 范式）→ 4 维 Scaling → 业务落地决策。能讲清"为什么 Chinchilla 被 Llama-3 '违反' 仍合理"、"Test-Time 如何换 14x 训练算力"，立刻显得有真研究。

加分：知道 Scaling Law 局限

Scaling Law 不是银弹：① 预测的是"Loss"，不是"能力"——Loss 降到 1.5 不代表 AGI；② 涌现可能是评测假象（换指标后变平滑）；③ 边际收益递减——C 翻 10x 仅 Loss -12%，C 翻 100x 也只 -23%；④ 推理成本、数据质量、算法创新同样重要；⑤ Reasoning 维度（o1/R1）需 RL + Test-Time 共同驱动。

加分：能讲一次工程踩坑

比如：盲目照搬 Chinchilla 20:1 训 70B 模型，结果数据耗尽 Loss 不降——发现是过拟合 → 加 5T tokens 过训到 70:1，推理成本持平但 Loss 降 0.05；或用 7B 模型加 Test-Time Compute（CoT + Self-Consistency）替代 70B 推理，成本降 5x、准确率持平。讲清"理论 → 实际 → 调优"三步，面试官会立刻认定你有真经验。
