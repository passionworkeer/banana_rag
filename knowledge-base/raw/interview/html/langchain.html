LangChain：从原型到生产的 LLM 编排框架

LangChain 是 LLM 应用层最主流的 Python/TypeScript 框架（2022.10 至今 100+ 版本、800+ 集成）。它把"模型调用 + Prompt 模板 + 链式组合 + 工具调用 + 记忆 + 检索 + Agent"封装成统一抽象。LangChain v0.1 后核心是 LCEL（LangChain Expression Language）+ LangGraph 状态机 + LangSmith 可观测性。本页把"模块组成 → 6 大核心抽象 → LCEL 语法 → Agent 范式 → 选型与坑 → 面试 FAQ"一次性串清楚。

一、为什么需要 LangChain

  • 统一抽象：100+ 模型（OpenAI / Anthropic / Ollama / HuggingFace）、100+ 工具、50+ 检索器、20+ 向量库——一套代码切换
  • 链式组合：把 Prompt + LLM + OutputParser + Tool 组合成 Chain，LCEL 用管道符 `|` 串接
  • 标准模式：RAG、Agent、ChatBot、文档摘要等场景都有最佳实践模板
  • 可观测性：原生 LangSmith 集成，trace 调试、token 成本、延迟一目了然
  • 生态丰富：LangServe（部署）、LangGraph（状态机）、LangSmith（追踪）形成闭环
  • 代价：① 抽象层重、源码复杂；② 老 API（v0.0）→ 新 API（v0.1+ LCEL）迁移成本高；③ 简单场景过度封装
2024 后的 LangChain 不再是"长链式工具"——它已经演化为：LCEL（链式组合）+ LangGraph（状态机）+ LangSmith（可观测）三件套。核心是 LCEL，复杂流程用 LangGraph。

二、核心架构与 6 大模块

三、LCEL（LangChain Expression Language）核心

LCEL 是 v0.1+ 的统一组合语法，用 `|` 把 Runnable 串成链，支持流式、异步、批量、配置透传。

基础语法：管道符串接

prompt | model | parser

每一段都是 Runnable，输入输出类型严格匹配。Runnable 协议定义了 invoke / stream / batch / ainvoke / astream 五个标准方法。

from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_template("用一句话解释{concept}")
model = ChatOpenAI(model="gpt-4o-mini", temperature=0)
parser = StrOutputParser()

# LCEL：管道符串接
chain = prompt | model | parser

# 同步
print(chain.invoke({"concept": "Scaling Law"}))

# 流式（生产推荐）
for chunk in chain.stream({"concept": "Mamba"}):
    print(chunk, end="", flush=True)

# 批量
results = chain.batch([{"concept": "MoE"}, {"concept": "RLHF"}])

# 异步
result = await chain.ainvoke({"concept": "Agent"})

# RunnablePassthrough 注入 + RunnableParallel 并行
from langchain_core.runnables import RunnablePassthrough, RunnableParallel

chain = (
    RunnableParallel({
        "context": retriever,
        "question": RunnablePassthrough()
    })
    | prompt
    | model
    | parser
)

五、Agent 范式（ReAct / OpenAI Tools / Plan-Execute）

LangChain Agent v0.1 后核心是 create_* 工厂函数 + AgentExecutor。2024 推荐用 LangGraph 替代 AgentExecutor。

from langchain_openai import ChatOpenAI
from langchain.agents import create_tool_calling_agent, AgentExecutor
from langchain_core.tools import tool
from langchain_core.prompts import ChatPromptTemplate

@tool
def get_weather(city: str) -> str:
    """查询某城市天气"""
    return f"{city} 25度 晴"

tools = [get_weather]
model = ChatOpenAI(model="gpt-4o")

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个助手，可以使用工具回答用户问题"),
    ("placeholder", "{chat_history}"),
    ("human", "{input}"),
    ("placeholder", "{agent_scratchpad}")
])

# 工厂函数创建 Agent（v0.1+ 推荐）
agent = create_tool_calling_agent(model, tools, prompt)
agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

# 调用
result = agent_executor.invoke({"input": "北京今天穿什么合适？"})
print(result["output"])
关键变更：① v0.0 时代的 `initialize_agent` 已弃用；② v0.1+ 用 `create_*_agent` 工厂；③ 2024+ 推荐直接用 LangGraph 做 Agent 状态机（更可控、可观测、循环支持）。AgentExecutor 仍可用但路径有限。

六、RAG 完整链路（LangChain 实现）

from langchain_community.document_loaders import PyPDFLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_community.vectorstores import Chroma
from langchain_openai import ChatOpenAI
from langchain_core.runnables import RunnablePassthrough
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate

# 1. 加载
loader = PyPDFLoader("白皮书.pdf")
docs = loader.load()

# 2. 切片
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
splits = splitter.split_documents(docs)

# 3. Embedding + 入库
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Chroma.from_documents(splits, embeddings)
retriever = vectorstore.as_retriever(search_kwargs={"k": 4})

# 4. Prompt
prompt = ChatPromptTemplate.from_template("""
基于以下上下文回答问题：
{context}

问题：{question}
""")

# 5. LCEL 链
model = ChatOpenAI(model="gpt-4o-mini")
chain = (
    {"context": retriever, "question": RunnablePassthrough()}
    | prompt
    | model
    | StrOutputParser()
)

# 6. 调用
answer = chain.invoke("什么是 MoE？")

七、Memory 与对话管理

v0.1+ 推荐用 LangGraph 管理 Memory（state 中显式存 messages），不再用 Memory 类。但兼容老 API。

传统 Memory 类（v0.0 风格）

① ConversationBufferMemory：全量历史，O(n) 增长；② ConversationBufferWindowMemory：最近 K 轮；③ ConversationSummaryMemory：用 LLM 总结历史；④ VectorStoreRetrieverMemory：用语义检索历史。已不推荐，state 管理更稳。

LangGraph State（v0.1+ 推荐）

State Graph 中显式存 messages 字段，用 add_messages reducer 自动追加。生产中可加 checkpointing、time-travel、thread_id 多会话管理。Memory / 工具 / 决策都放 state。

八、LangSmith 可观测性

LangSmith 是 LangChain 的官方 SaaS 平台（langchain-ai/langsmith 仓库），做 trace / eval / hub / monitoring 四件套。

  • Trace：自动记录 Chain / Agent 每步输入输出、token、延迟、错误。LLM 应用的"X-ray"
  • Eval：内置 LLM-as-Judge、自定义 evaluator、人类标注、A/B
  • Hub：Prompt 模板版本管理、共享、对比
  • Monitoring：QPS / P99 延迟 / token 成本 / 失败率 dashboard
  • 集成：设置 `LANGCHAIN_TRACING_V2=true` + `LANGCHAIN_API_KEY=...` 即可，零侵入
import os
os.environ["LANGCHAIN_TRACING_V2"] = "true"
os.environ["LANGCHAIN_API_KEY"] = "lsv2_xxx"
os.environ["LANGCHAIN_PROJECT"] = "my-rag-app"

# 之后所有 chain.invoke() 都会自动 trace
result = chain.invoke("...")  # 在 LangSmith UI 看到完整执行链

九、LangServe 部署

把 Chain / Agent 包装成 REST API 的 FastAPI 框架。一行代码启动生产级 API 服务。

# serve.py
from fastapi import FastAPI
from langserve import add_routes
from my_chain import chain  # 你的 chain

app = FastAPI(title="My LLM App")
add_routes(app, chain, path="/chat")

# 启动：uvicorn serve:app --host 0.0.0.0 --port 8000
# 调用：curl -X POST http://localhost:8000/chat/invoke -d '{"input": {...}}'
# 自动获得 /invoke /stream /batch /playground 等端点
LangServe 不是生产首选——简单 demo 可用，生产建议：① FastAPI 自研 + LangChain 作为库调用；② LangGraph Platform（2024+ 推出）；③ vLLM / Ollama 部署 openai 兼容 API + LangChain 客户端调用。

十二、面试 FAQ

Q1：LangChain 核心是什么？

A：6 大核心抽象（ChatModel / Prompt / OutputParser / Tool / Retriever / Memory）+ LCEL 管道符串接 + LangGraph 状态机 + LangSmith 可观测。2024 后核心是 LCEL + LangGraph 两件套。

Q2：LCEL 优势？

A：① 统一接口（invoke / stream / batch / ainvoke / astream）；② 自动支持流式输出（生产关键）；③ 类型安全（input/output schema）；④ 透明透传 callbacks / config；⑤ 简单语法（`prompt | model | parser`）。

Q3：LangChain vs 直接调 OpenAI SDK？

A：① 简单单轮 → 直接调 SDK 更轻；② 多步 / 工具 / RAG → LangChain 节省 50%+ 代码；③ 切模型（OpenAI → Claude → Ollama）→ LangChain 改 1 行；④ 100+ 集成（向量库 / 文档 / 工具）→ 不用自己写适配。

Q4：v0.0 老 API 和 v0.1+ 区别？

A：v0.0：LLMChain / AgentExecutor 老版，type 不严格，依赖混乱。v0.1+：① 拆分 langchain-core / langchain / langchain-community；② 引入 LCEL 统一链式；③ 类型注解 + Pydantic 严格；④ LangGraph 接管复杂流程。生产必升 v0.1+。

Q5：LangChain Agent 怎么选？

A：① 简单 tool calling → create_tool_calling_agent + AgentExecutor（OpenAI 风格）；② 复杂 ReAct → create_react_agent；③ 任何循环 / 中断 / 状态机 → LangGraph。生产首选 LangGraph。

Q6：LangChain 怎么和 LangGraph 配合？

A：① LangGraph 内部用 LangChain 的 ChatModel / Tool / Retriever；② LCEL 链可以作为 Graph 的一个 Node；③ LangGraph 负责状态流转，LangChain 负责单步执行；④ LangSmith 同时 trace 两者。两者是上下层关系，不是替代。

Q7：LangSmith 怎么集成？

A：① 设置环境变量 LANGCHAIN_TRACING_V2=true + LANGCHAIN_API_KEY；② 所有 chain.invoke() / agent.invoke() 自动 trace；③ 在 LangSmith UI 看树状执行流 + token 统计；④ 自定义 evaluator 做 A/B 评估。零侵入。

Q8：LangChain 性能怎么样？

A：v0.1+ 比 v0.0 提升 2-5x，主要靠：① 减少 import（按需加载 community）；② LCEL 编译优化；③ 内部用 Pydantic v2。生产中 RAG latency 50-300ms、Agent 500-3000ms，瓶颈在 LLM 而非框架。

Q9：LangChain 怎么和向量库配合？

A：① VectorStore 抽象统一接口（Chroma / Pinecone / Milvus）；② `.as_retriever()` 直接拿到 retriever；③ MultiQueryRetriever / ContextualCompressionRetriever / SelfQueryRetriever 等高级 retriever 包装；④ RAG chain 拼装 `retriever | prompt | model | parser`。

Q10：什么时候不用 LangChain？

A：① 简单单轮 prompt → OpenAI SDK 更轻；② 极致性能场景 → 框架有 overhead；③ 团队不熟悉 Python → 低代码（Dify / Coze）；④ 科研实验（要控制每个细节）→ 自己写；⑤ 已有 v0.0 老代码迁移成本高 → 评估升级 ROI。

回答模板与加分项

30 秒电梯版

面试开场可以这样讲：LangChain 是 LLM 应用层最主流的 Python 框架，2024 后的核心是 LCEL（管道符 | 串 Runnable）+ LangGraph（状态机 Agent）+ LangSmith（可观测）三件套。6 大抽象：ChatModel / Prompt / OutputParser / Tool / Retriever / Memory。生产 RAG / Agent / ChatBot 都用它，单服务支持 100+ QPS。优势是 100+ 集成 + 链式组合，劣势是抽象层重、过度封装、版本迁移成本。

5 分钟深入版

从动机（统一抽象 / 多集成）→ v0.0 → v0.1+ 架构变化（core/langchain/community 拆分）→ LCEL 管道符 + Runnable 协议 → 6 大核心抽象 → Agent 范式（create_tool_calling_agent / ReAct）→ RAG 完整链路 → Memory 与 LangGraph State → LangSmith Trace → 选型与避坑。能讲清"为什么 v0.1+ 拆 3 个包"、"为什么 LangGraph 替代 AgentExecutor"，立刻显得有真经验。

加分：知道 LangChain 局限

LangChain 不是银弹：① 抽象层重，简单场景过度封装；② v0.0 → v0.1 迁移成本高；③ 框架 overhead 影响极致性能；④ 老 API（LLMChain / AgentExecutor）已弃用；⑤ Memory 类被 State 替代；⑥ LangSmith 是付费 SaaS；⑦ 复杂 Agent 仍需 LangGraph；⑧ 中文文档少。

加分：能讲一次工程踩坑

比如：用 v0.0 的 LLMChain + 老 AgentExecutor 上线客服，发现：① 老 Memory 类 token 爆炸；② 流式输出不工作；③ Agent 循环没终止条件烧 token；④ 没有 trace 难调试 → 升级 v0.1+ 用 LCEL + LangGraph State + LangSmith，token 成本 -40%、bad case 排查时间 -90%。讲清"老 API 问题 → 升级 → 收益"三步，面试官会立刻认定你有真经验。

LCELLCEL 怎么流式输出？答"Runnable stream 协议"：用 `chain.stream(input)` 替代 `chain.invoke(input)`，每段输出 chunk 增量返回。LCEL 链中所有 Runnable 默认支持流式，无需额外配置。生产中是 token-by-token 体验关键。
AgentAgentExecutor vs LangGraph 选哪个？答"按复杂度"：简单 tool calling（≤5 步）用 AgentExecutor 快；复杂循环 / 状态 / 中断 / 多 Agent 必用 LangGraph。LangGraph 是 AgentExecutor 的超集，可观测性、循环、人介入都更优。2024+ 推荐 LangGraph。
RAGRAG 用 LangChain 还是 LlamaIndex？答"按场景"：纯文档 RAG（重检索 / 索引）→ LlamaIndex（API 更丰富）；RAG + Agent / 工具 / 多模态 → LangChain（生态更全）。生产中常组合：LlamaIndex 做索引 + LangChain 做 Agent。
MemoryMemory 类用哪个？答"按版本"：v0.0 用 ConversationBufferWindowMemory（最近 K 轮）；v0.1+ 用 LangGraph State + add_messages reducer。Memory 类已不推荐，State 更可控。生产中 State + checkpointing 多会话管理。

选型什么时候不用 LangChain？答"按场景"：① 简单单轮 → OpenAI SDK；② 极致性能 → 自己写；③ 不熟 Python → Dify / Coze 低代码；④ 科研实验 → 自己写控制；⑤ v0.0 老代码 → 评估升级 ROI。
