Router：把任务分给最合适的模型 / 工具 / Agent

Router 是 Agent 系统的"调度中心"——根据用户意图、上下文、风险等级，把任务路由到合适的下游（不同模型 / 工具 / 子 Agent / 人工）。工业界主流三类：规则 Router、LLM Router、Embedding Router。本页讲清路由维度、决策框架、常见失败模式（路由错了比答错了更糟糕）。

一、Router 在 Agent 系统中的位置

二、3 类主流 Router

  • 规则 Router：关键词 / 正则 / 意图分类器（BERT）匹配
  • LLM Router：用 LLM 判意图（如 Function Call 输出结构化路由）
  • Embedding Router：对 query embedding 与候选 route 描述算相似度
Hybrid 路由：先规则粗筛 → LLM 精排。工业界最常见组合，平衡速度与准确度。

三、5 维路由决策

  • 意图：用户想做什么（QA / 任务 / 闲聊 / 投诉）
  • 复杂度：是否需要多步推理、检索、工具
  • 风险：是否涉及支付、删除、隐私等不可逆动作
  • 用户身份：VIP / 普通 / 黑名单 / 内部员工
  • 成本/质量：是否需要大模型 / 是否能容忍低质量

四、Cascade 路由（成本优化的核心模式）

Cascade 路由省 60-80% token 成本（简单问题小模型答，复杂问题升级）。关键是"何时升级"——可看置信度阈值、self-eval 分、或下游 RAG 召回率。

五、Embedding Router 实现

典型实现：
  1. 为每个 route 准备一段描述（如"处理订单查询"）
  2. 离线对所有 route 描述生成 embedding
  3. 在线对用户 query embedding → 算与所有 route 的余弦相似度
  4. Top-1 或 Top-k 即路由目标

优点：成本低、速度快、可解释（看相似度分布）；缺点：长尾意图（"我要退货 + 改地址"）难分清。生产常配 LLM Router 兜底。

六、LLM Router 实现

典型实现：
  1. 用 Function Call 把 routes 定义为函数
  2. LLM 看用户 query → 输出结构化路由决策
  3. 配 fallback："if no route matches, ask user"

优点：理解复杂意图、可处理多意图；缺点：贵（每次 LLM 调用）、慢。生产中常用于"Embedding Router 不确定时升级"。

七、面试 FAQ

Q1：路由错了和答错了哪个更糟？

A：路由错更糟——它把整个任务交给错误的下游，错误会被下游放大，且常无法被"自我纠错"。生产监控重点是"路由准确率"而非"下游模型回答质量"。

Q2：Router 怎么选类型？

A：意图明确、类别少（<20）、标签易得 → 规则 / 分类器；意图模糊、类别多、需多步推理 → LLM Router；类别多但描述清楚、成本敏感 → Embedding Router。生产中 Hybrid 最常见（规则 + LLM 兜底）。

Q3：Cascade 路由怎么设阈值？

A：从小模型置信度 / self-eval 分中找拐点。方法：① 看下游人工评估准确率 vs 阈值关系；② 固定"升级率"目标（如 20%）；③ 监控 P95 延迟，确保大模型兜底不超时。阈值经验 0.7-0.85 看具体任务。

Q4：Router 评估指标有哪些？

A：① 路由准确率（路由到正确下游的比例）；② 路由延迟（Router 自身的耗时）；③ 下游任务完成率（路由对了之后下游能否完成）；④ 成本节省（Cascade 路由省了多少 token）。最关键是 ① + ③。

Q5：Router 怎么支持新增下游？

A：① 规则 Router：加正则 / 关键词；② Embedding Router：加 route 描述（无需重训）；③ LLM Router：更新 Function Call schema 即可（无需重训）。Embedding 和 LLM Router 扩展性更好，但需要 prompt / 描述质量高。

Q6：Router 怎么避免"全打到大模型"？

A：3 个手段：① 阈值卡紧（自评 < 0.7 才升级）；② 路由多样性约束（同一 session 强制先走小模型）；③ 监控"升级率"指标，异常飙升时降级。避免"小模型永远不答，全都大模型兜底"的退化。

Q7：Multi-Agent 系统的 Router 怎么设计？

A：常用两层：① 大 Router 把任务分给子 Agent 组；② 每个子 Agent 内部又有小 Router 分任务到工具/模型。和 CrewAI 的"Role + Task"、AutoGen 的"GroupChat"对应。设计原则：Router 决策应基于"能力描述"而非"代码逻辑"。

Q8：怎么避免 Router 成为单点故障？

A：① Router 自身做高可用；② 加 fallback 路径（Router 挂了走默认模型）；③ Router 决策可被下游否决（"我不该被路由到这里"）；④ 监控 Router 决策分布，异常时报警。

八、回答模板与加分项

30 秒电梯版

Router 是 Agent 系统的调度中心，按意图 / 复杂度 / 风险 / 用户身份 / 成本 5 维决策把任务路由到下游。3 类主流：规则、LLM、Embedding Router。工业界最常见 Cascade 路由（小模型先答、不确定再升级大模型），省 60-80% 成本。关键风险是路由错——比答错更糟，因为错误会被下游放大。

5 分钟深入版

从动机（不同任务适合不同下游）→ Router 在 Agent 系统中的位置 → 3 类 Router（规则 / LLM / Embedding）对比 → 5 维路由决策 → Cascade 路由实现 → Embedding Router 和 LLM Router 实战代码 → 评估指标 → 单点故障防护。能讲清"为什么 Cascade 是工业标准"、"为什么 Router 错比答错更糟"，立刻显得有真经验。

加分：项目案例

讲一次"Cascade 路由省成本"——比如客服系统 70% 问题简单（"查订单"、"改地址"），Sonnet 答得稳；剩 30% 复杂（"投诉升级"、"退换纠纷"）才上 Opus。Hybrid Router 后月度 token 成本从 $5 万降到 $1.5 万，用户满意度反而 +5%。

加分：知道局限

Router 不是银弹：① 路由错比答错更糟（错误被放大）；② Embedding Router 长尾意图分不清；③ LLM Router 成本高；④ Cascade 阈值难调。诚实说"Router 是 Agent 系统的咽喉，必须有 fallback 路径"得分更高。
