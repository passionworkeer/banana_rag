长上下文工程：把 4K 推到 128K / 1M 的全套技术

从 4K 到 128K 再到 1M 上下文，挑战不止"显存够不够"——位置编码外推、注意力退化、中间信息丢失、推理成本 4 段增长。本页讲清 RoPE 插值、YaRN、LongLoRA、滑动窗口、渐进压缩、Needle-in-Haystack 评测，构成完整长上下文技术栈。

一、长上下文的 4 重挑战

二、RoPE 位置编码

$$\mathrm{RoPE}(q, m) = R(m \cdot \theta) \cdot q$$

R(θ) = 旋转矩阵

$$\theta_{i} = 10000^{-2i/d}$$

— — —

m = token 位置

训练时 $m \in [0, L_{\text{train}}]$

推理时 $m \in [0, L_{\text{infer}}]$

$L_{\text{infer}} > L_{\text{train}} \;\Rightarrow\;$ 外推

外推后高频位置编码出现"未见过的角度"

RoPE 优势：相对位置、相邻距离敏感、长度泛化。但直接外推到远超训练长度会失效。

三、Position Interpolation（PI）

核心思想：把超长位置"压缩"到训练时见过的范围

— — —

$$m' = m \cdot \tfrac{L_{\text{train}}}{L_{\text{infer}}}$$

$$R(m' \cdot \theta) = R(m \cdot \theta \cdot \text{scale})$$

$$\text{scale} = \tfrac{L_{\text{train}}}{L_{\text{infer}}}$$

— — —

例：L_train=4K, L_infer=32K

scale = 1/8

所有位置编码角度 × 1/8

优点：4K 训练好的模型可推到 32K，仅需 ~1K 步微调。缺点：高频信息略损。

四、YaRN（Yet another RoPE extensioN）

YaRN = NTK-aware 部分 PI + attention 温度调整。保留高频、压缩低频。

对 RoPE 不同频率分量用不同 scale：

· 高频（短距离）：不变，保留局部信息

· 低频（长距离）：用 PI 压缩

· 临界频率：ramp function 平滑过渡

— — —

额外：attention logits 除以温度 t

$$t = 0.1 \cdot \ln(L_{\text{infer}} / L_{\text{train}}) + 1$$

效果：4K 训练模型无需微调直接推 128K，效果接近从头训练 128K 模型。Llama-3 / Qwen-2.5 都用 YaRN 思想。

五、LongLoRA / 滑动窗口 / 渐进压缩

  • LongLoRA：训练时用 shift sparse attention 模拟长注意力，比全 attention 训练省 2-3x 显存
  • Sliding Window：Mistral 风格，每层只看固定窗口（4K-8K），但多层叠加等效长程
  • Attention Sink：StreamingLLM 思想，前 4 个 token 永远保留，注意力"锚"在头
  • 渐进压缩：长 context 旧部分做摘要 / 压缩，保留关键信息
  • Memory Bank：把超长 context 存外部 KV 库，按需 retrieve

六、Needle-in-Haystack 评测

把"关键事实"插入到长文本的不同位置，看模型能否准确 retrieve：

  • 深度（Depth）：needle 在文本中的相对位置 0-100%
  • 长度（Context Length）：4K / 8K / 16K / 32K / 64K / 128K
  • 评测：模型 recall 准确率，画成热力图（绿=全对，红=错）
"Lost in the Middle"现象：针放在 50% 位置时 recall 显著低于 0% 或 100%。这是 LLM 的固有缺陷，需要 prompt 设计（"请特别关注中间内容"）或检索增强缓解。

八、面试 FAQ

Q1：RoPE 为什么比绝对位置编码更易扩展？

A：RoPE 把位置信息编码为"旋转向量角度"，是相对位置性质。相对位置泛化能力更强（短距离关系可迁移到长距离）。绝对位置编码在未见过的位置上是"完全陌生"的 embedding。

Q2：PI 和 YaRN 区别？

A：PI（Position Interpolation）对所有 RoPE 频率用相同 scale 压缩，简单但损失高频信息。YaRN 只压缩低频、保留高频，再加 attention 温度调整。YaRN 效果更好，是目前主流。

Q3：Lost in the Middle 怎么缓解？

A：4 个手段：① RAG 检索 + 重排序，把关键信息放在 context 头尾；② prompt 显式提示"中间段落也有重要信息"；③ 多 chunk 并行召回投票；④ StreamingLLM 注意力 sink 保留"头尾"信号。

Q4：长上下文推理成本怎么控？

A：5 个手段：① FlashAttention IO 优化；② KV Cache 量化（INT4/INT8）；③ Sliding Window 限制 attention 范围；④ 渐进压缩 / 摘要；⑤ RAG 替代部分 context 注入。128K 实测可比朴素 4x-8x 加速。

Q5：Mamba / SSM 真能替代 Transformer 长上下文？

A：部分场景。Mamba 的状态空间模型 O(1) 推理 / O(N) 训练，长序列优势明显。但 Mamba 在"精确检索"任务上比 Transformer 弱（Mamba-2 / Jamba 混合架构在追赶）。生产上 128K+ context 仍是 Transformer 为主 + 各种 trick。

Q6：怎么评估长上下文真的"工作"？

A：4 个层面：① Needle-in-Haystack（基本 retrieval）；② 多跳问答（需要综合多处信息）；③ 长程依赖（位置 N 的 token 引用位置 M 的事实）；④ RULER 基准（综合 13 种长 context 任务）。单看 NIAH 容易被"hacked"——简单 regex 也能命中。

Q7：长 context 训练数据怎么准备？

A：3 步：① 收集长文档（书籍 / 长报告 / 代码仓库）；② 续写式训练（按 chunk 切，loss 算全段）；③ 混合短长数据（防遗忘）。LongLoRA / Long-Context 论文都有具体 recipe。

Q8：为什么 1M context 至今没普及？

A：3 个核心困难：① 训练成本指数涨（高质量长程数据稀缺）；② 推理成本高（KV Cache 巨大）；③ 评估困难（1M 真用起来的场景少）。多数"宣称支持 1M"的模型实际 64K 后效果明显掉。

九、回答模板与加分项

30 秒电梯版

长上下文工程 = 4 重挑战（位置编码 / 注意力退化 / 计算成本 / 评估）+ 4 大技术（RoPE 插值 / YaRN / 滑动窗口 / 稀疏注意力）。PI 和 YaRN 让 4K 模型可推 128K；LongLoRA / StreamingLLM 解决注意力退化；NIAH 是评测基准但不够，需多跳问答。生产上 32K+ 多用 RAG 替代纯长 context。

5 分钟深入版

从动机（4K 够用吗？长文档 / 长视频 / 多轮对话）→ RoPE 原理 → PI / YaRN 解决位置外推 → Lost in the Middle 现象 → FlashAttention + 稀疏 + 滑动窗口解决成本 → 4 层评估（NIAH / 多跳 / 长程 / RULER）→ 实战决策树。能讲清"为什么 YaRN 优于朴素 PI"、"为什么 1M context 至今没普及"，立刻显得有真经验。

加分：项目案例

讲一次"4K → 32K 上下文扩展"——比如 Llama-2-7B 用 YaRN 推 32K：① 准备 5K 条 32K 长程 QA 微调数据；② YaRN 缩放 scale=1/8；③ 1 epoch 训练；④ NIAH 评测 0%-100% depth 全 95%+；⑤ 推理 KV Cache 用 INT4 量化省一半显存。

加分：知道局限

长上下文不是银弹：① 真用起来的场景少（多数是 RAG 替代）；② 1M 上下文至今没广泛普及；③ NIAH 评测容易被 hack；④ Lost in the Middle 是固有缺陷。诚实说"32K-128K 是甜区，超出后 RAG + 短 context 更经济"得分更高。
