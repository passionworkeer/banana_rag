Reward Model：把"好回答"转成可优化分数

Reward Model（RM）是 RLHF 的"中间件"——把人类主观偏好转成可微分的标量分数。核心是 Bradley-Terry pairwise loss、scalar head 替换 LM head、Reward Hacking 的识别与防控。RM 训不好，PPO 全盘崩；RM 训得太死板，模型学会刷分。本页讲清训练原理、常见偏差、评估方法。

一、RM 架构与训练流程

φ(x, y) ∈ R 标量奖励 偏好对 (y_w, y_l) y_w 比 y_l 更好 分别打分 r(y_w) 和 r(y_l) Pairwise Loss −log σ( r(y_w) − r(y_l) ) 要求 r(y_w) > r(y_l) 关键设计 · LM head 替换为 scalar head · RM 大小 = LLM（同 7B） · 显存独立（PPO 阶段 14GB）

二、Bradley-Terry 偏好模型

$$P(y_{w} \succ y_{l} \mid x) = \sigma\!\left(\, r(x, y_{w}) - r(x, y_{l}) \,\right)$$

$$\sigma(z) = \tfrac{1}{1 + e^{-z}}$$

— — —

$$L_{\text{RM}} = -\mathbb{E}\!\left[\, \log \sigma(\Delta r) \,\right]$$

$$\Delta r = r(y_{w}) - r(y_{l})$$

假设：人偏好某回答的概率，等于 RM 给两回答分数差经过 sigmoid 后的结果。推导基础是 pairwise 比较模型（Elo 评分前身）。

优点：不需要绝对分数标签，只需要相对排序——标注更省事。

三、训练数据 4 类来源

  • 人类排序：标注员对 K 个回答排序（K=4-8 常见）
  • AI 偏好：GPT-4 / Claude 评判生成的偏好对
  • 隐式反馈：用户采纳 / 点赞 / 停留时长转化为偏好
  • 规则化 RM：可验证任务（答案对/错）的 0 成本信号
数据量经验：InstructGPT ~33K、GPT-4 RLHF ~50-100K。质量比数量重要——单条错误排序会污染整组训练。

四、常见 Reward Hacking 偏差

偏差现象解法
长度偏差RM 偏好长回答，模型学会堆废话长度归一化、长度 cap、长度惩罚
格式偏差RM 偏好 Markdown 列表，模型所有回答列点数据多样化、显式反例
奉承偏差RM 对"夸用户"的回答打高分标注员培训、负面样本
重复偏差RM 偏好"自信"的回答，模型重复强调perplexity 加权、n-gram 惩罚
OOD 极端分训练分布外的输入给极端分数数据增强、温度平滑、ensemble
位置偏差RM 偏好排在前的回答随机化顺序、位置嵌入

五、RM 评估 4 维度

  • 分类准确率：holdout 偏好对预测准确率，70%+ 可用、80%+ 良好
  • 校准性：RM 打分与人类最终打分的 Pearson / Spearman 相关性
  • Reward 分布：避免分数饱和（全部聚集极端）
  • OOD 测试：训练分布外的样本是否仍合理打分

六、RM 训练技巧

  • 初始化：从 SFT 模型加载（不是 base）
  • 学习率：比 SFT 小 1-2 个量级（1e-5 ~ 5e-5）
  • Margin Loss：r(y_w) − r(y_l) ≥ margin，提高区分度
  • Label Smoothing：标签 0/1 → 0.1/0.9，防过拟合极端
  • Length Normalization：除以 |y|，去长度偏差
  • Ensemble：训 3-5 个 RM 取平均 / min，降低噪声
  • 持续更新：用 online 数据定期重训（应对分布漂移）

七、面试 FAQ

Q1：RM 为什么是 pairwise loss 而不是回归？

A：人类对"绝对分数"标注一致性差（不同标注员给的分数方差大），但对"两个里挑更好的"一致性高（Kappa 通常 0.7+）。Pairwise 损失把"标绝对分"的难题换成"标相对序"——后者准确率显著更高，BT 假设也支撑。

Q2：RM 大小怎么选？和 policy 一样大？

A：经验上和 policy 一样大（GPT-4 RLHF 中 RM = 6B，policy = 6B）。理由：RM 需要足够表达力来"理解"回答质量，太小学不到复杂偏好。但 RM 不需要 Adam 优化器状态，所以显存压力比 policy 小。

Q3：Reward Hacking 怎么识别？

A：3 个信号：① RM 平均分在 PPO 后期异常飙升（刷分特征）；② KL 散度同步暴涨（策略偏离 SFT）；③ 人类评估分下降（用户真实感受差）。三者结合判断。监控策略：实时画"RM 分数 / KL / 人类偏好"三联图。

Q4：RM 长度偏差怎么解？

A：① 数据层：人工标注时控制长度相似；② 训练层：长度归一化 loss、margin with length penalty；③ 推理层：把"长度分"从 RM 输出中减掉；④ 行为层：训练时给超长回答低分。最彻底是训一个"去长度 RM"专门去偏差。

Q5：RM 训到什么时候停？

A：3 个 stop 条件：① holdout 偏好对准确率 plateau；② OOD 验证集分数不再提升；③ 多个 RM 之间一致性高（ensemble 一致）。停太早欠拟合、停太晚会过拟合到训练数据风格。

Q6：为什么需要 Rule-based RM？

A：神经 RM 训练成本高、主观偏差大。数学 / 代码 / 推理任务上，规则 RM（答案匹配 / 单元测试）0 标注成本、0 主观偏差、训练快。GRPO 配合规则 RM 是 DeepSeek-R1 成功的关键。

Q7：RM 评估准确率 80% 算好吗？

A：80% 算可用、85% 算良好、90%+ 优秀。但要注意：评估集和训练集分布对齐时 80% 不难，难的是 OOD 准确率（实际部署时遇到的新 prompt）。建议同时看 in-domain 和 OOD 准确率。

Q8：RM 能直接用 GPT-4 替代吗？

A：可以但有 trade-off。GPT-4 当 RM 优点：0 训练成本、表达力强、即时更新；缺点：贵（每条 query 要调 API）、不可微（无法直接进 PPO）、延迟高、API 不稳。实际多用作"离线数据标注器"或"在线 critic"，不直接替代神经 RM。

八、回答模板与加分项

30 秒电梯版

Reward Model 是 RLHF 的中间件——把人类主观偏好转成可微分的标量分数。核心是 Bradley-Terry pairwise loss、Scalar head 替换 LM head、从 SFT 模型初始化。最大风险是 Reward Hacking：长度、格式、奉承等偏差会被模型放大。评估要 in-domain + OOD 双看。规则 RM（数学/代码）是 0 成本替代品，DeepSeek-R1 走的就是这条路。

5 分钟深入版

从动机（人类偏好难直接优化）→ RM 架构（基座 + Scalar head）→ BT 偏好模型 + pairwise loss → 数据来源 4 类（人工/AI/隐式/规则）→ Reward Hacking 6 类偏差 + 解法 → 评估 4 维度（准确率/校准/分布/OOD）→ 训练技巧（ensemble / 长度归一化 / 持续更新）→ 与 GPT-4 judge、规则 RM 的取舍。能讲清"为什么 pairwise"、"为什么用 SFT 初始化"、"长度偏差怎么解"立刻拉开差距。

加分：踩坑案例

讲一次"RM 训崩"事故：① 用 base 模型初始化 RM 训不出来（loss 不降）—— RM 需要 SFT 模型的"语言理解能力"做 anchor；② pairwise loss 训到 90% 准确率但 PPO 一塌糊涂—— RM 过拟合到训练 prompt 风格，OOD 差；③ RM 长度偏差没解决，PPO 后模型生成越来越长。讲排查过程（看 RM 在 holdout 上的分数分布、看 OOD 准确率）立刻显得有真经验。

加分：知道 RM 局限

RM 不是银弹：① 标注成本高（人类 pairwise）；② Reward Hacking 难以完全避免；③ 通用 RM 在垂类效果差（需要垂类 RM）；④ RM 一次训练不会自动适配新偏好（需要持续更新）。诚实说"工业界用 ensemble + 在线更新 + 规则 RM 组合缓解"得分更高。
