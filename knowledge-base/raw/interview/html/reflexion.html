Reflexion：让 Agent 从试错中"长记性"

Reflexion（Shinn 等 2023）让 Agent 在失败后用自然语言自我反思，把反思结果存到 Episodic Memory，下次遇到类似任务时调出。本质是"verbal RL"——把 RL 的"环境反馈 → 行为调整"链路用自然语言实现。简单、便宜、可叠加，是 Agent 推理增强的"瑞士军刀"。

三、Episodic Memory 检索

新任务开始时，Actor 从 Memory 库检索 top-k 条历史反思（按当前 prompt 相似度），作为上下文注入 prompt："过去类似任务我反思过..."。
  • 写入：反思结果 + 任务摘要 + 失败原因
  • 读取：当前任务 embedding → top-k 历史反思
  • 去重：相似反思合并，避免冗余
  • TTL：可设过期时间，避免"老经验"误导

五、Reflexion 适用场景

  • 代码生成：跑测试失败 → 反思哪行逻辑错 → 重写
  • 决策任务：模拟环境下试错 → 反思策略 → 优化下一步
  • 长任务分解：步骤失败时回滚 + 反思 + 重新规划
  • 对话/角色扮演：角色言行失误 → 反思人设 → 修正
  • 数据/文档任务：抽取错误 → 反思格式 → 调整 prompt

六、Reflexion 失败模式

  • 反思空洞：模型说"我下次会更仔细"但没具体方案
  • 反思循环：反复犯同类错误，反思未触及根因
  • Memory 噪声：相似反思堆积，检索返回过时 / 不相关
  • 奖励黑客：Evaluator 漏洞让模型"通过但不真完成"
  • 上下文膨胀：历史反思越长 prompt 越长，成本涨
解法：反思 prompt 强制要求"具体到动作"（"下次先 X 再 Y"而不是"我要更努力"）；Memory 定期摘要 / 过期；反思去重与去重相似度阈值。

七、面试 FAQ

Q1：Reflexion 和 RL 的关系？

A：Reflexion 被称为 "verbal RL"——把 RL 的"环境反馈 → 行为调整"链路用自然语言实现。区别是：① 反思不是数值梯度，是文本；② 记忆不是权重，是 episodic memory；③ 没有显式策略更新。优点是简单可叠加，缺点是收敛慢、上限低。

Q2：Reflexion 和 ReAct 怎么选？

A：单次工具使用 → ReAct；需要"试错 + 改进"的多轮任务 → Reflexion。两者也可叠加：ReAct 做单步推理，Reflexion 在多轮之间做反思。Reflexion + ReAct 是常见组合。

Q3：反思质量怎么保证？

A：4 个手段：① 反思 prompt 强制"具体动作"而非空话；② 用 strong LLM 做反思（GPT-4 反思自己或 Claude 反思 Opus）；③ 多轮反思（自反思 + 互反思）；④ 反思后用 CoT 验证可执行性。

Q4：Memory 库多大合适？

A：经验上 50-500 条反思条目是甜区。太少：检索不到有用历史；太多：噪声大、检索成本高。定期做"反思去重"和"过期反思清理"。生产中可按用户 / 任务类型分库，减少跨任务污染。

Q5：Reflexion 适合做"风格对齐"吗？

A：不适合。风格对齐需要稳定目标（"语气" "长度"），Reflexion 的"试错"路径太慢；DPO / RLHF 一次性训好更直接。Reflexion 适合"做对 vs 做错"边界清晰的任务。

Q6：Reflexion 失败了怎么 fallback？

A：3 层 fallback：① 反思生成空 → 退化为 ReAct；② Memory 检索无结果 → 退化为单轮推理；③ 反思后仍失败 → 升级人工或换模型。三层保险避免"反思后更糟"。

Q7：Reflexion 与 self-consistency 关系？

A：Reflexion 是"时序"改进（跨轮用历史）；self-consistency 是"空间"改进（单次采样多个回答投票）。两者正交可叠加：先用 self-consistency 选最佳回答，再用 Reflexion 反思改进。

Q8：怎么评估 Reflexion 效果？

A：3 个指标：① 任务完成率（vs 无 Reflexion baseline）；② 平均轮次到成功（衡量"反思是否真有用"）；③ 反思利用率（多少条历史反思被检索到、是否真的影响后续决策）。第三点是关键——避免"反思库有但没用上"。

八、回答模板与加分项

30 秒电梯版

Reflexion 用"verbal RL"做 Agent 自我改进：执行 → 评估 → 失败时生成反思 → 写入 episodic memory → 下次检索历史反思作为上下文。简单、便宜、可叠加，但反思质量不稳定、Memory 噪声大。适合"试错 + 改进"型长任务（代码 / 决策 / 规划），不适合风格对齐。

5 分钟深入版

从动机（Agent 一次失败不"长记性"）→ 三步循环（执行 / 评估 / 反思）→ Episodic Memory 读写 → 反思 prompt 设计 → 与 ReAct / ToT 对比 → 适用场景（代码 / 决策 / 长任务）→ 失败模式（空洞反思 / 循环 / 噪声）→ 评估方法。能讲清"为什么反思 prompt 要强制具体动作"、"为什么 Memory 要定期清理"，立刻显得有真经验。

加分：项目案例

讲一次"为什么从 ReAct 切到 Reflexion"——比如数据分析 Agent 跑 SQL 经常犯同类错（GROUP BY 误用），无记忆反复试错；加 Reflexion 后把"过去哪些 GROUP BY 错"作为反思存库，第 3 次起同类错率降 60%，任务完成率 +25%。

加分：知道局限

Reflexion 不是银弹：① 反思质量不可控（"空话"反思无价值）；② Memory 噪声会污染后续；③ 上下文膨胀成本线性涨；④ 失败模式需要"成功/失败"二元判断，对主观任务不友好。诚实说"Reflexion 是工具不是解药"得分更高。
