LLM 量化：用更少 bit 装下同一个模型

把 FP16/BF16 权重 / 激活 / KV Cache 压到 INT8/INT4 甚至 INT2，显存砍 2-4x、推理吞吐 2-3x。代价是模型质量轻微下降（<1% perplexity）。主流方案：GPTQ（INT4 权重量化）、AWQ（激活感知权重量化）、SmoothQuant（W8A8 平衡）、GGUF（llama.cpp 生态）。本页讲清粒度、PTQ/QAT、精度损失来源。

一、量化的基本原理

FP16 权重 W ∈ [W_min, W_max]（连续浮点）

INT8 量化：$$W_{q} = \mathrm{round}\!\left(\, \tfrac{W - z}{s} \,\right)$$

反量化：$$W \approx s \cdot W_{q} + z$$

$$s = \tfrac{W_{\max} - W_{\min}}{q_{\max} - q_{\min}} \quad\text{（缩放因子）}$$

z = zero point

对称量化（z=0）vs 非对称量化（z≠0）：权重分布对称时用对称更简单，分布偏时非对称更准。LLM 权重一般对称。

二、量化粒度（4 个层级）

粒度压缩精度适用
Per-Tensor最高最低简单模型
Per-Channel高中CNN / LLM 小模型
Per-Group中高LLM 主流（GPTQ group_size=128）
Per-Token中高激活值量化
LLM 量化基本是 per-channel 权重 + per-token 激活的组合。group_size=128（per-group 的 128 个 weight 共用一组 scale/zero）是 GPTQ 黄金参数。

三、PTQ vs QAT

  • PTQ (Post-Training Quantization)：训后量化，用小校准集（128-1024 条）算 scale/zero。便宜、几分钟搞定，效果可接受（<1% ppl 损失）
  • QAT (Quantization-Aware Training)：训练时模拟量化误差，finetune 数小时到数天。效果更好但贵，工业上少用
LLM 几乎全用 PTQ：成本低、效果可接受。QAT 仅在"PTQ 效果不达标"时考虑（如 INT2 极端量化）。

步骤：

② 算 Hessian 矩阵

③ 逐列贪心量化

④ 误差补偿更新

精度损失 < 1% ppl，是 LLM INT4 量化的事实标准之一。

六、AWQ 核心

观察：1% salient 权重（激活值大的输入对应）

决定输出大部分信息

— — —

做法：

① 找 salient weight（用激活值分布）

② salient weight 用更高精度（如 FP16）

③ 其余 INT4

硬件友好：salient weight 只占 1%，几乎无速度损失。效果略优于 GPTQ。

七、KV Cache 量化

  • 动机：长上下文场景下 KV Cache 显存巨大（LLaMA-70B 8K 上下文 → ~10GB KV）
  • 方案：KV 量化到 INT8 或 INT4，per-token / per-head 量化
  • 代表：KIVI、KVQuant、CacheQuant
  • 效果：KV 显存砍 2-4x，长上下文吞吐显著提升
  • 代价：质量轻微下降（< 0.5% ppl），需校准
KV 量化是"在精度可接受前提下把长上下文推到极限"的关键技术，与 PagedAttention 互补（一个管存储、一个管计算 IO）。

八、量化精度损失来源

  • Outlier 权重：少数极端大值主导 scale，挤掉小值精度
  • 激活分布：激活值动态范围大，per-token 量化仍有损失
  • 校准集偏差：校准分布与生产分布不一致
  • 累积误差：多层量化误差逐层放大
  • 小模型更敏感：<7B 模型量化损失比 70B 大

九、面试 FAQ

Q1：INT4 量化精度损失多大？

A：经验 INT4 让 perplexity 上升 < 1%（LLaMA-2 7B WikiText-2 上 ppl 5.47 → 5.55）。下游任务准确率损失 0.5-2%。但小模型（<3B）INT4 损失显著（3-5%），需考虑 INT8 或 AWQ 保护 salient。

Q2：GPTQ 和 AWQ 选哪个？

A：默认 AWQ——保护 salient weight 效果好，硬件友好。GPTQ 是老牌方案、生态更全。两者在 LLaMA-70B 上效果接近，AWQ 在小模型上略胜。生产中可两个都试，看下游任务表现。

Q3：SmoothQuant 适合什么场景？

A：W8A8（权重 INT8 + 激活 INT8）场景——比纯权重量化多砍一档。NVIDIA GPU 上配合 TensorRT-LLM 部署。比 INT4 精度好、比 FP16 显存省一半。推理服务规模化时是首选。

Q4：GGUF 和 GPTQ 区别？

A：GGUF 是 llama.cpp 生态的格式（Q2-Q8 多档可选），主打 CPU + Apple Silicon + 消费级 GPU。GPTQ 是 PyTorch 生态，主打 GPU + 数据中心。同一模型可两套都量化，看部署目标。

Q5：KV Cache 量化值得做吗？

A：长上下文（> 4K）场景必做。短上下文收益小。生产中"模型 INT4 + KV INT8"是常见组合（兼顾模型精度和 KV 显存）。

Q6：FP8 是什么？

A：8-bit 浮点（E4M3 / E5M2 两种格式），Hopper GPU 原生支持。比 INT4 范围大、精度略好，比 FP16 显存砍半。训练和推理都能用，是 NVIDIA 新一代 AI 芯片的"甜点格式"。

Q7：QLoRA 和量化什么关系？

A：QLoRA = NF4 量化基础模型 + LoRA adapter。量化是"冻结基础模型用低精度存储"，LoRA 是"在量化基础上加少量可训参数"。两者结合：消费级 GPU 训 7B 模型成为可能（24GB 显存）。

Q8：量化怎么评估？

A：3 个层面：① 量化误差（perplexity 变化、weight 重构 MSE）；② 任务表现（下游 benchmark 准确率）；③ 部署表现（吞吐量、延迟）。只看 ppl 不够，必须测真实业务指标。

十、回答模板与加分项

30 秒电梯版

LLM 量化把 FP16 权重 / 激活 / KV 压到 INT4/INT8，显存砍 2-4x、吞吐 2-3x。精度损失 < 1%。主流方案：GPTQ（INT4 二阶优化）、AWQ（保护 salient 权重）、SmoothQuant（W8A8）、GGUF（llama.cpp 生态）。LLM 几乎全用 PTQ 训后量化，校准集 128-1024 条就够。

5 分钟深入版

从动机（显存 / 吞吐是推理瓶颈）→ 基本公式（Wq = round((W-z)/s)）→ 量化粒度（per-tensor / per-channel / per-group / per-token）→ PTQ vs QAT → 5 大方案对比 → GPTQ 核心（二阶 Hessian 优化）→ AWQ 核心（salient 保护）→ KV Cache 量化 → 精度损失来源 → 评估方法。能讲清"为什么 group_size=128 是黄金参数"、"为什么 outlier 是量化最大敌人"，立刻显得有真经验。

加分：项目案例

讲一次"为什么从 FP16 切到 INT4"——比如 LLaMA-70B FP16 需 140GB 显存，单机跑不动；GPTQ-INT4 压到 40GB，1×A100 80G 跑起来，吞吐还 2x 提升。配上 vLLM + PagedAttention + SpD 后 QPS 涨 4-5x。

加分：知道局限

量化不是银弹：① 小模型 INT4 损失大；② 校准集偏差会放大；③ 极端 INT2/INT3 需 QAT；④ 量化与 SpD 接受率略冲突。诚实说"量化是部署标配，但要做下游任务验证而不是只看 perplexity"得分更高。
