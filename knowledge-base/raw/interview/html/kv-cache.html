KV Cache

Transformer 推理加速 — 缓存已计算的 K / V，避免每步重新计算全序列 attention，把自回归生成的复杂度从 O(L²) 降到 O(L)。

一、KV Cache 为什么需要

  • 问题：重复计算严重
    • 自回归生成每步只新增 1 个 token，但 attention 要算新 token 对全序列的 attention score
    • 如果不缓存：每步重算全序列 attention，复杂度 O(L²)，L=2048 时已经 4M 次运算
    • 大量浪费：历史的 K / V 其实从未变，每步都重算了一遍
  • 核心做法
    • 把历史的 K / V 矩阵缓存下来（按层 / 按头存）
    • 新 token 只算自己的 Q（向量），与缓存的 K 做 attention，节省矩阵乘法
    • 算完后再把自己的 K / V 追加到缓存末尾，给下一步用
    • 复杂度从 O(L²) 降到 O(L)，推理速度提升 5-10x
  • 显存代价
    • 每层、每头、每个已生成 token 都要存一组 K 和 V 矩阵
    • 长序列 + 大模型下 KV Cache 显存会成主要瓶颈（甚至超过模型权重）
    • 例：LLaMA-7B fp16 推理 L=2048 约 1GB，L=8192 约 4GB
  • 优化方向：
    • Multi-Query Attention (MQA)：所有 head 共享同一组 K / V（KV 容量 ÷ 头数）
    • Grouped Query Attention (GQA)：分组共享（如 8 头 Q 共享 2 组 K / V）
    • PagedAttention (vLLM)：把 KV 分成固定大小页（block）按需分配，消除碎片
    • FlashAttention：在线计算 K / V，分块加载到 SRAM，显著降显存
    • KV 压缩 / 稀疏：H2O / StreamingLLM 保留重要 token、淘汰次要 token

二、KV Cache 时序

每步推理只需算新 token 的 Q 矩阵（向量），与缓存的 K 矩阵做 attention 后用 V 加权。算完把新 K / V 追加到缓存。显存增长线性、计算量线性。

三、KV Cache 显存

单序列显存： Memory = 2 × L × d × n_layers × dtype_bytes

MQA / GQA 时： Memory = 2 × L × head_dim × n_kv_heads × n_layers × dtype_bytes

变量含义： L=序列长度, d=隐藏维, n_layers=层数, dtype_bytes=2(fp16)/1(int8)

例（LLaMA-7B, fp16, L=2048）：

2 × 2048 × 4096 × 32 × 2 / 1024³ ≈ 1.0 GB / 序列

L=8192 时约 4 GB / 序列，batch=8 时总占用 32 GB（KV 已超过模型权重 14GB）。

LLaMA-2-70B 同条件约 5 GB / 序列（fp16），多 batch 部署时显存压力极大。生产经验：vLLM + PagedAttention + INT8 量化是常见组合。

五、面试 FAQ

Q1：KV Cache 显存怎么算？

A：2 × L × d × n_layers × dtype_bytes（MHA）；2 × L × head_dim × n_kv_heads × n_layers × dtype_bytes（MQA/GQA）。例：LLaMA-7B fp16 L=2048 约 1GB；L=8192 约 4GB。生产用 vLLM 实际占用可通过 nvidia-smi 观察。

Q2：PagedAttention 怎么省显存？

A：把 KV 切成固定大小页（block，如 16 token / block），按需分配，序列用"块表"（block table）记录物理块号。好处是 碎片接近 0（传统连续分配浪费 30-50%）、支持非连续物理布局、多请求共享空闲块。vLLM 的核心创新。

Q3：MQA 和 GQA 区别？

A：MQA（Multi-Query Attention）：所有 head 共享 1 组 K / V，KV 容量 ÷ N（N=头数）。GQA（Grouped Query Attention）：分组共享，N 个 Q 头对应 G 个 K / V 头（如 8Q:2KV）。GQA 是 MHA 和 MQA 的折中，效果接近 MHA、显存接近 MQA，LLaMA-2 / Mistral 都用 GQA。

Q4：长上下文 KV Cache 满了怎么办？

A：四种方案：滑动窗口（只保留最近 K 个 token 的 KV）、稀疏 attention（Longformer / BigBird 模式）、KV 压缩（H2O 按分数淘汰）、KV 量化（INT8 / INT4 存）。生产经验：先用 PagedAttention + 量化兜底，超长上下文再上稀疏。

Q5：KV Cache 和 Prompt Cache 区别？

A：KV Cache是 token 级别的张量缓存（每步追加 K / V，向量级），Prompt Cache是请求级别的完整前缀复用（字符串 / token 序列级）。Prompt Cache 命中时直接复用预计算的 KV 块，省去 prefill 阶段。Anthropic / OpenAI 都提供 Prompt Cache 能力。

Q6：Beam Search 时 KV Cache 怎么管理？

A：每个 beam 独立维护一份 KV Cache（结构相同、内容不同）；前缀共享的部分用 Tree Attention 共享 KV 块（vLLM 支持）。代价是 beam 数量 × 单 beam KV 显存，beam=5 时 5 倍占用。

Q7：什么时候不需要 KV Cache？

A：三种情况：非自回归任务（一次性 Encoder 推理）、小 batch + 短序列（缓存收益不显）、训练阶段（整序列前向，不需要增量）。KV Cache 只在自回归解码阶段有意义。

Q8：KV Cache 怎么调试？

A：用 nvidia-smi 看显存是否与理论值一致；用 torch.cuda.memory_summary() 看分配 / 缓存比例；用 kv cache profiler 工具看每请求峰值；异常大时检查是否有 beam search 复制、是否有 prompt 超长未拦截。

回答模板与加分项

30 秒电梯版

面试开场可以这样讲：KV Cache 是 Transformer 自回归推理的标配优化，缓存历史的 K / V 矩阵让新 token 只算自己的 Q，复杂度从 O(L²) 降到 O(L)、加速 5-10x。代价是 KV 显存随序列线性增长，催生了 PagedAttention（vLLM）、FlashAttention、MQA/GQA 等优化方向。生产用 vLLM + FlashAttn + INT8 量化是常见组合。

5 分钟深入版

从自回归的重复计算问题 → KV Cache 基本做法 → 显存公式 → 优化路径（Paged / Flash / MQA / GQA / 量化）→ 实际项目收益，逐层展开。最后落到你们模型的 QPS / 显存 / 延迟数据。有真实数据能立刻拉开差距。

加分：知道 KV Cache 的局限

KV Cache 不是银弹：长序列显存爆炸、beam search 占用翻倍、跨请求无法直接共享、抢占 / 中断时缓存重建。建议结合"PagedAttention 减少碎片 + 量化降显存 + Prefix Cache 跨请求共享"三件套缓解。

加分：能讲一次踩坑

比如：beam=5 时显存爆了（5 倍 KV）；长 prompt prefill 阶段 OOM（prefill 也要算 KV）；PagedAttention block size 设太小导致块表太大；GQA 模型用错 attention 实现导致索引错位。讲一次具体排查过程，面试官会立刻认定你有真经验。

面试官可能怎么追问

追问方向示范追问建议回应思路
基础原理为什么 KV Cache 能省计算？答"自回归的局部性"：每步只新增 1 个 token，历史的 K / V 已固定无需重算；attention 矩阵里只有最后一行是新的，其余可缓存。抓住"局部性 + 增量"。
显存计算7B 模型 L=2048 KV 显存多大？答"约 1GB"：2 × 2048 × 4096 × 32 × 2B / 1024³ ≈ 1GB。强调 LLaMA 用 GQA 后实际是 1/8 ≈ 128MB。再追问 MQA / GQA 区别。
优化路径vLLM 为什么快？答"PagedAttention + 连续批处理"：KV 分页消除碎片、动态 batch 把等待中的请求塞进 GPU 空隙、Prefix Cache 共享前缀。三个组合起来 QPS 提升 10x+。
工程实践怎么选 KV 量化精度？答"按显存 / 质量权衡"：INT8 几乎无质量损失（推荐默认）；INT4 显存再省 50% 但质量轻微降；FP8（Hopper）新硬件支持好。生产经验：先 INT8，效果不够再降。
进阶FlashAttention 和 KV Cache 关系？答"互补"：FlashAttention 是 kernel 层优化（不存中间 attention 矩阵），KV Cache 是张量层缓存（保留 K / V）。两者可叠加用：FlashAttention 算 attention 块、KV Cache 跨步存 K / V。
最后提示：KV Cache 是推理优化的核心话题，面试允许说"这块我了解原理但生产经验有限"，但要能讲清楚复杂度收益、显存公式、主流优化 + 给出项目设计。诚实 + 思路清晰 > 假装熟练。
