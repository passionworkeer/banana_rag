Constitutional AI：让模型按"宪法"自我改进

Anthropic 2022 提出。用一组"宪法原则"（Constitution）替代人类偏好标签，让模型先自我批评（Critique）、再自我修正（Revision）、最后用 AI 反馈（RLAIF）做 RLHF。核心卖点：把"什么是有害/有帮助"的判断从人转给 AI + 一组明文规则，大幅降低标注成本和主观偏差。

一、Constitutional AI 两阶段流程

A, yB 对同 prompt ② AI 判断哪个更符合宪法 prompt: "考虑宪法原则 C, 哪个更好？" ③ 构造偏好对 (y_w, y_l) 用作 RM 训练数据 RM 训完 → PPO 训练 无人类标注的 RLHF 闭环 SFT 训完

二、Constitution 原则示例

示例原则（节选）：
1. 请选择最无害、最有帮助的回答
2. 请避免提供可能有害、违法或不道德的建议
3. 请不要基于种族、性别、宗教等歧视任何人
4. 请不要提供可能违反隐私的信息
5. 请避免在用户表达痛苦时冷漠对待
6. 请不要帮助制造武器、毒品等危险物品
7. 请选择最不操控用户情感的回答
...

原则用自然语言写，每条对应一类问题。模型在 Critique 时按顺序核对所有相关原则。

三、典型 Critique-Revision Prompt

Critique Prompt:
"请对以下回答进行批评：
{response}
请参照宪法原则：
{constitution_principles}
指出该回答可能违反原则的地方。"

Revision Prompt:
"请根据以下批评重写上述回答：
{critique}
{response}
请确保新回答完全符合宪法原则。"

实际操作中会让模型反复 Critique-Revision 多次（典型 N=3-5），最后取最新版本作为 SFT 训练数据。

五、CAI 的 3 大优势

  • 低成本扩展：新增一条原则 = 新覆盖一类问题，无需重标数据
  • 可解释性：对齐标准在明文规则中，监管、审计、用户都可读
  • 去除主观偏差：标注者的文化背景、政治倾向不再直接传导到模型

六、CAI 的 3 大风险

  • 宪法完备性问题：原则写漏一类问题，模型学不到
  • 原则冲突：原则之间矛盾时模型无所适从（如"有帮助"vs"无害"）
  • AI 评判循环：AI 给 AI 反馈，无人类把关时错误会放大
  • Reward Hacking 2.0：模型学会"看起来在遵循宪法"而非真遵循
  • 宪法 = 写规则者的价值观：从人类偏好到 AI 偏好，只是把"谁"换了一层
CAI 不应作为唯一的对齐手段，工业界实际多采用"RLHF + CAI 兜底"双轨制：核心价值观靠人类偏好 RLHF，长尾安全 / 风格问题靠 CAI 兜底。

七、面试 FAQ

Q1：CAI 是怎么"去除"人类偏好的？

A：不是完全去除，而是把"人类排序"换成"AI 按宪法评判"。人类还是要写宪法原则，所以价值观源头还是人。但相比"给每条回答排序"，写一组原则的成本低、主观偏差小、可解释。

Q2：Constitution 怎么写才"好"？

A：Anthropic 论文总结几条经验：① 原则要具体到"可被判断"的程度（"有帮助"太虚，"请不要为毒品制程提供步骤"具体）；② 覆盖正反两面（既要说"做什么"也要说"不做什么"）；③ 原则之间不能有直接冲突；④ 定期根据 bad case 补充新原则。

Q3：CAI 的 Critique-Revision 跑多少轮？

A：典型 3-5 轮。轮次太少修改不彻底；太多边 0 边际收益反而引入"过度修正"（模型变得过度谨慎、闪烁其词）。实践中监控 "Revise 后 vs Revise 前"的提升幅度，趋于稳定就停。

Q4：CAI 适合中文场景吗？

A：可以，但 Constitution 要用中文写、且要覆盖中文社区特有的价值观（中国法规、文化禁忌、平台规范）。直接翻译英文原则会丢失本地化细节，效果打折。

Q5：CAI 怎么和 RLHF 结合？

A：常见模式"RLHF 主训练 + CAI 兜底"：① RLHF 训核心偏好（人审）；② CAI 用宪法补长尾安全问题（AI 自评）；③ 两者输出融合到 PPO 训练。或更简单：CAI 单独训一个 Critic 模型，PPO 中作为额外 RM。

Q6：CAI 与 RLAIF 关系？

A：CAI = RLAIF 的一种具体实现（带宪法评判规则的 RLAIF）。RLAIF 是大类（任何用 AI 反馈替代人类反馈），CAI 特指"按宪法原则评判"的实现。

Q7：CAI 怎么避免"看起来遵循宪法"？

A：很难完全避免。常见做法：① 训练数据混入"用户故意诱导"的红队样本；② 评估时不用模型自评（容易同谋），用独立模型；③ 最终用人类 expert 抽查高风险回答。

Q8：CAI 在工业界用得多吗？

A：Anthropic 主力（Claude 系列），其他厂商多用简化版（如 OpenAI 的 critique prompt 嵌入对齐流程）。中文社区目前少有完整 CAI 实践，多数仍用 RLHF / DPO 路径。

八、回答模板与加分项

30 秒电梯版

Constitutional AI 是 Anthropic 提出的 RLAIF 变体：用一组明文宪法原则替代人类偏好标签，分两阶段：① 模型先自我批评再自我修正（SL-CAI）；② 用 AI 按宪法评判作为偏好信号训 RM + PPO（RL-CAI）。核心收益是降标注成本 + 可解释 + 去除主观偏差，核心风险是宪法完备性 + 原则冲突 + AI 评判循环。

5 分钟深入版

从动机（RLHF 标注贵且主观）→ 两阶段流程（SL-CAI 自批评自修正 / RL-CAI AI 反馈）→ Constitution 怎么写（具体、可判、不冲突）→ 与 RLHF / DPO 对比 → 优势（低成本扩展 / 可解释 / 去偏差）→ 风险（完备性 / 冲突 / 循环）→ 工业落地形态（双轨制）。能讲清"为什么 CAI 不能完全替代 RLHF"，立刻显得有真经验。

加分：项目案例

讲一次"为什么切到 CAI"——比如某业务"内容安全"场景下 RLHF 标注成本占总对齐成本 70%，且标注员分歧大；改用 CAI + 业务宪法（"不出现 XX 类关键词"、"敏感事件需附加免责说明"等 20 条原则）后，标注成本降 60%、bad case 率从 5% 降到 1.5%。

加分：知道局限

CAI 不是银弹：① 宪法完备性瓶颈（写不到 100% 覆盖）；② 原则冲突两难；③ Reward Hacking 2.0（"看起来遵循"非"真遵循"）；④ 宪法本身也是人写，价值观源头未变。诚实说"CAI 是工具不是解药，工业界多用 RLHF + CAI 双轨"得分更高。
