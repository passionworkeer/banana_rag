Speculative Decoding：小模型起草 + 大模型验收

用一个小的 draft model 先快速生成 K 个候选 token，再用大 target model 一次性 verify 整段。接受率 α 决定加速比。Leviathan 等 2023 提出，数学保证：接受 / 拒绝的分布与原大模型自回归生成完全一致。典型场景 2-3x 加速，且不损失质量。

二、Acceptance Rate α 决定加速

$$\text{加速比} \approx \tfrac{1}{1 + \alpha - \alpha \cdot c}$$

α = 接受率，c = 草稿/验证成本比

— — —

α=1.0, c=0.1, K=4 → ~2.4x

α=0.7, c=0.1, K=4 → ~1.7x

α=0.5, c=0.1, K=4 → ~1.4x

α 取决于 draft 和 target 模型的相似度。同一系列小/大模型（Llama-7B 起草 / Llama-70B 验收）α 普遍 0.7+；跨模型（GPT-2 起草 / LLaMA 验收）α 可能 <0.4，反而负优化。

三、Greedy 与 Sampling 公式

Greedy 模式：

若 $q(x) = p(x) \Rightarrow$ 接受

否则拒绝并取 p(x) 最大

— — —

Sampling 模式：

若 $r < p(x) / q(x) \Rightarrow$ 接受

否则从 $\max(0,\, p - q)$ 归一化重采样

两种模式都数学保证输出分布与原大模型完全一致（Leviathan 2023 定理 1）。

五、加速比计算示例

draft 7B：~30ms/步（生成 4 token）

target 70B：~200ms/步

α = 0.7

— — —

无 SpD：800ms 生成 4 token

SpD：30 + 200 = 230ms（α 0.7 下期望）

加速 ≈ 800/230 = 3.5x

α 0.7 实际能拿到，是因为小模型和大模型在同一任务上"想得差不多"。

六、Speculative Decoding 适用场景

  • 同系列大/小模型：Qwen-1.5B + Qwen-72B、LLaMA-7B + LLaMA-70B
  • 长输出生成：加速比在长文本上更明显
  • 批处理高并发：vLLM + SpD 叠满
  • 延迟敏感：交互式对话、代码补全
  • 数学保证：Greedy/Sampling 模式输出分布与原模型一致

七、Speculative Decoding 不适用场景

  • 跨系列模型：GPT-2 + LLaMA 接受率 < 0.4 反而拖慢
  • 短回答：加速 < 2x 不值得工程复杂度
  • 极长 prefix：draft 也要处理长 context，自身慢
  • 采样温度高：低概率 token 增多，α 下降
  • 无小模型可用：训 Medusa/EAGLE head 有数据成本
判断口诀：有同系列小模型 + 接受率 0.6+ + 长输出 → 上 SpD；没有同系列小模型 → 训 Medusa head 或放弃。

八、面试 FAQ

Q1：Speculative Decoding 数学保证是什么？

A：Leviathan 2023 定理 1 证明：用 draft 模型生成 + rejection sampling 验证，最终输出分布与原大模型自回归生成完全相同。所以"用大模型小模型配合"生成的结果就是"用大模型自己生成"的结果，无损加速。

Q2：为什么 Medusa 也能用？它没独立 draft 模型？

A：Medusa 在 target LLM 上额外训练若干"轻量 FFN 头"，每个头预测某个未来位置的 token。这些 head 极小（每个几 MB），可一次性前向算出 K 个候选 token，配合 tree attention 让 target 一次 verify 多分支。优点：单模型部署；缺点：需要训头、且 α 略低于独立 draft。

Q3：EAGLE 和 Medusa 区别？

A：Medusa 用额外 FFN 头预测 token；EAGLE 在 target 倒数第二层加一个小 transformer，用 hidden state 而非 embedding 预测下一 token。EAGLE α 通常更高（用更深层特征）、训练稍慢。

Q4：接受率 α 怎么估？

A：在小规模验证集上跑 draft + target 配对，统计"草稿 token 被 target 接受的比率"。α 0.7+ 算优秀，0.5-0.7 可用，<0.5 不建议上 SpD。生产中 α 随 prompt 分布变化，需要监控漂移。

Q5：SpD 适合 batch 大小为 1 的场景吗？

A：特别适合。batch=1 时大模型显存利用率极低（KV Cache 没复用），target verify 算力浪费严重。SpD 让一次 verify 处理 K 个 token，GPU 利用率显著提升。生产交互式对话 + SpD 是经典组合。

Q6：SpD 与 KV Cache 优化冲突吗？

A：不冲突。SpD 走的是 target 模型的 KV Cache，vLLM 的 PagedAttention 仍生效。实际生产中 vLLM + SpD 一起用：PagedAttention 省显存、SpD 省计算步骤。

Q7：SpD 与量化冲突吗？

A：可能略冲突。SpD 假设 draft 和 target 输出分布接近；target 量化到 INT4 时分布会偏移，α 可能下降 5-10%。需要重新校准 draft 阈值或选 FP8 target。

Q8：怎么选 K（草稿 token 数）？

A：K=4-8 是经验 sweet spot。K 太小 → verify 收益小；K 太大 → draft 阶段后期准确率下降，α 衰减。生产中根据 α 动态调 K：α 高时 K 调大、α 低时 K 调小。

九、回答模板与加分项

30 秒电梯版

Speculative Decoding 用小模型先草拟 K 个 token，大模型一次性 verify。接受率 α 决定加速比，2-3x 常见。关键是"数学保证输出分布与原大模型一致"——无损加速。变体有 Medusa（target 上加 head）、EAGLE（小 transformer 预测）、Self-Speculative（early exit）。配合 vLLM + PagedAttention + 量化是当前推理优化四件套。

5 分钟深入版

从动机（大模型 decode 阶段 GPU 利用率低）→ 经典 3 步流程（draft / verify / accept-reject）→ 接受率 α 与加速比公式 → Greedy / Sampling 公式 → 4 类变体（Classic / Medusa / EAGLE / Self-Speculative）→ 适用边界 → 与 PagedAttention / 量化 / FlashAttention 组合。能讲清"为什么数学保证无损"、"为什么 α 决定加速"、"为什么 Medusa 用 head 而非独立模型"，立刻显得有真经验。

加分：项目案例

讲一次"为什么从普通推理切到 SpD"——比如客服对话场景 batch=1，大模型 70B 一次 decode 200ms，QPS 受限；加 Qwen-1.5B 起草后，α=0.75，verify 一次 200ms 处理 3-4 个 token，端到端 1 token 60ms，QPS 提升 3x 用户无感。

加分：知道局限

SpD 不是银弹：① 需要同系列小模型；② α < 0.5 时反优化；③ 短回答收益小；④ 量化时 α 下降；⑤ Medusa/EAGLE 需要训 head。诚实说"SpD 是 batch=1 + 长输出场景的杀手锏，但不是所有场景都适用"得分更高。
