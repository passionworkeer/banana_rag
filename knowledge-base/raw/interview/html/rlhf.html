RLHF：用人类偏好把模型"教乖"

Reinforcement Learning from Human Feedback。三步走：训 SFT → 训 Reward Model → 用 PPO 把语言模型对齐到人类偏好。核心不是"强化学习很难"，而是"为什么需要 RM、为什么需要 KL 约束、为什么会被 Reward Hacking"。

二、Reward Model 损失

$$L_{\text{RM}} = -\mathbb{E}_{(x, y_{w}, y_{l}) \sim \mathcal{D}}\!\left[\, \log \sigma\!\left(\, r_{\varphi}(x, y_{w}) - r_{\varphi}(x, y_{l}) \,\right) \,\right]$$

$y_{w}$ = 偏好的回答（winner），$y_{l}$ = 落选的（loser）。本质是 pairwise ranking loss，要求 RM 对"更好的回答"打更高分。

Bradley-Terry 假设：人偏好的概率差等于两个回答奖励差经过 sigmoid 后的结果。

三、PPO 目标函数

$$\text{objective} = \mathbb{E}_{(x, y) \sim \pi_{\theta}}\!\left[\, r_{\varphi}(x, y) \,\right] - \beta \cdot \mathrm{KL}\!\left(\, \pi_{\theta}(y \mid x) \,\|\, \pi^{\text{SFT}}(y \mid x) \,\right)$$

$$\nabla_{\theta} = \mathbb{E}\!\left[\, \nabla_{\theta} \log \pi_{\theta}(y \mid x) \cdot A(x, y) \,\right]$$

两项都很关键：奖励项让回答更好；KL 项防止策略飘太远、保留 SFT 学到的能力。β 是平衡超参，太大→不敢改、效果差；太小→Reward Hacking。

四、PPO 训练时显存里的 4 个模型

角色是否训练作用显存占用参考（7B，fp16）

五、Reward Hacking 案例

  • 长度偏差：RM 偏好长回答 → 模型越说越长、堆废话
  • 格式偏差：RM 偏好 Markdown 列表 → 模型所有回答都列点
  • 奉承偏差：RM 对"夸用户"的回答打分高 → 模型变得谄媚
  • 重复偏差：RM 偏好"看起来自信"的回答 → 模型反复强调同一观点
  • OOD 输入：RM 在训练分布外的输入上给出极端高分 → 模型学会触发这些 case
解法：KL 约束、长度归一化、多样化 RM 数据、在线人类反馈（online RLHF）、以及 DPO/GRPO 这类"不需要显式 RM"的方法。

八、面试 FAQ

Q1：RLHF 一定要有 SFT 阶段吗？

A：InstructGPT 原文是 SFT→RM→PPO 三阶段；理论上也可以"从基座直接 PPO"（skip SFT），但实践中几乎没人这么做——没有 SFT 锚点，KL 约束没有参考、模型容易崩坏。也有 RLAIF / DPO 完全跳过 RM 的方案。

Q2：为什么 KL 约束这么重要？

A：KL 项让优化后的策略不偏离 SFT 太远。没了它，PPO 会疯狂刷 RM 分数（Reward Hacking），但输出可能完全崩坏（乱码 / 重复 / 不相关）。β 越大越保守，效果上限越低；越小越激进，越容易翻车。

Q3：Reward Model 怎么训？需要多大数据？

A：InstructGPT 用 ~33k 条排序数据；GPT-4 RLHF 用 50-100k。RM 通常从 SFT 模型初始化（去掉最后 LM head，加 scalar head），用 Bradley-Terry pairwise loss 训。关键点：RM 数据质量比数量重要，单条错误排序会污染整组训练。

Q4：PPO 为什么这么难训？

A：3 个原因：① 4 个模型同时前向/反向，显存压力大；② reward 信号稀疏（只有整句生成完才有分数），方差大；③ 策略更新和奖励模型相互博弈，容易震荡。GRPO/REINFORCE++ 砍掉 critic 可缓解。

Q5：online RLHF 和 offline RLHF 区别？

A：offline 用固定偏好数据集（DPO、原始 RLHF）；online 在 PPO 训练中持续用当前模型采样 + 人类标注新偏好（GPT-4 路径）。online 效果更好但成本极高，工业界折中：用 self-play / AI feedback（RLAIF）模拟 online。

Q6：RLHF 后模型能力会下降吗？

A：会。常见现象叫"对齐税"（alignment tax）：RLHF 提升了安全性和人类偏好分，但 MMLU/GSM8K 这类能力基准会掉 1-3 个点。解法：RLHF 中混入能力数据 / 用更强的基座 / 多目标奖励（RM 多任务混合）。

Q7：RM 怎么评估？

A：两个角度：① 分类准确率——对 holdout 偏好对的预测准确率（70%+ 算可用）；② 校准性——RM 打分与人类最终打分的相关性。RM 评估比 policy 评估容易做，是 RLHF pipeline 中最稳定的环节。

Q8：KL 系数 β 怎么调？

A：经验从 0.05-0.1 起步；观察到模型输出崩坏/重复→加大 β；观察到效果停滞/RL 步数不再带来收益→减小 β。也可以做成 schedule（先大后小）。

九、回答模板与加分项

30 秒电梯版

RLHF 是用人类偏好信号训练语言模型的三阶段流程：先 SFT 学格式，再训 Reward Model 学"什么是好回答"，最后用 PPO 把策略对齐到 RM 评分，同时加 KL 约束防止崩坏。优点是天花板高，缺点是显存贵、训练不稳、易 Reward Hacking，所以工业界演化出 DPO/GRPO 等简化方案。

5 分钟深入版

从动机（SFT 后模型仍不"听话"）→ RM 数据构造（pairwise 排序）→ Bradley-Terry 损失 → PPO 目标（reward − β·KL）→ 4 模型显存结构 → Reward Hacking 案例 → 与 DPO/GRPO 的取舍。能在 5 分钟内把"为什么需要 KL"、"为什么显存这么贵"、"怎么避免 Reward Hacking"讲清楚，就能立刻拉开差距。

加分：踩坑案例

讲一次真实事故：① KL 设太大，模型没变化，训 3 天白做；② KL 设太小，模型输出全是 emoji 和感叹号刷 RM 分数；③ RM 数据被注入 prompt injection，所有负面回答打低分；④ 训练后期 PPO 步数不收敛，怀疑 RM 已被 policy 攻破。讲排查过程（指标观察 → 假设 → 验证 → 修），面试官立刻认定有真经验。

加分：知道 GRPO 改进点

GRPO（DeepSeek 提出）砍掉 Value Model，用同一 prompt 采样 N 个回答、用组内归一化分数当 advantage，显存从 4 模型降到 2 模型，且对长 CoT 推理任务更友好。是当前开源模型对齐的事实标准之一。
