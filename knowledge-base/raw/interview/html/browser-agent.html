二、Browser Agent 能力栈

  • 视觉理解：VLM 理解截图（按钮 / 文本 / 布局）
  • 坐标定位：决定点击 / 输入的像素坐标

  • 决策循环：think → act → observe → 反思
  • 任务分解：把"订票"拆成 10-30 步子任务

五、WebArena / WebVoyager 评测

  • WebArena：CMU 2023，真实网站复刻（购物 / 论坛 / 地图等），641 任务，主流 benchmark
  • WebVoyager：Apple 2024，跨 15 个真实网站（Amazon / Google Flights 等）
  • OSWorld：OS 级任务评测（文件管理 / 安装软件）
  • MobileAgent：移动端评测
GPT-4V / Claude 3.5 在 WebArena 上成功率 ~40-60%，远超人类单次通过率（~78%）但仍远低于"完全自主"。SOTA 还在快速演进。

六、Browser Agent 安全风险

  • 提示注入：网页内容可含恶意指令（间接注入）
  • 误操作：点错按钮导致真实损失（付款 / 删数据）
  • 账户劫持：Agent 登录后 cookie 被劫持
  • 隐私泄露：Agent 看到用户所有操作（密码 / 聊天）
  • DoS：Agent 死循环点按钮 / 刷新
  • 资金损失：Agent 自动支付 / 转账
生产中 Browser Agent 必须在沙箱 VM 中跑 + 高危动作必须 HITL（人工确认）+ 输入清洗 + 输出审计。

七、面试 FAQ

Q1：Browser Agent 和传统 RPA 区别？

A：传统 RPA（UiPath）靠录制 + 规则匹配，UI 一变就废。Browser Agent 用 VLM 理解截图 + LLM 决策，鲁棒性高、能处理没见过的情况。代价是慢 + 贵 + 不可预测。生产中 RPA + Agent 混合（稳定步骤用 RPA，灵活决策用 Agent）较常见。

Q2：Browser Agent 准确率为什么不够高？

A：3 个原因：① VLM 截图理解有偏差（小图标 / 反色 / 模糊）；② 长链路累积错误（10 步中 1 步错就失败）；③ 网页 DOM 复杂（iframe / 弹窗 / 异步加载）。WebArena 上 SOTA 50-60% 远未达到生产标准。

Q3：Computer Use 的安全风险怎么控？

A：5 层：① 沙箱 VM 隔离（不能动真实系统）；② 域名白名单（只允许访问可信网站）；③ 高危动作 HITL（支付 / 删数据前人工确认）；④ 输入清洗（屏蔽 prompt injection 关键词）；⑤ 全程录屏 + 异常告警。

Q4：browser-use 框架怎么工作？

A：3 步循环：① 截图 + DOM 信息给 VLM；② VLM 决定动作（click / type / scroll / navigate）；③ Playwright 执行并返回新截图。框架提供 ReAct 风格的状态管理、错误恢复、超时控制。可接任意 LLM。

Q5：Browser Agent 和 Operator / CUA 区别？

A：Operator / CUA 是 OpenAI 的 SaaS 产品，背后用 GPT-4V 跑 Computer Use，给用户提供托管体验（不需自己搭）。browser-use 是开源框架，自己接任意 LLM。生产中"自己控制"选开源、要"开箱即用"选 SaaS。

Q6：WebArena 任务难在哪？

A：3 个难点：① 自然语言指令模糊（"订便宜机票"含义多样）；② 网页结构复杂（多 tab / 弹窗 / 验证码）；③ 跨网站信息整合（"比价"需打开多个网站）。是 Agent 系统综合能力的"期末考"。

Q7：Browser Agent 适合什么生产场景？

A：3 类典型：① 内部工具（数据录入、批量报告、跨系统对账）；② 客户服务（自动填表、查订单）；③ 数据采集（合规前提下的爬虫）。不适合：① 实时性要求高（毫秒级）；② 高频任务（每天 1000+ 次）；③ 涉及大额资金。

Q8：Browser Agent 的"未来"方向？

A：4 个趋势：① 更高准确率（SOTA 60% → 90%+）；② 多模态融合（截图 + DOM + accessibility tree）；③ 与 A2A 协议结合（Agent 间协作）；④ 安全沙箱标准化（OS 级隔离、审计）。Anthropic / OpenAI 持续投入，是 Agent 商业化的关键路径。

加分：项目案例

讲一次"Browser Agent 自动对账"——比如财务场景：每天自动登录 5 个银行系统，下载账单、解析、对比、生成报告。WebArena 风格任务上 Agent 准确率 70%，人工兜底 30%。讲排查 + 沙箱 + HITL 过程立刻显得有真经验。

加分：知道局限

Browser Agent 不是银弹：① 准确率仍不达标（50-60% SOTA）；② 慢 + 贵（每步 VLM 调用）；③ 长链路累积错误；④ 安全风险大。诚实说"Browser Agent 适合内部工具 + 人工兜底，不适合直接面向用户的关键操作"得分更高。
