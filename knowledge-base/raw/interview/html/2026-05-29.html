为什么大模型需要"对齐"？

预训练模型学会的是"预测下一个词"，但不一定符合人类期望。对齐技术让模型从"能说话"变成"会说话"，从"有知识"变成"有智慧"。

Prompt无法解决、复杂价值观对齐、隐式偏好学习、需要泛化到分布外场景时。

RLHF vs DPO 选择决策

资源充足追求极致效果选PPO/RLHF；资源受限、快速迭代选DPO。

一、RLHF：强化学习框架下的对齐

RLHF (Reinforcement Learning from Human Feedback) 是将人类偏好融入模型训练的核心范式。

"RLHF的本质是：让模型学会理解'人类的意图'，而不仅仅是'下一个词的概率分布'。人类反馈是指引方向，强化学习是优化手段。"

RLHF三阶段

1

SFT（Supervised Fine-Tuning）

有监督微调阶段，用高质量问答对让模型学会"正确回答问题"。这是基础，让模型具备基本对话能力。

2

Reward Model（奖励模型）

训练一个模型来学习人类偏好。输入(提示, 回答)，输出人类对该回答的评分。典型结构是Elo评分系统。

3

RL Fine-Tuning（强化学习微调）

用PPO算法优化策略模型，让模型生成更高奖励的回答。核心约束是KL散度，防止模型跑偏。

💡 为什么需要Reward Model？

直接让人类标注所有回答太贵且不可扩展。Reward Model学到了人类偏好的隐式函数，可以泛化到新回答。

PPO (Proximal Policy Optimization) 是RLHF的核心优化算法。

PPO目标函数

ppo_loss.py
# PPO核心目标函数 - 带KL约束的策略优化 import torch import torch.nn.functional as F def ppo_loss( old_log_probs: torch.Tensor, # 旧策略的概率 log_probs: torch.Tensor, # 新策略的概率 rewards: torch.Tensor, # 奖励信号 values: torch.Tensor, # 价值估计 old_values: torch.Tensor, # 旧的价值估计 gamma: float = 0.99, # 折扣因子 epsilon: float = 0.2, # CLIP范围 kl_coef: float = 0.04 # KL惩罚系数 ) -> torch.Tensor: # 1. 计算优势函数 A = R - V advantages = rewards - values # 2. 计算策略比率 r(θ) = π_θ(a|s) / π_OLD(a|s) ratio = torch.exp(log_probs - old_log_probs) # 3. PPO裁剪目标 - 防止策略更新过大 clipped_ratio = torch.clamp(ratio, 1 - epsilon, 1 + epsilon) policy_objective = -torch.min( ratio * advantages, clipped_ratio * advantages ).mean() # 4. KL散度惩罚 - 防止模型偏离原始太远 # KL(π_θ || π_ref) = Σ π_ref(a|s) * log(π_ref(a|s) / π_θ(a|s)) kl_penalty = F.kl_div( log_probs, old_log_probs, reduction='batchmean' ) # 5. 价值函数损失（可选） value_loss = F.mse_loss(values, rewards) return policy_objective + kl_coef * kl_penalty + 0.5 * value_loss

关键机制解析

机制作用为什么有效
Clipping限制策略更新幅度防止灾难性遗忘
KL惩罚约束与参考模型的偏离保持模型基本能力
GAE优势函数估计平衡偏差与方差
Value Baseline减少方差稳定梯度更新

完整的RLHF训练流程需要多个模型协同工作。

rlhf_pipeline.py - 完整RLHF流程
# RLHF三阶段训练流程 import torch from typing import List, Tuple class RLHFTrainer: def __init__(self, model, config): self.model = model self.config = config self.ref_model = torch.compile(model) # 冻结的参考模型 def stage1_sft(self, dataset: List[Tuple[str, str]]): """ 阶段1: 有监督微调 直接用高质量(提示, 回答)对训练 """ for prompt, response in dataset: # 标准语言模型训练 output = self.model(prompt, labels=response) loss = output.loss loss.backward() self.optimizer.step() def stage2_reward_model(self, preference_data: List): """ 阶段2: 训练Reward Model 数据格式: (prompt, chosen_response, rejected_response) """ for prompt, chosen, rejected in preference_data: reward_chosen = self.model(prompt, chosen) # 正样本得分 reward_rejected = self.model(prompt, rejected) # 负样本得分 # Bradley-Terry模型: P(prefer A) = sigmoid(score_A - score_B) # 损失: -log(sigmoid(reward_chosen - reward_rejected)) loss = -F.logsigmoid(reward_chosen - reward_rejected).mean() loss.backward() def stage3_rl_finetune(self, prompts: List[str], reward_model): """ 阶段3: PPO强化学习微调 """ for prompt in prompts: # 1. 用当前策略生成回答 response = self.model.generate(prompt) # 2. Reward Model评分 reward = reward_model(prompt, response) # 3. KL散度惩罚 - 与参考模型的距离 with torch.no_grad(): ref_response = self.ref_model.generate(prompt) kl_penalty = self.compute_kl(response, ref_response) # 4. 带KL约束的PPO更新 final_reward = reward - self.config.kl_coef * kl_penalty self.ppo_update(final_reward)

🔍 RLHF的工程挑战

• 需要同时加载多个模型（策略、参考、奖励、价值）
• 训练不稳定，需要仔细调参
• 奖励黑客（Reward Hacking）问题
• KL散度系数敏感度高

二、DPO：简化版的对齐方案

DPO (Direct Preference Optimization) 将RLHF的三阶段简化为直接策略优化。

"DPO的核心洞察：不需要显式训练Reward Model，不需要PPO，只需要一个简化损失函数，就能实现对齐。这个洞察来自于对RLHF目标函数的数学推导。"

DPO数学推导

dpo_formula.md
# DPO从RLHF目标函数推导而来 # RLHF原始目标（带KL约束的Reward最大化）: # max_θ E[r_θ(x, y)] - β · KL[π_θ(y|x) || π_ref(y|x)] # 这个目标的解可以写成: # π_θ(y|x) ∝ π_ref(y|x) · exp(r_θ(x, y)/β) # 由此可以推导出Reward函数: # r_θ(x, y) = β · log(π_θ(y|x) / π_ref(y|x)) # DPO的损失函数（用偏好对替代显式Reward）: # L_DPO = - E_{(x, y_w, y_l)~D} [ log σ( r_θ(x, y_w) - r_θ(x, y_l) ) ] # 代入Reward表达式: L_DPO = - E_{(x, y_w, y_l)} [ log σ( β · log(π_θ(y_w|x) / π_ref(y_w|x)) - β · log(π_θ(y_l|x) / π_ref(y_l|x)) ) ] # 简化后: L_DPO = - E_{(x, y_w, y_l)} [ log σ( β · [ log ratio(y_w) - log ratio(y_l) ] ) ] # 其中: log ratio(y) = log(π_θ(y|x) / π_ref(y|x))

DPO实现简洁，只需实现一个损失函数。

dpo_trainer.py
import torch import torch.nn.functional as F from torch.utils.data import DataLoader class DPOTrainer: """ Direct Preference Optimization 实现 参考: https://arxiv.org/abs/2305.18290 """ def __init__(self, model, ref_model, beta: float = 0.1): self.model = model # 待优化的策略模型 self.ref_model = ref_model # 参考模型（冻结） self.beta = beta # KL散度温度系数 def compute_logprobs( self, model, input_ids: torch.Tensor, labels: torch.Tensor, attention_mask: torch.Tensor ): """ 计算给定模型的log概率 用于DPO中的比率计算 """ output = model( input_ids=input_ids, attention_mask=attention_mask, labels=labels ) # 返回每个token的log概率（用于计算序列概率） return output.logits.log_softmax(dim=-1) def dpo_loss( self, prompt_ids: torch.Tensor, # 提示token IDs chosen_ids: torch.Tensor, # 正样本（被选中的回答） rejected_ids: torch.Tensor, # 负样本（被拒绝的回答） prompt_mask: torch.Tensor, chosen_mask: torch.Tensor, rejected_mask: torch.Tensor ): """ DPO核心损失函数 目标: 提高正样本的相对概率，降低负样本的相对概率 """ # 1. 计算策略模型的log概率 policy_chosen_logprobs = self.get_token_logprobs( self.model, prompt_ids, chosen_ids, chosen_mask ) policy_rejected_logprobs = self.get_token_logprobs( self.model, prompt_ids, rejected_ids, rejected_mask ) # 2. 计算参考模型的log概率 with torch.no_grad(): ref_chosen_logprobs = self.get_token_logprobs( self.ref_model, prompt_ids, chosen_ids, chosen_mask ) ref_rejected_logprobs = self.get_token_logprobs( self.ref_model, prompt_ids, rejected_ids, rejected_mask ) # 3. 计算对数优势 (log ratio) # log π_θ(y|x) - log π_ref(y|x) chosen_log_ratio = (policy_chosen_logprobs - ref_chosen_logprobs).sum() rejected_log_ratio = (policy_rejected_logprobs - ref_rejected_logprobs).sum() # 4. DPO损失: -log σ(β · (chosen_log_ratio - rejected_log_ratio)) # 等价于最小化: -log σ(β · advantage) advantage = chosen_log_ratio - rejected_log_ratio loss = -F.logsigmoid(self.beta * advantage).mean() # 5. 可选: 添加KL散度正则项防止跑偏 # L = loss + α · KL(π_θ || π_ref) return loss def get_token_logprobs(self, model, prompt_ids, response_ids, mask): """ 辅助函数: 计算响应部分的token log概率 """ input_ids = torch.cat([prompt_ids, response_ids], dim=1) labels = torch.cat([ torch.zeros_like(prompt_ids), # prompt部分不计算loss response_ids # response部分计算loss ], dim=1) output = model(input_ids) logits = output.logits # 计算token级别的log概率 log_probs = F.log_softmax(logits, dim=-1) token_log_probs = torch.gather( log_probs, dim=2, index=labels.unsqueeze(2) ).squeeze(2) # 只取响应部分的概率（根据mask） response_mask = mask * (labels != -100).float() return (token_log_probs * response_mask).sum(dim=1)

📌 为什么DPO能work？

DPO不是"绕过"RLHF，而是从数学上证明了在给定偏好对的情况下，可以直接优化策略而不需要显式学习Reward函数。核心是隐式包含了KL约束。

三、KL散度：约束的核心

KL散度在RLHF/DPO中扮演关键角色，是防止模型"跑偏"的数学保证。

kl_divergence.py
# KL散度定义与性质 # KL(P || Q) = Σ P(x) · log(P(x) / Q(x)) # = E_P[log(P(x) / Q(x))] # = - E_P[log(Q(x) / P(x))] # KL散度的核心性质: # 1. 非负性: KL(P||Q) >= 0 # 2. 非对称性: KL(P||Q) ≠ KL(Q||P) # 3. 连锁规则: KL(P||Q) + KL(Q||R) >= KL(P||R) import torch import torch.nn.functional as F def kl_divergence(p_log_probs: torch.Tensor, q_log_probs: torch.Tensor): """ 计算KL散度 P: 参考模型分布, Q: 当前策略分布 KL(P||Q) = Σ P(x) · log(P(x)/Q(x)) = Σ P(x) · log P(x) - Σ P(x) · log Q(x) = -H(P) + E_P[-log Q(x)] """ # 使用PyTorch的kl_div函数 # 注意: kl_div输入的是log_probs return F.kl_div(p_log_probs, q_log_probs, reduction='batchmean') # 在RLHF/DPO中的作用: def kl_constrained_loss( policy_logprobs: torch.Tensor, ref_logprobs: torch.Tensor, reward: torch.Tensor, kl_coef: float = 0.04 ): """ 带KL约束的损失函数 L = reward - β · KL(π_θ || π_ref) 直观理解: - 最大化reward: 让模型生成更高分的回答 - 最小化KL: 约束不要偏离原始模型太远 - β系数: 控制"对齐程度" vs "保持能力"的平衡 """ # 计算KL散度 kl = kl_divergence(ref_logprobs, policy_logprobs) # 带KL惩罚的总损失 # 注意是减法: reward - β*KL return -(reward - kl_coef * kl)

💡 KL散度系数β的选择

• β太小: 模型过度优化，偏离原始能力，可能产生"奖励黑客"
• β太大: 模型几乎不变，对齐效果不明显
• 典型值: 0.01-0.2，InstructGPT用0.04

import torch import torch.nn as nn from transformers import AutoModel class RewardModel(nn.Module): """ Reward Model: 学习人类偏好 输入: (prompt, response)，输出: 评分 核心思想: Bradley-Terry模型 P(prefer A over B) = sigmoid(score(A) - score(B)) """ def __init__(self, base_model_name: str): super().__init__() self.base_model = AutoModel.from_pretrained(base_model_name) self.reward_head = nn.Linear( self.base_model.config.hidden_size, 1, bias=False ) def forward(self, input_ids, attention_mask): # 获取最后一层隐藏状态 outputs = self.base_model( input_ids=input_ids, attention_mask=attention_mask ) last_hidden = outputs.last_hidden_state # 只取第一个token (START) 的hidden state作为reward reward = self.reward_head(last_hidden[:, 0, :]).squeeze(-1) return reward def compute_loss(self, chosen_rewards, rejected_rewards): """ 偏好学习损失函数 目标: chosen_reward > rejected_reward 损失: -log σ(chosen_reward - rejected_reward) 当 chosen > rejected 时，损失趋近于0 """ # sigmoid cross-entropy loss loss = -torch.nn.functional.logsigmoid( chosen_rewards - rejected_rewards ).mean() return loss # 数据格式示例 # preference_data = [ # { # "prompt": "如何学习Python?", # "chosen": "建议从基础语法开始...", # 人类偏好这个回答 # "rejected": "Python很难，不建议学" # 人类不喜欢这个回答 # }, # ... # ]
ppo_core.py - PPO核心更新
import torch import torch.nn as nn class PPOEngine: """ PPO算法的核心实现 包含: GAE优势估计 + PPO裁剪更新 """ def compute_gae( self, rewards: torch.Tensor, # [T] 奖励序列 values: torch.Tensor, # [T] 价值估计 last_value: torch.Tensor, # 最后一个状态的价值 gamma: float = 0.99, lam: float = 0.95 ): """ GAE (Generalized Advantage Estimation) 优势函数估计 - 平衡偏差与方差 A_t = Σ (γλ)^k · δ_t+k 其中 δ_t = r_t + γV(s_t+1) - V(s_t) λ 控制了偏差-方差的平衡: - λ=1: 高方差，低偏差 - λ=0: 低方差，高偏差 """ T = len(rewards) advantages = torch.zeros(T) last_advantage = 0 for t in reversed(range(T)): # TD误差 if t == T - 1: next_value = last_value else: next_value = values[t + 1] delta = rewards[t] + gamma * next_value - values[t] # GAE递归公式 advantages[t] = last_advantage = delta + gamma * lam * last_advantage # returns = advantages + values returns = advantages + values return advantages, returns def ppo_update( self, log_probs: torch.Tensor, # 当前log概率 old_log_probs: torch.Tensor, # 旧log概率 advantages: torch.Tensor, # 优势函数 epsilon: float = 0.2 ): """ PPO裁剪更新 L^CLIP(θ) = E[ min(r(θ)·A, clip(r(θ), 1-ε, 1+ε)·A) ] 其中 r(θ) = π_θ(a|s) / π_OLD(a|s) """ # 策略比率 ratio = torch.exp(log_probs - old_log_probs) # 双保险: min(未裁剪目标, 裁剪目标) # 这样既鼓励了策略提升，又限制了过大更新 unclipped_objective = ratio * advantages clipped_objective = torch.clamp(ratio, 1-epsilon, 1+epsilon) * advantages # 取较小的那个（更保守） objective = -torch.min(unclipped_objective, clipped_objective).mean() return objective

🔧 RLHF/DPO工程技巧

1. 梯度累积应对显存不足
accumulate_steps = 4，小batch累积后更新

2. 混合精度加速训练
model = model.bfloat16() + GradScaler

3. 参考模型用eval模式 + no_grad
节省显存，只有策略模型需要梯度

4. Reward Normalization
标准化reward可以稳定训练

5. KL系数渐进调整
从大β开始，逐步减小，让模型平滑过渡

optimization_tricks.py
# RLHF训练稳定性技巧 from torch.cuda.amp import autocast, GradScaler class StableRLHFTrainer: def __init__(self, model, ref_model): self.model = model self.ref_model = ref_model.eval() # 冻结参考模型 self.scaler = GradScaler() def train_step(self, batch): with autocast(): # 1. 生成响应 with torch.no_grad(): response = self.model.generate(batch['prompt_ids']) # 2. Reward评分 reward = self.reward_model(batch['prompt'], response) # 3. Reward Normalization (稳定性技巧) reward = (reward - reward.mean()) / (reward.std() + 1e-8) # 4. 计算KL散度 kl = self.compute_kl(response, ref_response) # 5. 带KL惩罚的loss loss = -reward.mean() + self.kl_coef * kl # 6. 混合精度反向传播 self.scaler.scale(loss).backward() self.scaler.step(self.optimizer) self.scaler.update()

🎯 面试题 - 点击展开答案

来自真实面试的RLHF/DPO高频问题。

Q1
什么场景必须引入RLHF/DPO？Prompt不能解决什么问题？

必须引入对齐的场景：

  • 复杂价值观对齐：安全、合规、伦理判断（如医疗建议不能推荐危险药物）
  • 隐式偏好学习：用户自己都说不清楚想要什么，但能判断哪个更好
  • 泛化到分布外：Prompt无法枚举所有情况，模型需要"理解"而非"记忆"
  • 风格/语气控制：友好但不啰嗦、专业但不冰冷（难以用规则描述）

Prompt能解决 vs 不能解决：

  • ✅ 能解决：简单任务、一次性需求、明确指令
  • ❌ 不能解决：复杂价值观、隐式偏好、需要泛化的场景
Q2
请解释PPO算法的核心步骤和目标函数

PPO核心步骤：

  • 1. 采样：用当前策略生成样本，计算奖励
  • 2. GAE：用广义优势估计计算优势函数，平衡偏差和方差
  • 3. 计算损失：策略损失 + KL惩罚 + 价值损失
  • 4. 梯度更新：裁剪后更新策略

目标函数：

L^CLIP(θ) = E[ min(r(θ)·A, clip(r(θ), 1-ε, 1+ε)·A) ]

解释：

  • r(θ)：策略比率 = 新策略/旧策略的概率比
  • A：优势函数，正值表示该动作好
  • clip：裁剪函数，限制策略更新幅度不超过(1±ε)
  • min：取较小值，防止过度更新
Q3
DPO相比PPO的优势是什么？为什么DPO能work？

DPO的优势：

  • 训练复杂度低：只需2个模型（策略+参考），PPO需要4个
  • 实现简单：单损失函数，不需要PPO实现
  • 超参数少：只需调beta，PPO有多个敏感参数
  • 样本效率高：直接用偏好对训练
  • 训练稳定：不需要复杂的状态值估计

DPO能work的原理：

  • DPO不是绕过RLHF，而是从数学上等价推导
  • RLHF目标函数经过推导，可以写成用偏好对表示的形式
  • 核心洞察：不需要显式学习Reward函数，可以隐式包含在偏好对优化中
  • KL散度约束被隐式编码到损失函数中

代码层面：

L_DPO = -log σ(β · (log ratio_chosen - log ratio_rejected))

Q4
KL散度在RLHF/DPO中起什么作用？β系数怎么选？

KL散度的作用：

  • 约束不偏离：防止模型过度优化Reward，丧失原始能力
  • 防止奖励黑客：模型找到"作弊"方式获得高分
  • 平衡 trade-off：对齐程度 vs 保持能力的平衡

数学定义：

KL(P||Q) = Σ P(x) · log(P(x)/Q(x))

β系数选择：

  • β太小：过度优化，可能产生"幻觉"、违反安全准则
  • β太大：几乎不变，对齐效果不明显
  • 典型值：InstructGPT用0.04，实践中0.01-0.2不等
  • 建议：从0.1开始，根据效果调整
Q5
RLHF的三阶段各是什么？各自的作用？

阶段1：SFT（有监督微调）

  • 作用：让模型学会"正确回答"——基于高质量问答对
  • 输入：人工标注的(提示, 回答)对
  • 目标：最小化语言模型损失

阶段2：Reward Model（奖励模型）

  • 作用：学习人类偏好——判断回答好坏
  • 输入：(提示, 回答)，输出：评分
  • 目标：chosen回答分数 > rejected回答分数
  • 本质：Bradley-Terry模型的概率建模

阶段3：RL Fine-tuning（强化学习微调）

  • 作用：让模型生成更高Reward的回答
  • 方法：PPO优化策略模型
  • 约束：KL散度防止跑偏
Q6
GAE（广义优势估计）是什么？为什么要用它？

GAE定义：

A_t^GAE(γ,λ) = Σ (γλ)^k · δ_t+k

其中 δ_t = r_t + γV(s_t+1) - V(s_t)

作用：优势函数估计，平衡偏差和方差

  • λ=1：高方差，低偏差（更多依赖实际回报）
  • λ=0：低方差，高偏差（更依赖值函数估计）
  • 典型值：λ=0.95

为什么需要GAE：

  • 单步TD误差方差小但有偏
  • MC回报无偏但方差大
  • GAE通过指数加权，提供可调节的平衡
Q7
手撕：实现DPO损失函数
dpo_loss.py
def dpo_loss( policy_chosen_logprobs: torch.Tensor, # 策略对正样本的log概率 policy_rejected_logprobs: torch.Tensor, # 策略对负样本的log概率 ref_chosen_logprobs: torch.Tensor, # 参考模型对正样本的log概率 ref_rejected_logprobs: torch.Tensor, # 参考模型对负样本的log概率 beta: float = 0.1 ) -> torch.Tensor: """ DPO损失函数 L = -E[ log σ( β · (log ratio_chosen - log ratio_rejected) ) ] 其中 log ratio = log π_θ(y|x) - log π_ref(y|x) """ # 1. 计算log比率 chosen_log_ratio = policy_chosen_logprobs - ref_chosen_logprobs rejected_log_ratio = policy_rejected_logprobs - ref_rejected_logprobs # 2. 计算优势（正样本 vs 负样本） advantage = beta * (chosen_log_ratio - rejected_log_ratio) # 3. sigmoid cross entropy loss = -torch.nn.functional.logsigmoid(advantage).mean() return loss
Q8
实际项目中如何选择DPO还是PPO？

选择建议：

场景推荐方案原因
快速实验/研究DPO实现简单、迭代快
资源受限DPO只需2个模型，显存需求低
追求极致效果PPO/RLHFRL基础，效果通常更好
复杂安全对齐PPO/RLHF更好的KL控制
长文本生成PPO/RLHFDPO在长序列可能不稳定

实际经验：

  • 先用DPO验证效果，达标就不用PPO
  • 如果DPO效果不够，再尝试PPO
  • 混合方案：DPO预训练 + PPO精调
