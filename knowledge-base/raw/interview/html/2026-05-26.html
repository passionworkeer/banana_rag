知识点一：SFT 监督微调全流程
面试高频

一、SFT 是什么？

Supervised Fine-Tuning（监督微调），是在预训练大模型的基础上，用有标签的对话数据微调模型，使其学会理解指令、遵循对话格式、产生符合预期的回复。是 RLHF/DPO 之前的标准流程，也是当前大多数基座模型出厂的必经之路。

二、SFT 标准流程（5 步）

流程全景图

Step 1 预训练模型 → Step 2 数据准备（人工标注/LLM合成） → Step 3 格式化（ChatML） → Step 4 微调训练（LoRA） → Step 5 评测部署

Step 2：数据准备

📊 数据来源

  • 人工标注（高质量但贵）
  • LLM 合成（Self-Instruct）
  • 公开数据集（ShareGPT/Alpaca）
  • 业务日志清洗

✅ 质量要求

  • 多样性（话题/风格/长度）
  • 准确性（标签可信）
  • 安全性（有害内容过滤）
  • 分布对齐（与用户 query 一致）

业界通常 1万～10万条 高质量样本即可见效，远比预训练的万亿 token 少。关键在于质量而非数量。

Step 3：数据格式化（Loss Masking 核心）

用特殊 Token 包装对话，Loss 只在 assistant 回复部分计算：

chatml_format.txt
<|system|>你是一个有帮助的AI助手<|endoftext|> <|user|>你好，介绍一下SFT<|endoftext|> <|assistant|>SFT即监督微调，是在大模型预训练之后...<|endoftext|>

关键点：Loss Masking 策略——system 和 user 的 token 不参与梯度更新，只有 assistant 部分计算 loss。否则模型会"学会说话但不懂问题"。

Step 4：训练配置

  • 学习率：1e-5 ~ 5e-6（比预训练小10～100倍），配合 cosine/linear warmup
  • Epoch：3～5个，数据质量高则3个足够，防止过拟合
  • Batch Size：global batch 8～64，走过拟合曲线
  • LoRA / QLoRA：减少70%显存参数量，业界主流方案

三、如何构建高质量多样化数据集？

🎯 质量维度

  • 人工审核（专业领域必须）
  • Reward Model 筛选打分
  • LLM as Judge（GPT-4 自动评估）
  • DPO 正负样本对比（好/差配对）

🎨 多样性维度

  • 话题：数学/编程/写作/角色扮演/推理
  • 指令格式：开放式/选择题/格式化输出
  • 长度分布：短答/中答/长文均匀覆盖
  • Self-Instruct：用基座模型扩展多样性

⚠️ SFT 常见坑

  • 分布偏移：训练数据与用户query分布不一致 → 上线效果崩塌
  • 长度过拟合：训练集都是长回答，短问题回答质量差
  • 格式崩塌：ChatML标签闭合不严，模型学会乱加标签
  • 幻觉放大：SFT数据中factual错误会被模型放大

知识点二：Attention Scaling 数学原理
数学原理

一、Scaled Dot-Product Attention 公式

Attention(Q, K, V) = softmax(QKᵀ / √dₖ) V

二、为什么需要 Scaling？

假设 Q 和 K 的每个分量都是独立随机变量，均值0，方差1：

Q·K = Σᵢ qᵢ·kᵢ  →  均值 = 0，  方差 = dₖ

当 dₖ 较大时，点积值方差从1增长到 dₖ，导致 softmax 输入 scale 过大：

  • Softmax 趋向 one-hot 输出 → Attention 几乎只关注一个 token
  • 梯度消失，模型难以学习 token 之间的细粒度关系

除以 √dₖ 后方差归一化为1：

Var(QKᵀ / √dₖ) = dₖ / dₖ = 1

🎯 面试回答模板

"Scaled Dot-Product Attention 中除以 √dₖ 是为了防止点积值方差随维度增长导致 softmax 饱和成 one-hot 分布，造成梯度消失。标准做法源自 2017 Transformer 论文，dₖ=64 时 √64=8 是一个经验值，后续 NTK 理论也从数学上证明了这个设计的必要性。"

三、长序列 O(L²) 问题根源

标准 Attention 的空间复杂度是 O(L²)，这是 Transformer 的核心瓶颈：

  • L=4096 tokens → 4096² ≈ 1677万次运算，显存约 64MB（fp16）
  • L=32768（GPT-4 turbo）→ 10亿次运算，显存 1GB+，单层数GB
  • 超过 8192 的序列处理成本急剧上升

原因：完整的 Attention Matrix（N×N）和中间结果全部存入 HBM（显存），导致显存随序列长度平方增长。

知识点三：O(L²) 主流解决方案
工程实践

🔥 FlashAttention（工业首选）

  • 复杂度：O(L²) → O(L) 显存
  • 原理：Tiling + SRAM分级读写
  • 核心：Online Softmax，分块计算
  • 效果：2～4倍吞吐提升，精度无损
  • 代表：FlashAttention-2/3

📐 Sparse Attention

  • 复杂度：O(L·k)，k≪L
  • 原理：只计算局部/随机token的attention
  • 权衡：约1～2%精度损失
  • 代表：BigBird, Longformer

🔄 Linear Attention

  • 复杂度：O(L)
  • 原理：核函数近似，累加替代矩阵乘法
  • 权衡：表达能力弱于标准Attention
  • 代表：Performer, Mamba

📦 Chunk / Segment

  • 复杂度：O(n·L)
  • 原理：分段处理，滑动窗口
  • 权衡：跨chunk信息丢失
  • 代表：StreamingLLM

FlashAttention 核心原理

三大技术创新：

  • Tiling：将 Q/K/V 分成小块，每次只把一块调入 SRAM（高速缓存）计算，避免反复读写 HBM
  • Online Softmax：分块计算 softmax，无需存储完整的 exp(QKᵀ) 矩阵
  • Recomputation：用计算换显存，前向传播丢弃中间结果，反向时重新计算（约30%额外计算时间）

结果：显存从 O(L²) 降到 O(L)，70B 模型从需要 2×80GB A100 → 1×80GB 可跑。

💻 一行开启 FlashAttention

主流推理框架（vLLM、TGI、DeepSpeed）已内置。实际使用时只需开启对应 flag：

transformers_usage.py
from transformers import AutoModelForCausalLM model = AutoModelForCausalLM.from_pretrained( "meta-llama/Llama-2-70b", attn_implementation="flash_attention_2", torch_dtype=torch.bfloat16 ) # vLLM: --attention-backend=flash_attn

知识点四：长上下文信息遗忘 & 多轮对话局限性
Agent 工程

一、为什么模型会"遗忘"早期上下文？

1. 位置衰减（Positional Decay）

Attention Score 对不同位置有隐式权重，距离越远在 softmax 竞争中年均权重越低。实验中 1000 token 后的信息召回率显著下降。

2. KV-Cache 溢出

推理时使用 KV-Cache 加速，长期对话积累极长的 KV cache，超过 Max Tokens 后早期 KV 被淘汰（类似滑动窗口）。

3. 信息淹没

信息在中间层被压缩，早期关键信息可能被后期无关上下文"淹没"，检索时无法正确激活对应 KV。

二、缓解机制

🔧 工程方案

  • KV Cache 压缩（StreamingLLM）
  • 分层记忆（近期/短期/长期）
  • 信息回溯（定期总结写入外部记忆）
  • 滑动窗口Attention（H2O）

🏗️ 架构方案

  • Mamba/Linear Attention（O(L)复杂度）
  • RAG 补充（历史关键信息向量化）
  • Memory Bank（专用记忆模块）
  • Recurrent Episodic Memory

三、多轮对话中 Attention 的局限性

  • 历史累积干扰：每轮新增 query 都与全部历史做 Attention，噪声干扰当前回复
  • 层级坍缩：随对话轮次增加，模型各层表征趋于同质化
  • 计算成本爆炸：第N轮需要 N×avg_tokens 的 attention，成本线性增长

🤖 工业级 Agent 解法（LangGraph 实践）

用「分层记忆 + 主动检索」替代纯 Attention：

  • ① 最近 3～5 轮 → 直接塞入 context（高保真）
  • ② 更早对话 → 向量化存入 memory store，检索时动态召回
  • ③ 关键结论 → 显式写入 summary，避免被 Attention 淹没

💼 SFT 的产品价值

🎯 SFT 是模型「调性」的最后一公里

预训练模型像一个博学但任性的人，SFT 教会它在什么场景说什么话。直接决定用户感知到的模型性格——专业、俏皮、严谨还是简洁。

⚠️ 数据质量决定产品体验

  • 数据多样性不够 → 模型只会聊特定话题
  • 数据有偏见 → 产品上线后引发舆论风险
  • 长度分布失衡 → 用户问短问题，模型给长篇大论

📊 哪些场景需要长上下文？

  • 合同审查：上传100页PDF，需要全篇理解
  • 代码库理解：几十个文件一次性分析
  • 长文章摘要：万字文章一次性总结
  • Agent 记忆：跨数十次会话的长期上下文

💰 商业价值与成本权衡

超长任务断点续生成

问题：单次输出超过 Max Tokens（8192）限制 → 用 ChunkedGenerator 分片输出并存储断点：

chunked_generator.py
class ChunkedGenerator: def generate(self, prompt, checkpoint_id=None): if checkpoint_id: state = self.load_checkpoint(checkpoint_id) self.chunks = state["chunks"] accumulated = self.build_prompt(state) else: accumulated = prompt while True: response = self.model.generate( accumulated, max_tokens=self.max_tokens ) if len(response.tokens) < self.max_tokens: self.chunks.append(response) break # 保存断点，继续生成 self.chunks.append(response) ckpt = self.save_checkpoint(self.chunks) accumulated = self.build_continuation(response, ckpt) yield {"status": "checkpoint", "checkpoint_id": ckpt} return "".join(c.text for c in self.chunks) # 使用：流式中断，随时可恢复 for event in generator.generate(long_prompt): if event.get("status") == "checkpoint": print(f"进度: {event['checkpoint_id']}")

🎯 面试题库
1 Attention 为什么需要 Scaling？写出完整公式 ▼

公式：Attention(Q,K,V) = softmax(QKᵀ / √dₖ) V

原因：Q 和 K 的点积均值=0，方差随维度 dₖ 增长到 dₖ。除以 √dₖ 后方差归一化为1，防止 softmax 输入过大导致饱和成 one-hot 分布（梯度消失）。

面试加分：这是 2017 Transformer 原论文的经验性设计，后续 Neural Tangent Kernel（NTK）理论从数学上证明了这个缩放因子的必要性。当 dₖ=64 时 √dₖ=8 是一个温和的缩放值。

2 长序列 O(L²) 问题有哪些解法？各有什么优缺点？ ▼
  • FlashAttention：Tiling + SRAM + Recompute，显存 O(L²)→O(L)，精度无损，工业界首选
  • Sparse Attention：BigBird/Longformer，O(L·k)，约1～2%精度损失，适合超长序列
  • Linear Attention：Performer/Mamba，O(L)，理论上无限长，但表达能力弱于标准 Attention
  • Chunk 分段：StreamingLLM，O(n·L)，简单有效，但跨 chunk 信息丢失
3 模型在长上下文对话中容易遗忘信息，原因是什么？ ▼
  1. 位置衰减：Attention 权重对远距离 token 天然偏低，早期信息在 softmax 竞争中处于劣势
  2. KV-Cache 溢出：超过 Max Tokens 后，早期 KV 被截断淘汰
  3. 信息淹没：长序列中无关上下文会稀释关键信息的激活强度
  4. 中间压缩：信息在中间层被压缩，可能丢失
4 SFT 的完整流程是什么？如何构建高质量数据集？ ▼

SFT 流程：预训练模型 → 数据准备（标注/合成）→ ChatML 格式化 → Loss Masking 配置 → 微调训练（LoRA）→ 评测（Chatbot Arena）→ 部署

高质量数据集三要素：

  • 质量：人工审核 + LLM as Judge + Reward Model 筛选
  • 多样性：话题/长度/指令格式均匀覆盖 + Self-Instruct 扩展
  • 分布对齐：SFT 数据与线上用户 query 分布一致（上线效果核心保障）
5 单次生成超过 Max Tokens 限制怎么处理？ ▼
  1. Checkpoint 保存：每生成一个 chunk 保存中间状态（KV cache + 生成进度）
  2. Continual Generation：用「已生成内容 + checkpoint ID」构建新 prompt 继续生成
  3. 主动截断：判断接近 max_tokens 时主动停止，保存状态，等待下一轮调用
  4. 分段设计：从产品层面拆解任务为多个子任务，分次完成
6 FlashAttention 的核心思想是什么？ ▼

利用 GPU SRAM 的高速读写特性，把 attention 矩阵分块（Tiling）调入 SRAM 计算，配合 Online Softmax 无需存储完整的 exp(QKᵀ) 矩阵。核心是用计算换显存：前向传播丢弃中间结果，反向传播时重新计算（约30%额外计算，换取显存从 O(L²) 到 O(L)）。三大技术：Tiling + Online Softmax + Recomputation。
