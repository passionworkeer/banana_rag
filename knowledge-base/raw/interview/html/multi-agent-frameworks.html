一、为什么需要专门的 Multi-Agent 框架

  • multi-agent.html 讲架构模式（Router / Supervisor / Debate / Handoff / Hierarchical），那一层是"设计模式"。
  • 框架层解决：把对话流转、角色定义、状态共享、消息总线、终止条件——这些共性代码封装好，让你只写业务。
  • 手撸 LangChain AgentLoop 也能做多 Agent，但通信 / 状态 / 工具调用每个项目都重写一遍。
  • 专用框架把"角色 + 任务 + 流程"标准化：Role / Agent / Crew / GroupChat，约定大于配置。
  • 生态贡献可复用 Toolset、Memory、Observability（LangSmith、Arize、MLflow 等）。
判断口诀：1~3 个 Agent 的简单编排用 LangGraph 写图；≥3 个角色 + 流程化任务用 CrewAI；研究/对话驱动探索用 AutoGen；模拟组织生产软件用 MetaGPT / ChatDev。

三、AutoGen GroupChat 时序图

User 发起任务 → GroupChatManager 选下一发言人（LLM 决定 / 轮询）→ 各 Agent 依次回复 → 评审 / 拍板 → 终止条件满足 → 回传 User。GroupChatManager 是隐性 Supervisor。

四、CrewAI：Role + Task + Crew

三大核心对象：Role（人设 + 工具 + 目标）、Task（具体工作 + 期望产出 + 上下文依赖）、Crew（团队 = 角色集合 + 任务集合 + 执行流程）。

from crewai import Agent, Task, Crew, Process

researcher = Agent(
  role="Research Analyst",
  goal="挖掘 {topic} 的关键事实",
  backstory="10 年行业研究经验，擅长信息整合",
  tools=[search_tool, scrape_tool],
  verbose=True,
)
writer = Agent(
  role="Tech Writer",
  goal="把研究产出写成可发布文章",
  backstory="深度技术作者，擅长结构化表达",
  tools=[md_tool],
)

t1 = Task(description="搜索并整理 {topic} 的 5 个关键点",
         expected_output="Markdown 要点清单", agent=researcher)
t2 = Task(description="基于 t1 要点撰写 1500 字长文",
         expected_output="完整 Markdown 文章", agent=writer,
         context=[t1])  # 链式依赖

crew = Crew(agents=[researcher, writer],
            tasks=[t1, t2],
            process=Process.sequential,
            verbose=2)
result = crew.kickoff(inputs={"topic": "PagedAttention"})

五、CrewAI Process 流程（SVG）

Sequential：按任务列表顺序执行，context 显式声明依赖；Hierarchical：内置 Manager Agent 动态委派任务给 Agent，适合需要协调的复杂工作流。

六、MetaGPT 软件公司组织结构

SOP（标准作业流程）驱动：PM 写 PRD → Architect 设计 → PM 分配任务 → Engineer 编码 → QE 写测试 → Reviewer 审查。所有产物进 MessagePool，订阅者自动拉取。

七、AutoGen 实战代码

from autogen import AssistantAgent, UserProxyAgent, GroupChat, GroupChatManager

llm_cfg = {"config_list": [{"model": "gpt-4o"}]}

coder = AssistantAgent("Coder",
  llm_config=llm_cfg,
  system_message="你是 Python 工程师，输出可执行代码。")
reviewer = AssistantAgent("Reviewer",
  llm_config=llm_cfg,
  system_message="你是高级架构师，评审代码并提出改进。")
pm = AssistantAgent("PM",
  llm_config=llm_cfg,
  system_message="你是 PM，决定是否接受产出，TERMINATE 表示通过。")

user = UserProxyAgent("User",
  human_input_mode="TERMINATE",  # 关键节点才问
  code_execution_config={"work_dir": "out"})

chat = GroupChat(agents=[user, coder, reviewer, pm],
  messages=[], max_round=12,
  speaker_selection_method="auto",
  allow_repeat_speaker=False)

manager = GroupChatManager(groupchat=chat, llm_config=llm_cfg)
user.initiate_chat(manager,
  message="写一个 PagedAttention 简化版 demo（≤80 行）")

八、CrewAI + LangChain 工具集成

from langchain.tools import tool
from crewai import Agent

@tool("search")
def search(q: str) -> str:
    """搜索关键词，返回前 3 条结果摘要"""
    # 实际接入 SerpAPI / Tavily
    return f"结果：{q}"

researcher = Agent(
  role="Researcher",
  goal="找到 {topic} 的最新论文",
  backstory="学术搜索专家",
  tools=[search],          # LangChain tool 直接复用
  allow_delegation=False,  # 是否可把任务转交
  max_iter=5,
)

CrewAI 工具层复用 LangChain 的 BaseTool 生态，零迁移成本。

十、10 条面试 FAQ

1. AutoGen 和 CrewAI 区别？

AutoGen 是对话驱动（消息总线 + GroupChatManager 选下一发言人），适合研究 / 工具探索 / 自由对话；CrewAI 是流程驱动（Task 链 + Sequential/Hierarchical），适合业务流自动化、内容生产线。

2. MetaGPT 适合什么场景？

模拟软件公司组织自动生产代码（PRD → 设计 → 实现 → 测试），适合教学 / 快速生成小型工具 / 论文复现，但成本高、速度慢，复杂业务慎用。

3. AutoGPT 还能用吗？

能用但不是生产首选。自循环模式易陷入循环、token 浪费大；现在生产里更多用 LangGraph / CrewAI 的受控流程。可作"自主 Agent 概念演进"的史料讲解。

4. LangGraph 和这些框架什么关系？

LangGraph 是底层图编排，CrewAI / AutoGen 内部循环或复杂状态切换会用 LangGraph 重写（如 CrewAI 的 Hierarchical 后端）。

5. 怎么选？研究 / 业务 / 复杂状态机

研究 / 工具探索选 AutoGen；业务流（客服 / 报告 / 营销）选 CrewAI；需要精细状态 / 中断 / 并行分支选 LangGraph；模拟组织选 MetaGPT。

6. Hierarchical vs Sequential 怎么选？

任务有明确依赖链用 Sequential（更可控、可调试）；任务需要动态分配用 Hierarchical（Manager Agent 决定谁做什么，更灵活但成本高、调试难）。

7. Multi-Agent 框架的代价？

Token 成本 3-10x 单 Agent（每步都过 LLM）、延迟叠加、调试困难（哪个 Agent 出错难定位）、容易陷入循环。80% 场景单 Agent + 工具就够。

8. 怎么避免多 Agent 死循环？

设max_round / max_iter、is_termination_msg 显式终止 token、speaker_selection 限制候选、引入人类审批 Human-in-the-Loop、循环检测器（消息去重）。

9. 状态共享怎么做？

三种方式：①消息历史（AutoGen 风格，简洁但无结构）；②共享文档 / 内存（MetaGPT MessagePool，CrewAI Task context）；③外部存储（Redis / Vector DB，跨会话持久化）。

10. 多 Agent 系统的可观测性？

用 LangSmith / Arize / MLflow 跟踪每步消息；记录 Speaker、Token、耗时、工具调用；为每条消息打 trace_id 串联；OpenTelemetry 标准化导出。

十一、回答模板（30 秒版）

问："Multi-Agent 框架怎么选？"
答："先看任务是否真要多 Agent——80% 场景 LangGraph 单图就够。确定要多 Agent 后按场景选：研究 / 工具探索用 AutoGen，对话驱动灵活；业务流自动化用 CrewAI，Role + Task 约定清晰；复杂状态机 / 精细控制用 LangGraph，TypedDict State + interrupt；模拟软件公司用 MetaGPT 组织 SOP。生产里我现在倾向于CrewAI 做编排 + LangGraph 做底层，配合 LangSmith 做 trace，平衡开发效率和可观测性。"
