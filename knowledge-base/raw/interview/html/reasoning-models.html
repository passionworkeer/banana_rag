Reasoning 模型：让 LLM 在"想"上花更多算力

OpenAI o1 / o3、DeepSeek-R1、Claude 3.7 Sonnet Thinking 共同开启的范式：模型先生成"内部思维链"（internal CoT）、再给最终答案。关键洞察是"test-time compute scaling"——推理时给更多算力，模型可以"涌现"出更强推理。本页讲清 internal CoT 机制、test-time scaling 原理、蒸馏、与 RLHF 关系。

二、Internal CoT 是什么

用户看不到、但模型"在内部"生成了长思维链——思考、试错、回溯、验证。o1 系列的 CoT 平均 5K-50K token，是普通回答的 5-50x。
  • Hidden：API 不返回中间 CoT，只返回最终答案（商业壁垒 + 避免污染）
  • Native：不是"先想后答"的 prompt 技巧，是 RL 训练出来的内在能力
  • Self-Correction：CoT 中包含自我质疑、回滚路径
  • Verification：CoT 中包含对中间步骤的验证
  • Strategy Switch：复杂问题用 explore、简单问题用 direct

三、Test-Time Compute Scaling

传统 scaling：训练时堆参数

Test-time scaling：推理时堆算力

— — —

4 种 trade-off：

① Best-of-N：采样 N 个回答，Verifier 选最佳

② Beam Search：思维树搜索 + 评估

③ Self-Refine：生成 → 反思 → 改进循环

④ Process Reward：每步 reward（PRM）

Snell et al. 2024 论文证明：在数学 / 代码任务上，test-time compute 提升 4x 等价于模型大 2-3x。o1 / R1 走的是 PRM 路径。

五、PRM vs ORM

  • ORM（Outcome Reward Model）：只对最终答案打分（DeepSeek-R1 用规则 RM 算 ORM）
  • PRM（Process Reward Model）：对每一步中间思考打分（o1 路线）
  • PRM 优势：信号密集、训练更稳、避免"结果对但过程错"的奖励黑客
  • PRM 难点：需要标注每步正误（数据成本高）、PRM 自身也容易被 hack
  • R1 路径：纯规则 RM（数学 / 代码）也能训出 reasoning，证明 ORM 在可验证任务上够用

六、Reasoning 模型适用场景

  • 数学 / 竞赛题：AIME / MATH / Olympiad 显著提升
  • 代码 / 调试：复杂算法、长链调用
  • 科学推理：物理 / 化学 / 生物推断
  • 多步规划：Agent 任务规划、决策
  • 难题拆解：复杂查询分解、子问题链
不适用：闲聊、简单抽取、情感对话。Reasoning 模型在简单任务上既慢又贵（CoT 浪费 token）。

七、面试 FAQ

Q1：Reasoning 模型和 CoT prompt 区别？

A：CoT prompt 是"用 prompt 技巧让模型在回答前思考"，是表面引导。Reasoning 模型是"通过 RL 训练让模型在内部 CoT 上花算力"，是内在能力。R1 / o1 即使没有 CoT prompt 也会"自然地"内部思考。CoT prompt 可叠加（让 R1 效果更好），但本质不同。

Q2：Test-time compute scaling 为什么有效？

A：模型在面对难题时，简单的"一步推理"不够——需要"探索-验证-回溯"。test-time compute 让模型可以采样多路径、比较、自我纠错。数学 / 代码任务尤其受益，因为有客观对错可以验证。

Q3：R1-zero 和 R1 区别？

A：R1-zero：纯 GRPO 训，无 SFT 冷启动——模型自己"涌现"推理但有可读性差 / 语言混杂问题。R1：先 SFT 冷启动（用 R1-zero 生成的样本）再 GRPO——可读性恢复 + 推理能力保留。R1 才是发布版。

Q4：Reasoning 模型怎么蒸馏？

A：用大 Reasoning 模型生成（question, internal CoT, answer）三元组，作为 SFT 数据训小模型。DeepSeek 蒸馏 1.5B-70B 系列，号称 32B 蒸馏版超过 o1-mini。关键：蒸馏学的是"思维模式"而非只学"答案"。

Q5：为什么 Reasoning 模型成本高？

A：内部 CoT 平均 5K-50K token，是普通回答 5-50x；长 CoT 占大量 GPU 时间；API 按 token 收费时成本爆炸。但对难题"贵"换"准"的 trade-off 是值得的。

Q6：Reasoning 模型与传统 GRPO 训出来的模型区别？

A：传统 GRPO 训的模型（如 Qwen2.5-Math）有"能思考"的能力但没有"习惯思考"——需要 prompt 触发。Reasoning 模型是"默认思考"——不需 prompt 就内部 CoT。差别在 RL 训练强度 / 数据量 / 推理阶段。

Q7：How to evaluate Reasoning 模型？

A：① 推理基准（AIME / MATH / GPQA / Codeforces）；② token 效率（每题用多少 CoT token）；③ 简单任务不掉点（不能"过度思考"）；④ CoT 质量（人评 CoT 逻辑 vs 仅看答案）。只看最终答案分数会低估 PRM 路线模型。

Q8：Reasoning 模型和 self-consistency 关系？

A：self-consistency 是"test-time compute scaling"的简单版（采样 N 投多数票），不改变模型本身。Reasoning 模型是"模型自身在生成时就做 test-time compute"，对每个 query 内部采样 + 探索 + 验证。Reasoning 模型是"内化"的 test-time scaling。

八、回答模板与加分项

30 秒电梯版

Reasoning 模型是 2024-2025 的新范式（o1 / R1 / Claude 3.7 Thinking）：模型在内部生成长 CoT、test-time compute scaling。核心原理：推理时堆算力（PRM / self-correction / verifier）= 训练时堆参数。代表路径：OpenAI PRM、DeepSeek 纯 GRPO + 规则 RM。适合数学 / 代码 / 复杂规划，不适合简单对话。

5 分钟深入版

从动机（GPT-4 在 AIME 上只 13% 提升困难）→ internal CoT 机制 → test-time compute scaling 4 种 trade-off → PRM vs ORM 对比 → o1 / R1 / Claude 3.7 三大代表 → R1-zero vs R1 演进 → 蒸馏路径（DeepSeek R1-Distill）→ 适用边界。能讲清"为什么 PRM 路线和 ORM 路线都成功"、"为什么蒸馏 32B 超过 o1-mini"，立刻显得跟得上时代。

加分：项目案例

讲一次"用 R1 替代 GPT-4 的成本/效果 trade-off"——比如某业务难题 GPT-4 准确率 60%、R1 用 30K CoT 准确率 80% 但成本 +15x，最终混合方案：简单题 GPT-4、难题 R1，单题成本 +2x、准确率 +20%。

加分：知道局限

Reasoning 模型不是银弹：① 简单任务上"过度思考"既慢又贵；② 内部 CoT 不可见导致可解释性差；③ 训练成本极高（大量 RL 计算）；④ 不适合实时场景（CoT 太长）。诚实说"Reasoning 模型在'需要验证 + 客观对错'的任务上一枝独秀"得分更高。
