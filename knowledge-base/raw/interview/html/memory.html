Agent 记忆

短期 / 长期记忆机制，让模型在长对话中保留用户偏好和历史上下文。记忆分层 + 压缩策略 + 冲突更新是面试三大重点。

Working MemoryEpisodicSemanticCompressionConflict

一、Agent 记忆分层

  • 四层记忆模型（类比人脑）：
    • Working Memory（工作记忆）：当前对话上下文，存于 prompt / 上下文窗口
    • Episodic Memory（情景记忆）：过去发生的事件序列，存于向量库 + 时间戳
    • Semantic Memory（语义记忆）：事实性知识、用户偏好、领域概念，长期持久化
    • Procedural Memory（程序记忆）：技能与流程，由模型权重 + 提示模板承载
  • 短期 vs 长期：
    • 短期：放在 prompt 上下文窗口内，访问快但窗口有限（4k-200k token）
    • 长期：放在向量数据库 / KV 存储 / 文件系统，访问需检索但容量大
    • 分层策略：高频偏好 → 短期、累计事实 → 长期，检索时按场景混合
  • 压缩策略（解决上下文爆炸）：
    • 摘要：用 LLM 把 N 段对话压缩成 1 段摘要（保留率 5-10 倍）
    • 抽取：用规则或模型从对话中抽取关键事实（user_prefs、events）
    • 滑动窗口：保留最近 K 轮 + 长期摘要（最简单但容易丢早期信息）
    • 分层压缩：旧对话→摘要、摘要→更高层摘要，递归降采样
  • 冲突更新（同一条记忆被改写怎么办）：
    • 时间戳：记忆条目带 last_updated 字段，新覆盖旧
    • 版本号：同 key 多版本共存，检索时取最新
    • 显式覆盖：用户说"我改了地址"→ 触发 LLM 删除旧 + 写入新
    • 冲突标记：检测到矛盾时给用户确认（"你之前说 A，现在是 B，要保留哪个？"）

二、记忆架构

Agent 持 Working Memory 跑实时对话；溢出或会话结束后通过 LLM 抽取写入 Episodic（事件流）和 Semantic（事实库），再 Embedding 落到 Vector DB。下次会话开始时按需召回拼回上下文。

三、记忆压缩率

$$\mathrm{compression\_ratio} = \frac{\text{原始对话 token 数}}{\text{压缩后 token 数}}$$

典型值：摘要压缩 5-10x、事实抽取 10-50x、滑动窗口 ≈ N/总轮次

例：1 段 30 轮客服对话 ≈ 6000 token，LLM 摘要后 ≈ 800 token，压缩比 7.5x；进一步结构化抽取 user_prefs + order_history 可压到 200 token 内，比 30x。

Trade-off：压缩比越高 → 上下文越省 → 但细节可能丢失。生产经验是先做"事实抽取"保关键信息，再叠加"摘要"补充语境，避免只压不抽导致失真。

五、面试 FAQ

Q1：短期和长期记忆怎么划分？

A：按数据生命周期和访问频次。短期在上下文窗口（秒级 / 当前会话）、长期在持久化存储（天级 / 跨会话）；高频热数据用短期、低频冷数据用长期，检索时按场景拼回。

Q2：记忆冲突怎么办？

A：三种机制叠加：时间戳（last_updated 字段）实现新覆盖旧、版本号实现同 key 多版本共存、显式覆盖由用户话语触发 LLM 删除旧 + 写入新。检测到矛盾时优先向用户确认。

Q3：上下文窗口有限怎么压缩？

A：四种策略叠加：摘要（LLM 压缩，5-10x）、抽取（结构化关键事实，10-50x）、滑动窗口（保留最近 K 轮，1/N）、分层递归（旧摘要再压缩，20-100x）。生产经验是先抽后压，保关键信息。

Q4：和 RAG 区别？

A：记忆是会话级个性化（user_id 维度、按场景召回），RAG 是知识库检索（文档级、全局共享）。记忆偏"用户私人上下文"，RAG 偏"领域公共知识"，生产系统通常同时使用：RAG 注入知识、Memory 注入偏好。

Q5：记忆的遗忘机制怎么设计？

A：四种手段：TTL（过期时间）、容量上限（每用户最多 N 条）、显式删除（用户撤回或合规要求）、重要性衰减（长时间未访问降权）。设计原则：用户可控、可解释、有日志。

Q6：多用户隔离怎么做？

A：三个层次：命名空间（user_id 作向量前缀）、独立 collection（每个用户 / 租户一份）、ACL 校验（召回时强制过 user_id 过滤）。生产建议命名空间 + ACL 组合，独立 collection 仅在租户级隔离时用。

Q7：什么时候记忆反而有害？

A：三个反模式：陈旧偏好（用户改了地址没同步）、错误抽取（LLM 把玩笑当事实）、污染 prompt（低质量记忆塞满上下文）。设计时必须有"召回质量评估"和"用户纠正反馈回路"。

Q8：怎么评估记忆系统？

A：三类指标：召回质量（top-K 命中率、MRR）、压缩比（输入 token / 摘要 token）、用户感知（跨会话是否复用偏好、用户是否主动撤回记忆）。建议用 LLM-as-Judge 定期抽检。

回答模板与加分项

30 秒电梯版

面试开场可以这样讲：Agent 记忆分四层 — Working（上下文窗口）、Episodic（事件流）、Semantic（事实库）、Procedural（流程技能）。短期用窗口、长期用向量库，跨会话靠 Embedding 召回；关键设计是压缩（摘要 + 抽取 + 滑动窗口）和冲突更新（时间戳 + 版本号 + 显式覆盖）。

5 分钟深入版

从四层模型 → 读写时序 → 压缩策略 → 冲突治理 → 多用户隔离，逐层展开。最后落到你们项目的记忆系统架构、召回指标、压缩比、错误率。有真实数据能立刻拉开差距。

加分：知道记忆的局限

记忆不是银弹：错误抽取会污染 prompt、陈旧偏好会误导用户、容量爆炸会增加 token 成本。建议结合"用户可控的编辑入口 + 召回质量评估 + 显式遗忘"三件套缓解。

加分：能讲一次踩坑

比如：抽取时把"我以前喜欢蓝色"误存为"喜欢蓝色"导致后续推荐错误；压缩比设太高导致关键订单号丢失；多用户场景下忘了加 user_id 过滤导致跨用户召回。讲一次具体排查过程，面试官会立刻认定你有真经验。

面试官可能怎么追问

追问方向示范追问建议回应思路
分层模型四层记忆分别怎么实现？Working → 上下文窗口；Episodic → 时间序列 + 向量；Semantic → KV + Embedding；Procedural → 提示模板 + 微调。抓住"存储位置 + 生命周期"两个维度。
压缩策略压缩比怎么权衡？答"先抽后压"：先做事实抽取保关键信息，再做摘要补充语境；通过离线评估集调阈值。生产经验是 5-15x 摘要 + 显式抽取组合。
冲突治理用户偏好改了怎么更新？答"检测 + 确认 + 写入"：LLM 检测到"我改地址了"触发 update；新条目带时间戳覆盖旧；如果新旧冲突明显可先向用户确认。结合版本号回溯。
与 RAG 协作记忆和 RAG 怎么配合？答"上下文拼装时按层组装"：System Prompt = 角色定义 + 用户偏好（Memory） + 知识片段（RAG） + 当前对话（Working）。优先级：用户偏好 > 知识片段。
隐私与合规记忆数据怎么保护？答"全链路加密 + 显式遗忘"：存储加密、传输 HTTPS、提供用户删除入口、敏感字段（身份证 / 卡号）不写入记忆；遵循 GDPR / 个保法要求。
最后提示：记忆系统是 Agent 长期演进的关键模块，面试允许说"这块我了解设计模式但没在生产完整做过"，但要能讲清楚分层逻辑 + 给出假设场景的设计。诚实 + 思路清晰 > 假装熟练。
