Mamba / SSM / RWKV：线性注意力的复兴

Transformer 的二次方复杂度是长上下文的硬伤。Mamba（Mamba1/Mamba2）、RWKV、RetNet、Hyena、xLSTM 等"线性注意力 / 状态空间模型（SSM）"用 O(N) 复杂度和常数显存做到了百万级上下文，且推理时不需要 KV Cache。本页把"动机 → 原理 → 5 大家族对比 → 与 Transformer 的 trade-off → 面试 FAQ"一次性串清楚。

一、为什么需要"非 Transformer"架构

  • 复杂度：Transformer 自注意力的时间和显存都是 O(N²)，N 是序列长度。100K context 显存就吃紧
  • 推理 KV Cache：每生成一个 token 要保存所有历史的 K/V，长对话成本线性爆炸
  • 长上下文效率：RULER / NIAH 评测显示 Transformer 实际有效长度远小于标称窗口（Lost in the Middle）
  • 训练成本：长序列训练 GPU 利用率低，FlashAttention / Ring Attention 只是缓解
  • 线性架构目标：O(N) 训练复杂度 + O(1) 推理每步 + 长上下文不掉点
2023-2025 是"线性架构复兴年"：Mamba（2023.12）→ Mamba2（2024.5）→ Jamba（2024.3，AI21 混合 Mamba+Attention）→ Falcon Mamba（2024.8，纯 Mamba 7B 超越同尺寸 Transformer）→ RWKV-7（2025）→ Zamba2（2025，混合）。这条线在 2025-2026 持续被工程化推进。

二、状态空间模型（SSM）基础

SSM 是一类古老的时序模型（控制论 / 数字信号处理），核心是把输入映射到一维隐藏状态，再从状态读出输出。Mamba 的创新是把它"输入依赖"地引入 LLM。

连续时间 SSM

h'(t) = A · h(t) + B · x(t)

y(t) = C · h(t) + D · x(t)

离散化（Zero-Order Hold, Δt 步长）

Ā = exp(Δ · A), B̄ = (Δ · A)⁻¹ (exp(Δ · A) − I) · Δ · B

ht = Ā · ht-1 + B̄ · xt, yt = C · ht

核心结论：当 (A, B, C, Δ) 与输入无关时，SSM 可用卷积计算（O(N log N)）或线性递推（O(N)）。但这是线性时不变系统，记忆有限，模型表达力弱。

三、Mamba 的核心创新：Selective Scan（S6）

Mamba 1（Albert Gu & Tri Dao, 2023.12）把 SSM 的参数 (B, C, Δ) 改成"输入依赖"，让模型可以根据当前 token 决定保留还是遗忘信息——这把 SSM 从"线性时不变"变成"输入相关"，获得了接近注意力的表达力。

Selective State Space

Bt = LinearB(xt), Ct = LinearC(xt), Δt = softplus(LinearΔ(xt))

ht = exp(Δt · A) · ht-1 + Δt · Bt · xt

yt = Ct · ht

关键点：Δt（步长）由当前 token 决定 → "重要 token 用小步长仔细读，无关 token 用大步长快速过"。Mamba2（2024.5）证明 S6 等价于一种结构化掩码注意力（State Space Duality, SSD），把 selective scan 用矩阵乘法高效实现，训练速度提升 2-8x。

记忆口诀："Mamba = SSM + 输入依赖的 (B, C, Δ) + 硬件感知的并行扫描"。Mamba2 的贡献是发现 S6 与注意力有数学对偶（SSD），可以用 GPU 并行化大幅加速。

七、混合架构（Hybrid）

实践发现"全 SSM"在 in-context 检索（ICR）类任务上弱于 Attention，于是出现"Attention + SSM 混合"方案：

  • Jamba（AI21, 2024.3）：8B（52B 总参数 / 12B 激活），每 8 层 1 层 Attention，其余 7 层 Mamba
  • Zamba / Zamba2（Zyphra, 2024-2025）：7B，每 6 层 1 层共享 Attention block
  • Falcon Mamba（TTT lab, 2024.8）：纯 Mamba 7B，首次证明纯 SSM 在多项任务上可与同尺寸 Transformer 持平
  • Granite Hybrid（IBM, 2024）：Mamba2 + 2 层 Attention 块
  • Bamba（IBM, 2025）：9B 参数纯 Mamba2，与 Llama-3 持平
混合方案的好处：① Attention 补 ICR / 复制任务；② SSM 主干保线性效率；③ 平衡显存和长上下文。生产中"7-8 层 Mamba + 1 层 Attention"是常见配置。

八、RWKV 速解（线性注意力 + 衰减）

核心公式（Time-Mix + Channel-Mix）

wkvt = (rt · kt)T vt + exp(−w) · wkvt-1

outputt = (ot · wkvt) / (ot · at)

其中 at = rt · kt + exp(−w) · at-1，w 是可学习的 time-decay（标量）。

特点：训练时等价线性注意力（O(N) 并行），推理时等价 RNN（O(1) 每步），没有 KV Cache。RWKV-7 引入"动态递推 + 通用 delta 规则"，表达力大幅提升。

与 Mamba 区别：RWKV 显式维护 running scalar decay；Mamba 用矩阵 A + 选择性步长 Δ。两者数学上都是线性注意力变体。

十二、面试 FAQ

Q1：Mamba 的核心思想是什么？

A：把 SSM 的参数 (B, C, Δ) 改成"输入依赖"，让模型按当前 token 决定保留 / 遗忘什么。Mamba1 用 selective scan 串行实现，Mamba2 发现 S6 与注意力有 SSD 对偶，可用矩阵乘法并行训练。表达力追平 Transformer，复杂度 O(N)。

Q2：Mamba 为什么不需要 KV Cache？

A：因为 SSM 是递推计算：每步只需维护固定大小 state ht（与上下文长度无关）。不需要保存历史的 K/V，推理时显存 O(1) per step。代价是单步 state 容量有限，ICR 任务弱于 Attention。

Q3：Mamba 1 和 Mamba 2 区别？

A：Mamba1（2023.12）用 selective scan（parallel scan 算法，难并行）。Mamba2（2024.5）发现 S6 与结构化掩码注意力有 SSD（State Space Duality）数学对偶，可用 matmul 训练，吞吐提升 2-8x，硬件实现友好。两者数学表达力等价。

Q4：Mamba 和 RWKV 区别？

A：两者都是线性注意力变体，O(N) 训练 + O(1) 推理。RWKV 显式维护 running scalar decay（time-decay w），每步把过去信息按 w 衰减；Mamba 用矩阵 A + 动态步长 Δ 决定保留 / 遗忘。RWKV-7 引入 delta rule 后表达力追平 Mamba2。

Q5：Mamba 在哪些任务上弱于 Transformer？

A：主要是 In-Context Retrieval（ICR）类任务——需要"从历史任意位置精确提取信息"。如 NIAH（大海捞针）、多 key-value 查找、复杂复制任务。原因：state 容量有限，无法像 Attention 那样动态查全表。混合架构（Jamba、Zamba）通过插入 Attention 层缓解。

Q6：为什么 2024-2025 出现混合架构？

A：纯 SSM 在 ICR / 工具调用上弱于纯 Attention；纯 Transformer 在长上下文显存吃紧。混合方案用 Attention 补 ICR，SSM 主干保线性效率。Jamba（1:8 比例）、Zamba2（1:6）效果最佳。

Q7：Mamba 训练为何能 O(N)？

A：依赖 parallel scan 算法（Blelloch scan）把串行递推并行化。Mamba2 用 SSD 对偶直接用 matmul，更快。显存 O(N) 因为只需保存序列长度的 hidden state，不用保存 N² 的 attention matrix。

Q8：实际生产用什么？

A：2025-2026 主流是"混合 + 量化"。Codestral Mamba 7B、Mistral Large 3（混合）、Jamba 1.5 Large、Zamba2 7B。纯 SSM 模型少（Falcon Mamba 7B 是个标志），实际部署常配合 PagedAttention、Speculative Decoding、量化（AWQ/GPTQ）一起用。

Q9：Mamba 怎么 fine-tune？

A：和 Transformer 一样，SFT / DPO / LoRA 通用。但注意：① LoRA 适配 Mamba 块需要同时改 SSM 和 FFN；② 状态初始化需从头训练，不直接继承预训练 state；③ DPO 在 Mamba 上同样有效（参考 Zamba-DPO 实验）。

Q10：Mamba 有什么硬件坑？

A：① selective scan 的 custom kernel 难优化（causal-conv1d / mamba-ssm 库）；② 不直接支持 FlashAttention 等标准工具；③ vLLM / TensorRT-LLM 早期不支持 Mamba，2024 后逐步支持；④ 量化路径不成熟（AWQ 在 Mamba 上需适配）。

回答模板与加分项

30 秒电梯版

面试开场可以这样讲：Mamba / SSM / RWKV 是"非 Transformer"线性架构，目标是用 O(N) 训练 + O(1) 推理取代 Transformer 的 O(N²)。Mamba 的核心是把 SSM 参数改成输入依赖（selective scan），获得接近注意力的表达力；Mamba2 发现与注意力有 SSD 对偶，训练并行化。混合架构（Jamba / Zamba / Bamba）补 ICR 短板，是 2025-2026 主流。适合长上下文、端侧、高 QPS 场景。

5 分钟深入版

从 Transformer 复杂度痛点 → SSM 基础公式 → Mamba selective scan 创新 → Mamba1 vs Mamba2 (SSD) → 5 大家族对比 → 混合架构 (Jamba / Zamba) → 与 Transformer 的 trade-off → 落地选型。能讲清"为什么 Mamba 不需要 KV Cache"、"Mamba 2 SSD 对偶为什么重要"、"ICR 任务为何弱"，立刻显得有真研究。

加分：知道 Mamba 局限

Mamba 不是银弹：① ICR / 工具调用 / 复制任务弱于 Attention；② 训练需 parallel scan，硬件生态不成熟（vLLM / TensorRT 早期不支持）；③ 量化路径需重新适配；④ 解释性差（state 不像 attention 权重直观）；⑤ 上下文再长，state 大小固定，模型容量有限。

加分：能讲一次工程踩坑

比如：用 Mamba 替换 Transformer 训练 RAG 模型，发现 NIAH 评测从 95% 掉到 60%（ICR 短板）；加 1 层 Attention 块后回到 92%；混合比例 1:8 在 GPU 显存和效果间最平衡。讲清"理论 → 评测 → 调比例"三步，面试官会立刻认定你有真经验。

原理Selective Scan 怎么"输入依赖"？答"3 个动态参数"：Bt、Ct、Δt 都由当前 token 通过 Linear + softplus 投影得到。Δt 决定步长（重要 token 小步长，无关 token 大步长），实现内容感知。

工程Mamba 怎么部署？答"专用 kernel + 量化"：用 mamba-ssm / causal-conv1d 库提供 CUDA kernel；量化需自研（AWQ 在 Mamba 上需适配）。vLLM 0.5+ 支持 Mamba 推理，TensorRT-LLM 2025 起支持。
