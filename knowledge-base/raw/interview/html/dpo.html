Direct Preference Optimization

DPO：不用显式 Reward Model 的偏好对齐

DPO 的核心是用 chosen / rejected 偏好对直接训练模型，让模型更偏向人类更喜欢的回答，同时通过 reference model 防止模型偏离基座太远。面试里要讲清楚它和 SFT、PPO 的区别，以及 beta、KL、reference model 的意义。

DPO 数据和训练流

DPO 公式

loss = -log σ( β · [ log πθ(chosen) - log πθ(rejected) - log πref(chosen) + log πref(rejected) ] )
记号解释：πθ 是当前模型，πref 是参考模型，β 控制偏好强化强度。
直觉：让当前模型相对参考模型，更偏向 chosen，而不是 rejected。

知识点拆解

1. Reference Model

提供稳定基线，防止当前模型为了偏好数据过度漂移，丢掉原有语言能力。

2. beta

控制偏好强度。太小学不到偏好，太大可能过拟合偏好对，导致输出风格变窄。

3. KL

衡量新模型和参考模型的分布差异，对齐训练里常用来限制策略漂移。

4. 数据风险

如果 chosen 总是更长，模型可能学到长度偏好，而不是质量偏好，所以要控制样本偏差。

面试回答模板

“DPO 是一种直接利用偏好对做对齐的方法。它不显式训练 reward model，而是让模型在同一 prompt 下提升 chosen 相对 rejected 的概率，同时用 reference model 约束不要偏离基座太远。”

常见追问与回答

为什么不只做 SFT？

SFT 解决的是“会不会答”，但当同一个问题有多个都算对的答案时，还需要决定“哪种回答更好”。DPO 的作用就是把偏好排序这件事显式学进去，比如更简洁、更安全、更符合语气、更少幻觉。

没有 reference model 会怎样？

模型更新会更容易漂移，可能为了偏好数据牺牲原本的语言能力和通用性。reference model 相当于一个稳定锚点，用来约束策略不要偏离基座太远。

beta 怎么调？

β 越大，偏好信号越强，模型越容易明显区分 chosen 和 rejected；但太大可能让模型过度迎合偏好样本，造成风格变窄或泛化下降。通常要结合验证集做消融。

正负样本长度不一致有什么影响？

如果 chosen 总是更长，模型可能学到“长答案更好”的表面偏差，而不是真正的质量偏好。所以需要控制样本长度、按步骤对齐，或者在 judge 阶段显式忽略长度因素。

为什么 DPO 比 PPO 更容易落地？

DPO 不需要单独训练 reward model，也不需要在线 rollout 和复杂的策略更新链路，工程上更轻，训练更稳定，适合多数偏好对齐任务。

什么时候还是应该用 PPO / RLHF？

当奖励很复杂、需要在线探索、或者你希望模型在长链路决策里通过环境反馈学习时，PPO 仍然有价值。DPO 更像偏好对的监督优化，不是所有场景的替代品。
