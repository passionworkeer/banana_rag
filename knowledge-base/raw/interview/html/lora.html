LoRA 微调

Low-Rank Adaptation — 用极小参数量（<1%）微调大模型，避免全量训练的高成本。冻结原权重 W，引入低秩旁路 ΔW = A·B，推理时可合并到 W 零额外成本。

Low-RankAdapterFrozenRank rA·B

一、LoRA 核心思想

  • 问题：全量微调 7B 模型要更新 70 亿参数，显存 ≈ 280GB（权重 + 梯度 + Adam 优化器状态），单机多卡都难跑
  • 核心思路：冻结原权重 W ∈ R^(d×k)，引入低秩旁路 ΔW = A·B，只训练 A 和 B
  • 形状约定：
    • A ∈ R^(d×r)（输入侧降维）
    • B ∈ R^(r×k)（输出侧升维）
    • r ≪ min(d, k)，r 通常 4-64
  • 为什么低秩就够：实证观察 — 预训练模型微调时权重变化矩阵的秩远低于原始秩（多数 < 100），即 ΔW 近似落在低秩子空间里
  • 训练参数对比（以 d=k=4096 为例）：
    • 全量微调：d × k = 1670 万参数
    • LoRA（r=8）：d × r + r × k = 6.5 万参数（占全量 0.4%）
    • LoRA（r=64）：d × r + r × k = 52 万参数（占全量 3.1%）
  • 推理合并：训练完成后 W_new = W + α/r · A·B（α 是缩放系数），合并到 W 后零额外推理成本
  • 常见变体：
    • QLoRA：基础模型 4-bit 量化（NF4），更省显存
    • AdaLoRA：自适应调整每层秩，重要层高 r、不重要层低 r
    • LoRA+：A 和 B 用不同学习率（A 大 B 小）
    • DoRA：方向 + 幅度分解，提升效果
方案可训参数显存占用（7B 模型）推理成本效果

二、LoRA 旁路结构

输入 x 同时流过冻结的 W（主路）和可训的 B·A（旁路），输出相加。训练时只更新 A 和 B，W 冻结；推理时合并为单矩阵 W_new，前向计算量不变。

三、LoRA 公式

前向计算：$$h = W x + \Delta W\, x = W x + (B A)\, x$$

低秩约束：$$\Delta W = B A,\quad A \in \mathbb{R}^{d \times r},\; B \in \mathbb{R}^{r \times k},\; r \ll \min(d, k)$$

缩放：$$h = W x + \frac{\alpha}{r}\, B A\, x$$

可训参数量：$$|A| + |B| = d \cdot r + r \cdot k$$

参数量比：$$\frac{d \cdot r + r \cdot k}{d \cdot k} = \frac{r}{k} + \frac{r}{d}$$

例：d=k=4096, r=8，比值 = 8/4096 + 8/4096 ≈ 0.4%。α 通常取 16-32，让初始训练不破坏原模型（因为 B 初始化为 0）。

直观理解：ΔW 的"信息量"集中在少数方向上，低秩假设是"大模型微调时学到的能力也是低秩的"，所以用 r 维就够。

五、面试 FAQ

Q1：秩 r 怎么选？

A：经验 4-64，r=8/16 是常用起点。原则：任务简单（领域问答）r=4-8，任务复杂（多任务 / 风格迁移）r=16-64。通过验证集 loss 和下游指标调，最佳 r 通常在"参数量能装下任务复杂度"时。

Q2：LoRA 推理要带 Adapter 吗？

A：训练完成后 W_new = W + (α/r)·A·B 合并到 W，推理就是单矩阵前向，零额外成本。多 Adapter 场景下可保留独立 A·B，运行时动态加载（PEFT 库支持）。

Q3：和全量微调效果差多少？

A：经验上能逼近 90-95% 全量效果（r=8-16），r 调到 64 时能到 95-99%。DoRA / AdaLoRA 等变体效果可逼近全量。任务越复杂、训练数据越少，LoRA 优势越明显。

Q4：QLoRA 和 LoRA 区别？

A：QLoRA 把基础模型 4-bit 量化（NF4）+ Double Quant，显存节省约 3x，代价是量化噪声导致轻微效果损失（一般 < 2%）。适合消费级 GPU（24GB）训 7B-13B 模型。

Q5：冻结哪些层？

A：经验上冻结 embedding 和前 1-2 层 Transformer（语义相对通用），微调中间层和输出层（任务特异性）。LoRA 不直接"冻结层"，而是在某些层（Q/K/V、FFN）的权重上加低秩旁路。

Q6：LoRA 显存怎么算？

A：base 模型（fp16/bf16）+ A·B 梯度 + Adam 优化器状态（A·B 的 m 和 v）。以 7B + r=16 训为例：base 14GB + A·B 梯度 50MB + Adam 状态 100MB ≈ 14.2GB 总占用。

Q7：LoRA 适合什么场景？

A：四个典型场景：领域适配（医疗 / 法律 / 电商）、风格迁移（客服口吻 / 角色扮演）、多任务（一个基座 + N 个 Adapter）、消费级资源（单卡 / 小团队）。不适合"需要修改模型底层能力"的任务。

Q8：LoRA 怎么避免灾难性遗忘？

A：三个手段：小学习率（1e-4 ~ 5e-4，避免破坏原模型）、小 r（约束可学空间）、混入通用数据（训练集加 5-10% 原始通用数据）。本质是 LoRA 的低秩约束已经天然防遗忘。

回答模板与加分项

30 秒电梯版

面试开场可以这样讲：LoRA 是一种参数高效微调方法，冻结原权重 W、引入低秩旁路 A·B 替代 ΔW，可训参数量 < 1%；关键优势是显存省（7B 模型从 280GB 降到 16GB）、推理零成本（合并到 W）、可热切换多业务 Adapter。变体有 QLoRA、AdaLoRA、DoRA 等。

5 分钟深入版

从动机（全量微调成本高）→ 低秩假设（ΔW 是低秩的）→ 训练参数计算 → 推理合并 → 变体与选型 → 项目落地，逐层展开。最后落到 r 选择、目标模块、显存数据、合并部署实践。有真实数据能立刻拉开差距。

加分：知道 LoRA 的局限

LoRA 不是银弹：r 设小效果差、r 设大省显存优势弱、新增任务时叠加 Adapter 不方便管理、超大模型（70B+）效果略降。建议结合"DoRA / QLoRA 变体 + 多 Adapter 调度框架"缓解。

加分：能讲一次踩坑

比如：r=8 时 loss 收敛快但下游效果差（欠拟合）；r=64 时显存爆了（超预算）；目标模块只选 q_proj 时效果差（漏配 FFN）；B 初始化忘了设 0 导致训练初期模型崩坏。讲一次具体排查过程，面试官会立刻认定你有真经验。

面试官可能怎么追问

追问方向示范追问建议回应思路
低秩假设为什么 ΔW 是低秩的？答"实证观察 + 内在解释"：实验上微调 ΔW 的有效秩 < 100（Aghajanyan 2020 论文）；直观看，模型微调是对原有能力的精调，所需新信息维度有限。抓住"少而精"。
r 选择为什么 r=8 是常用起点？答"经验 + 任务复杂度"：8 维能覆盖大多数简单任务、参数量 < 1%、训练快；复杂任务再上调。也可以从 Singular Value Decomposition 分析 ΔW 的有效秩来定。
目标模块LoRA 应该加到哪些层？答"q_proj + v_proj 起步"：原始 LoRA 论文加到 Attention 的 Q/V；实战发现加到 FFN（gate/up/down）效果更明显；embed 和 lm_head 一般不加。可用 target_modules 配置。
效果对比LoRA 和全量微调效果差多少？答"90-95% 是常见结论"：单任务场景 r=8-16 即可；多任务 / 复杂生成 r=64 + DoRA 可逼近全量。关键看任务类型和数据量，小数据下 LoRA 反而更稳（防过拟合）。
生产部署LoRA 怎么上线？答"两种方式"：① 合并到 W，部署为标准模型（简单、QPS 不变）；② 保留独立 Adapter，运行时动态切换（多业务线、PEFT 库支持）。结合 A/B 测试验证效果。
最后提示：LoRA 是当前 PEFT 的事实标准，面试允许说"这块我了解原理但生产经验有限"，但要能讲清楚低秩假设、参数计算、推理合并 + 给出项目设计。诚实 + 思路清晰 > 假装熟练。
