低代码 / 无代码 LLM 平台：Dify / Coze / FastGPT / RAGFlow 全景

Dify、Coze、FastGPT、RAGFlow、Flowise、Langflow、Botpress、Voiceflow、MaxKB 等共同构成 LLM 应用低代码生态。本页聚焦"为什么需要低代码 → 12 大平台横向对比 → Dify DSL 架构图 → Coze 生态图 → RAGFlow 文档解析流程 → 私有化部署对比 → 选型决策 → 与代码框架的 trade-off → 项目落地 → 面试 FAQ"一次性串清楚。

一、为什么需要低代码 / 无代码 LLM 平台

  • PM / 业务方零代码搭建：Dify / Coze 可视化拖拽 + 模板，业务方 1 小时搭出客服 Bot，无需研发
  • 私有化部署刚需：金融 / 政企 / 医疗等场景数据敏感，FastGPT / RAGFlow / Dify / MaxKB 支持本地化部署，LangChain 不行
  • 降低 LLM 应用门槛：内置 RAG / Agent / Workflow / 插件市场，零 Prompt 工程也能跑出 70-80% 效果
  • 运维一体化：监控、日志、用户管理、知识库管理、模型路由、计费——平台一站式打包
  • 多端发布：Coze 一键发布到飞书 / 抖音 / 微信 / Web；Dify 提供 API + WebApp + 嵌入式
  • 代价：① 灵活度低于代码框架（深度定制受限）；② 自定义 Agent 逻辑难；③ 部分平台厂商绑定（Coze = 字节生态）；④ 高级 RAG 范式（多跳 / Agentic RAG）支持弱
核心判断：低代码 ≠ 取代代码框架。生产建议 ① 业务方 / 内部工具 / 客服知识库 → 低代码平台；② 核心产品 / 高定制 / 高并发 → 代码框架（LangChain / LlamaIndex）；③ 私有化 + 安全 → 国产开源（Dify / FastGPT / RAGFlow / MaxKB）。

十、面试 FAQ

Q1：Dify 和 Coze 怎么选？

A：① 字节生态 + 多端发布（飞书 / 抖音 / 微信）→ Coze 一键；② 私有化 + 复杂 App + Agent + 工作流 + 完整监控 → Dify 开源自部署；③ 简单客服 / 个人 / 内部工具 → Coze 快；④ 数据敏感 / 政企 / 金融 → Dify 私有化；⑤ 两者可组合：Coze 做前端 Bot、Dify 做后端 API。

Q2：FastGPT 和 RAGFlow 区别？

A：① 简单知识库问答 → FastGPT 轻量、部署最快；② 复杂文档 RAG（PDF 扫描件 / 表格 / 公式）→ RAGFlow（DeepDoc 解析业界最强 + 答案带原文引用）；③ FastGPT 偏通用问答、RAGFlow 专攻高质量文档解析；④ 都开源国产可私有化。生产复杂文档选 RAGFlow，简单问答选 FastGPT。

Q3：低代码平台能扛多大 QPS？

A：参考：Dify 单实例 50-200 QPS（取决于 LLM 推理速度 + 向量库）；FastGPT 单实例 30-100 QPS；RAGFlow 30-80 QPS（文档检索重）。瓶颈在 LLM 推理（GPT-4 ~20 QPS / Claude ~30 QPS / 开源 7B ~50-100 QPS）。生产建议：① LLM 推理用 vLLM 部署 + 负载均衡；② 向量库用独立集群；③ 多实例水平扩展 + Redis 缓存 + 异步队列。

Q4：低代码 vs LangChain 怎么选？

A：① 业务方主导 / 内部工具 / 简单客服 → 低代码（Dify / Coze / FastGPT）；② 核心产品 + 高并发 + 复杂 Agent / 多跳 RAG / 自定义逻辑 → LangChain / LlamaIndex；③ 过渡方案：低代码出原型 + 验证 PMF → 流量大后用代码重写；④ 私有化选国产开源低代码（自部署可控）；⑤ 海外业务 Coze / Voiceflow（云端 SaaS）。

Q5：Coze 为什么不能私有化？

A：Coze 是字节跳动闭源 SaaS 平台，核心模型 + 插件生态 + 多端发布依赖字节基础设施（飞书 / 抖音 / 火山引擎）。架构上不支持独立部署。私有化需求 → Dify / FastGPT / RAGFlow / MaxKB 国产开源。如果非要用 Coze 生态 + 私有化，考虑企业版（部分支持）+ 独立模型部署。

Q6：RAGFlow 的 DeepDoc 强在哪？

A：DeepDoc 是 RAGFlow 自研的文档解析引擎：① OCR（支持扫描件 + 多语言）；② Layout 分析（识别标题 / 段落 / 表格 / 公式 / 图片）；③ 表格结构化（合并单元格、跨页表格）；④ 公式识别（LaTeX 输出）；⑤ 答案带原文引用（可点击溯源到 PDF 页码）。对金融研报 / 法律文书 / 学术论文等复杂文档效果业界领先。

Q7：Dify 的 DSL 是什么？

A：DSL（YAML）是 Dify 核心抽象：① 可视化编辑器生成的 App 可导出为标准 YAML；② YAML 可重新导入到 Dify 编辑器；③ 通过 API 直接基于 YAML 部署 App；④ 支持版本管理（Git）；⑤ 方便二次开发 / 模板复用 / 跨环境迁移。优势：可视化与代码一一对应，App 即代码可版本管理。

Q8：Flowise 和 Langflow 区别？

A：① Flowise（JavaScript/TypeScript）→ npm/Docker 部署、LangChain JS 生态；② Langflow（Python）→ Python 原生、LangChain Python 生态；③ 功能类似都是 LangChain 拖拽低代码；④ Flowise 部署更轻、Langflow 与 Python 工具链集成更顺。选型看团队栈：JS → Flowise，Python → Langflow。

Q9：私有化低代码平台怎么选？

A：① 国产 + 完整 App + Agent + Workflow → Dify（最全）；② 简单知识库问答 → FastGPT（最轻）；③ 复杂文档 RAG → RAGFlow（解析最强）；④ 企业内部知识库 → MaxKB（运维最简）；⑤ LangChain 拖拽 → Flowise / Langflow（生态绑）。生产中常组合：Dify 主平台 + RAGFlow 文档解析子模块。

Q10：低代码平台有哪些坑？

A：① 平台厂商绑定（Coze = 字节）；② 复杂逻辑难（深度定制要 fork 源码）；③ 高级 RAG 范式支持弱（多跳 / Agentic RAG / Hybrid Search 难）；④ 监控和可观测性受限（不如 LangSmith）；⑤ QPS 上限低（百级）；⑥ 数据迁移成本（导出格式非标）；⑦ 升级风险（平台 API 变）。生产核心产品建议代码框架 + 低代码辅助。

回答模板与加分项

30 秒电梯版

低代码 / 无代码 LLM 平台是 LLM 应用层"业务方零代码搭建"的解决方案。核心有 4 类：① 国产开源可私有化（Dify / FastGPT / RAGFlow / MaxKB）——金融 / 政企首选；② 字节生态闭源（Coze）——飞书 / 抖音多端发布；③ LangChain 拖拽（Flowise / Langflow）——研发快速原型；④ 海外 SaaS（Voiceflow / Botpress / Stack AI）——海外市场。低代码 ≠ 取代代码框架，业务方用低代码、核心产品用 LangChain / LlamaIndex。

5 分钟深入版

从动机（为什么需要：业务方零代码 / 私有化 / 降低门槛 / 多端发布 / 运维一体化）→ 12 大平台横向对比表（开源/闭源/私有化/RAG/Agent/价格）→ Dify DSL 架构图（Studio + DSL + Workflow + 知识库 + Models）→ Coze 生态图（Bot + 插件 + 多端）→ RAGFlow 5 步文档解析（DeepDoc 业界领先）→ 私有化部署对比 → 按角色选型 → 与 LangChain 的 trade-off。能讲清"Dify DSL 是什么"、"RAGFlow DeepDoc 强在哪"，立刻显出实战深度。

加分：知道平台局限

① 灵活度低于代码框架；② 复杂 Agent 逻辑难；③ 平台厂商绑定（Coze = 字节）；④ 高级 RAG 范式支持弱；⑤ QPS 上限低（百级）；⑥ 数据迁移格式非标；⑦ 监控不如 LangSmith；⑧ 升级 API 风险；⑨ 私有化运维成本（需懂 K8s / Docker）；⑩ 自定义 LLM 训练 / 微调难集成。

加分：能讲一次工程踩坑

比如：用 Coze 搭客服 Bot 出原型，2 周上线验证 PMF 后，发现 QPS 撑不住（峰值 500+ QPS）+ 复杂工单逻辑难定制 → 迁移到 LangGraph + LangSmith 重写，QPS 提升 5x、bad case 排查时间从 30 分钟降到 3 分钟。私有化版本同时用 Dify 自部署给内部团队用，避免外部 SaaS 风险。讲清"原型 → 验证 → 迁移 → 收益"四步，面试官会认定你真踩过坑。
