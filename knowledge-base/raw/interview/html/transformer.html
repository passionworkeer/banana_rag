Transformer：把序列依赖变成可并行的注意力计算

Transformer 的本质不是“一个模型名字”，而是一个序列建模范式：用 Attention 建模 token 之间的关系，用 FFN 做非线性变换，用残差和归一化稳定训练。大模型里最重要的，是理解它为什么能并行、为什么会长上下文退化、以及 KV Cache 和 MoE 是怎么接在它上面的。

核心公式

$$Q = X W_{q},\quad K = X W_{k},\quad V = X W_{v}$$

$$\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left(\, \frac{Q K^{\top}}{\sqrt{d_{k}}} \,\right) V$$

$$\mathrm{softmax}(z_{i}) = \frac{e^{z_{i}}}{\sum_{j} e^{z_{j}}}$$

Q 是查询，K 是索引，V 是内容；Attention 本质是基于相似度的加权求和。

Scaling 的作用：避免高维点积过大，softmax 过饱和，梯度变小。

为什么 Multi-Head 重要

问题单头会怎样多头怎么改进

局部与长程依赖并存容易顾此失彼有的头看局部，有的头看远处

长上下文和 KV Cache

KV Cache 为什么快

生成第 t 个 token 时，不需要重算前面所有 token 的 K/V，只需要当前 token 的 Q 和新的 K/V。这样把重复计算变成缓存复用，用空间换时间。

KV Cache 代价

显存随序列长度、层数、batch 和 KV head 数线性增长。长上下文服务里，显存瓶颈常常不是模型参数，而是缓存本身。

KVCacheBytes = batch · seq_len · layers · kv_heads · head_dim · 2 · bytes_per_element
这里的 2 表示 Key 和 Value 两份缓存。长上下文、高并发时，KV Cache 往往会成为主要显存压力。

面试回答模板

“Transformer 的本质是把序列建模变成注意力加权求和。Self-Attention 负责 token 间关系，FFN 负责非线性映射，Residual 和 LayerNorm 保证深层可训练。多头是让不同头学习不同关系，而 KV Cache 是自回归推理里的缓存复用机制。”

常见追问与回答

Self-Attention 和 Cross-Attention 怎么区分？

Self-Attention 的 Q/K/V 都来自同一序列，用来建模内部 token 关系；Cross-Attention 的 Q 来自当前序列，K/V 来自外部序列或模态，用来读取外部信息。

为什么要加 scaling？

高维点积的数值会随维度增大而变大，softmax 容易变得过尖，导致梯度变小。除以 √dk 可以稳定分布。

Decoder-only 为什么能做生成？

Decoder-only 用 causal mask 保证每个位置只能看前文，通过 next token prediction 训练。对话、代码和问答都可以转成“给定上下文预测下一个 token”。

长上下文为什么容易遗忘？

原因包括位置外推能力有限、上下文噪声太多、关键信息被埋在中间，以及注意力计算虽然能看全局但不保证有效利用所有信息。常用摘要、RAG、记忆和重排缓解。
