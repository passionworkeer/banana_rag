GRPO：免 critic 的组内相对优化

Group Relative Policy Optimization，DeepSeek 2024 提出。从 PPO 演化而来，砍掉 value network，对同一 prompt 采样 N 个回答、用组内归一化分数当 advantage。核心卖点：显存砍半、训练更稳、长 CoT 推理任务上效果反超 PPO。已成为开源大模型对齐的事实标准之一（Qwen-2.5、Llama-3 都用）。

二、GRPO 目标函数

对 prompt $q$ 采样 $N$ 个回答 $\{y_{1}, \ldots, y_{N}\}$

$$r_{i} = \text{RewardModel}(y_{i})$$

$$A_{i} = \frac{r_{i} - \mathrm{mean}(r)}{\mathrm{std}(r)}$$

— — —

$$J_{\text{GRPO}}(\theta) = \mathbb{E}\!\left[\, \tfrac{1}{N} \sum_{i} \min\!\left(\, r_{i}(\theta) \cdot A_{i},\; \mathrm{clip}\!\left(r_{i}(\theta),\, 1 - \varepsilon,\, 1 + \varepsilon\right) \cdot A_{i} \,\right) - \beta \cdot \mathrm{KL}\!\left(\pi_{\theta} \,\|\, \pi_{\text{ref}}\right) \,\right]$$

$r_{i}(\theta) = \pi_{\theta}(y_{i} \mid q) \,/\, \pi_{\text{old}}(y_{i} \mid q)$，重要性采样。优势用组内归一化代替 V 网络。KL 仍保留防 SFT 能力遗忘。

三、为什么组内归一化能代替 V？

V(s) 估计"状态 s 下所有动作的期望回报"

— — —

组内归一化：

用同 prompt 采样 N 个回答的 mean 当 baseline

对单个 prompt 而言，相当于"这 N 个回答的期望分"

— — —

优势：

① 无 V 网络，砍一半显存

② baseline 是"同组其他回答"，天然去 prompt 偏差

③ advantage 估计更稳定（无 V 估计误差）

前提：N 足够大（典型 4-16），同 prompt 采样要够多样化，否则 group baseline 退化为常数。

四、GRPO 训练循环

old 给每个 prompt 生成 N 个 y（典型 4-16） ③ RM 打分 对每组 N 个回答 算 r1...rN ④ 算 advantage Ai = (ri − mean)/std 组内归一化 ⑤ 更新 πθ 梯度 clip + KL 关键细节 · N 越大 baseline 越稳，但 RM 调用成本线性增长 · KL 系数 β 通常 0.04（DeepSeekMath 论文） · clip ε 0.2 / 多次 epoch（一般 1-2）

五、GRPO 适用场景

  • 长 CoT 推理：DeepSeek-R1 用 GRPO + 规则化 RM（答案对/错）训推理
  • 数学 / 代码：可验证任务（答案确定），RM 简单
  • 资源受限：4×A100 跑 7B 对齐成为可能
  • 开源复现：Qwen-2.5、Llama-3 都用 GRPO 路径
  • DPO 上限低时：迭代到 GRPO 进一步提分

六、GRPO 不适用场景

  • 主观偏好：没有"对/错"的任务（如写作风格、对话），RM 训练本身难
  • 短回答：N 个采样多样性差，组内归一化失效
  • 极长生成：采样 N 个长回答 RM 调用成本爆炸
  • RM 质量差：组内归一化放大 RM 噪声
  • 需要历史回报：不能像 PPO 那样用 GAE 多步累积
判断口诀：可验证任务 + 显存紧张 + 想要"推理涌现" → 上 GRPO。主观对话 + 有强 RM → 仍用 PPO 或 DPO。

八、面试 FAQ

Q1：GRPO 砍掉 value network 真的没代价吗？

A：有。V 网络能学"任意状态 baseline"，GRPO 只能用同 prompt 采样的 group mean 替代。N 越小，baseline 噪声越大；任务越依赖长期回报，V 网络的"折扣累积"价值越大。DeepSeek 实践 N=4~16 在推理任务上够用，对话 / 创作任务不一定够。

Q2：为什么 DeepSeek-R1 用 GRPO 训推理？

A：推理任务有"答案对/错"的天然规则 RM（数学答案、代码单元测试），不需要训神经 RM；GRPO 砍显存让 7B-67B 模型能在合理硬件上对齐；组内归一化天然鼓励"答对且快"，筛掉"答对但啰嗦"的回答。

Q3：group_size N 怎么选？

A：经验 4-16。N 小 → 训练快但 baseline 噪声大；N 大 → baseline 稳但 RM 调用成本线性增长。数学 / 代码任务 N=8 是常见起点；对话 / 创作 N=16 更稳。

Q4：GRPO 的 KL 系数怎么选？

A：DeepSeekMath 论文用 β=0.04，DeepSeek-R1 用 β=0.04-0.1。β 太小→策略偏离 SFT，基础能力掉；β 太大→学不动。推理任务上 β 可以稍小（容忍更多探索），对话任务上 β 稍大（保能力）。

Q5：GRPO 适合做"风格对齐"吗？

A：不适合。风格对齐需要主观 RM（如"是否礼貌"、"是否简洁"），而 GRPO 的优势在"可验证任务 + 规则 RM"。对话风格对齐仍优先 DPO / Iterative DPO 路径。

Q6：GRPO 和 RLOO 区别？

A：RLOO (REINFORCE Leave-One-Out) 也是"免 critic + 组内 baseline"，但用朴素 REINFORCE 目标（无 clip）；GRPO 是 PPO 风格（有 clip + KL）。GRPO 更稳，RLOO 更简单。

Q7：规则 RM 怎么写？

A：数学：答案匹配 / 答案规范化后匹配；代码：单元测试通过率；推理：答案正确性 + 格式合规。优势是 0 标注成本、0 错误率、0 主观偏差；缺点是稀疏（只有对/错），需要 GRPO 这种"组内对比"方法放大信号。

Q8：GRPO 能完全替代 PPO 吗？

A：工业界目前趋近于"是"——R1 之后开源模型几乎全用 GRPO / DPO 路径。但超大规模（>70B）头部模型仍用 PPO，因 V 网络在长上下文长回报任务上仍有价值。短期内 PPO / GRPO / DPO 三足鼎立。

九、回答模板与加分项

30 秒电梯版

GRPO 是 DeepSeek 提出的 RLHF 改进，砍掉 value network，对同 prompt 采样 N 个回答、用组内归一化分数当 advantage。核心收益：显存砍半（2 模型 vs 4 模型）、训练更稳、推理任务上效果反超 PPO。已成为开源大模型对齐的事实标准（DeepSeek-R1、Qwen-2.5 都用）。

5 分钟深入版

从动机（PPO 4 模型显存贵）→ 关键改动（组内 baseline 替代 V 网络）→ 目标函数推导 → 训练循环 5 步 → 适用边界（可验证任务 + 推理）→ 与 PPO/DPO 对比 → DeepSeek-R1 实战路径。能讲清"为什么 N 越大越稳"、"为什么规则 RM 配 GRPO 才发挥威力"、"为什么对话任务上 GRPO 不一定稳"，立刻显得有真经验。

加分：项目案例

讲一次"为什么从 PPO 切到 GRPO"——比如硬件只有 4×A100 80G 跑不动 7B PPO，切 GRPO 后 2 卡就能训；再讲一次"为什么规则 RM 这么香"——数学 / 代码场景下规则 RM 0 标注成本、0 主观偏差、训练快 2-3 倍。

加分：知道 GRPO 局限

GRPO 不是银弹：① 主观任务上 group baseline 不如 V 网络；② N 太小 baseline 噪声大；③ RM 调用成本随 N 线性增长；④ 短回答任务上 N 个采样多样性差。要诚实说"GRPO 在推理任务上一枝独秀，对话任务上未必比 DPO 强"。
