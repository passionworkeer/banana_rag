ReAct / CoT

推理与行动交织的 Agent 思维范式 — 边想边做（ReAct）vs 先想后答（CoT）。两者都是把推理过程显式化，让模型能"自我审视"并应对动态环境。

ThoughtActionObservationLoopReflection

一、ReAct vs CoT

  • CoT（Chain of Thought）：先想后答，把推理过程显式化
    • 形式：模型一次输出完整推理链（"step 1: ... step 2: ... answer: ..."）
    • 代表：Zero-Shot CoT（"Let's think step by step"）、Few-Shot CoT、Self-Consistency
    • 适用：单步推理、数学题、逻辑题、代码生成（一次性完成）
    • 优势：实现简单、token 成本低
    • 局限：不能与环境交互，遇到错误无法修正
  • ReAct（Reason + Act）：推理 + 行动循环
    • 形式：Thought → Action → Observation → Thought → ... 多轮循环
    • 代表：Yao et al. 2022 论文、LangChain ReAct Agent、AutoGPT
    • 适用：多步工具调用、动态环境、需要实时纠错的任务
    • 优势：可调用工具、可感知环境、可自我纠正
    • 局限：易陷入循环、token 消耗高、需设最大步数
  • 与 Plan-and-Execute 区别：
    • ReAct：边想边调整，每步根据 observation 决定下一步
    • Plan-and-Execute：先全盘规划（生成完整 plan）→ 再逐步执行
    • ReAct 更灵活但不稳定，Plan-Execute 更稳但适应性差
  • 何时用 ReAct：环境动态、需多步工具调用、错误需实时纠正、信息逐步揭示
  • 何时用 CoT 单次：单步推理、数学题、代码生成、文本分类
  • 反思（Reflection）：执行后自评（"这次回答对吗？"），决定是否重试
    • Self-Refine：模型对自己的输出做批评 + 改写
    • Reflexion：把反思存到 long-term memory，下次避免同样错误
  • 失败模式：
    • 循环卡住：反复执行相同 Action
    • Observation 不准：工具返回错误或噪声数据
    • Thought 发散：推理链偏离目标
    • Step 超限：超过最大步数仍未完成

ReAct vs Plan-and-Execute 选型

维度ReActPlan-and-ExecuteReflexion
规划方式逐步规划（每步决定）一次性规划执行后反思
适应性高（实时调整）低（计划后不再改）高（带记忆）
稳定性中（可能循环）高（计划明确）中（依赖反思质量）
Token 成本高（每步重新生成）中（计划一次 + 执行 N 次）高（多轮反思）
适用任务动态 / 不确定环境结构化 / 可预测任务需要长期学习
失败模式循环 / 发散计划错误导致全盘失败反思误导
选型经验：不确定任务边界用 ReAct，结构化任务用 Plan-and-Execute，需要长期学习用 Reflexion。生产中常组合：ReAct 做单次决策 + Plan 做整体框架 + Reflection 做总结。

二、ReAct 循环

Thought 决定下一步动作，Action 调用工具，Observation 反馈结果，循环直到 Final Answer 或步数上限。每一步 LLM 都"看得见"自己的推理过程，便于调试和回溯。

三、ReAct Prompt 模板

System Prompt

You are an agent that solves problems via Thought/Action/Observation loops.
Available tools:
  - search(query): 搜索
  - calc(expr): 计算
  - lookup(key): 查表
Format:
  Thought: {reasoning}
  Action: {tool_name}[{input}]
  Observation: {result}  (system fills)
  ... (repeat)
  Thought: I now know the answer
  Final Answer: {answer}

完整 trace 示例

Question: 北京今天穿什么合适？
Thought 1: 需要先知道今天北京天气
Action 1: get_weather[{"city": "北京"}]
Observation 1: {"temp": 22, "condition": "晴", "humidity": 45}
Thought 2: 22 度晴朗，可以推荐薄外套 + T 恤
Action 2: search[{"q": "22 度穿搭建议"}]
Observation 2: [{"title": "22 度穿搭", "tip": "薄外套 + 长袖"}]
Thought 3: 信息够了，可以给出穿搭建议
Final Answer: 今天北京 22°C 晴朗，建议穿薄外套 + 长袖 T 恤

模板要点：工具描述要清晰、格式严格（避免解析失败）、终止条件明确、Few-shot 示例（2-3 个 trace 提升稳定性）。

CoT Prompt 模板

Zero-Shot CoT（最简形式）

Q: 小明有 5 个苹果，吃了 2 个，又买了 3 个，现在有几个？
Let's think step by step.
A: 小明原来 5 个，吃了 2 个剩 3 个，又买了 3 个共 6 个。答案：6。

Few-Shot CoT（带示例）

Q: 一个工厂 3 天生产 60 个零件，10 天能生产多少？
A: 每天生产 60/3 = 20 个，10 天 20×10 = 200 个。答案：200。

Q: 小明有 5 个苹果，吃了 2 个，又买了 3 个，现在有几个？
A: 小明原来 5 个，吃了 2 个剩 3 个，又买了 3 个共 6 个。答案：6。

CoT 关键：Let's think step by step 是 Zero-Shot 的"咒语"；Self-Consistency 多次采样投票能再提升准确率 5-10%。

五、面试 FAQ

Q1：ReAct 和 Function Call 区别？

A：Function Call 是输出格式（模型怎么表达"我要调工具"），ReAct 是思维范式（边想边做）；ReAct 内部可以用 Function Call 实现。ReAct 是"为什么这么做"，Function Call 是"怎么告诉系统我要做"。

Q2：什么时候用 ReAct？

A：四个特征：需要多步工具调用（如先查后算）、错误需实时纠正（API 失败重试）、信息逐步揭示（一次回答需要分步探索）、环境动态（每次工具调用结果可能不同）。简单问答 / 单步推理用 CoT 即可。

Q3：ReAct 会陷入循环吗？

A：会。三种防御：最大步数（如 10 步强制终止）、重复 Action 检测（连续 N 步 Action 相同则触发反思换工具）、Reflection 自评（执行后让模型判断"我是否在绕圈"）。

Q4：CoT 和 ReAct 可以组合吗？

A：可以。ReAct 的 Thought 阶段内部用 CoT 做推理（"先想清楚再决定动作"），效果比单步 Thought 好。代表实现：ReAct with CoT prompting、Chain-of-Thought Tool Use。

Q5：如何让 Agent 不重复尝试？

A：四个层次：状态记忆（记录已尝试的 Action）、相似度检测（连续 N 步 Thought 相似度 > 阈值则换工具）、显式反思（"我已经试过 X，结果是 Y，现在应该换思路"）、外部监督（人为设定"禁止调用 X"白名单）。

Q6：ReAct 和 Plan-and-Execute 选哪个？

A：简单任务（明确步骤）用 Plan-and-Execute（稳定）；复杂 / 动态环境用 ReAct（灵活）；生产中常 Plan + ReAct 组合：先 Plan 生成框架，再 ReAct 逐步执行并容错。

Q7：Reflection 怎么避免"自欺欺人"？

A：四个手段：外部验证（用工具或测试验证答案）、多模型投票（让不同 LLM 互相评）、Ground Truth 比对（有标准答案的场景）、成本控制（反思步数设上限避免过度）。反思不是万能，但能显著降低错误率。

Q8：ReAct Agent 怎么调试？

A：用 LangSmith / LangChain Tracing 工具记录每步 Thought / Action / Observation；存到 DB 便于回放；失败 case 单独标注；生产环境加 trace_id 全链路追踪。推荐用 LangGraph 可视化 Agent 状态机。

回答模板与加分项

30 秒电梯版

面试开场可以这样讲：CoT 是"先想后答"单次推理（适合数学 / 单步），ReAct 是"边想边做"循环（适合多步工具调用）；ReAct = Thought + Action + Observation 循环，每轮模型推理后决定调哪个工具，结果反馈后再思考。Reflection 是 ReAct 的增强，执行后自评决定是否重试。生产中常 Plan + ReAct 组合。

5 分钟深入版

从 CoT 起点 → ReAct 循环 → Plan-and-Execute 对比 → Reflection 反思 → 失败模式与终止策略，逐层展开。最后落到你们项目的 prompt 模板、循环检测、记忆系统。有真实数据能立刻拉开差距。

加分：知道 ReAct 的局限

ReAct 不是银弹：易陷入循环、token 成本高、对 prompt 质量敏感、模型"幻觉式思考"（Thought 不准）。建议结合"最大步数 + 循环检测 + Reflection + 外部验证"四件套缓解。

加分：能讲一次踩坑

比如：模型反复调同一个工具（无循环检测）；Thought 发散到无关话题（无 system prompt 约束）；Reflection 把自己骗了（无外部验证）；Step 数爆了 token（无 max_step）。讲一次具体排查过程，面试官会立刻认定你有真经验。

面试官可能怎么追问

追问方向示范追问建议回应思路
范式区别CoT 和 ReAct 怎么选？答"任务特征"：单步推理用 CoT（数学 / 代码）、多步工具调用用 ReAct（客服 / Agent）、结构化任务用 Plan-and-Execute。生产中常组合：Plan 做整体框架、ReAct 做单步决策、Reflection 做总结。
循环终止ReAct 怎么避免死循环？答"三层防御"：① 最大步数（hard cap）；② 重复 Action 检测（连续 N 步相同则触发反思）；③ Reflection 自评（执行后判断是否在绕圈）。结合成本预算和超时控制。
Function CallReAct 内部怎么调工具？答"两种实现"：① 文本解析（模型输出"Action: tool[args]"，正则解析）；② Function Call（OpenAI / Anthropic 原生支持结构化工具调用）。后者更稳定但耦合厂商。
反思质量Reflection 怎么保证有效？答"外部验证 + 多样化反馈"：让模型自评容易"自欺"，需用工具 / 测试 / 多模型投票交叉验证；反思要"具体可执行"（"我错在 X，应改 Y"），不要空泛"下次注意"。
性能优化ReAct 太慢怎么办？答"减少步数 + 并行工具"：① 合并多 Action 一次调（multi-tool）；② 不确定步骤让模型提前 plan（Plan + ReAct 组合）；③ 用更小模型做"工具选择 + 反思"、大模型做"Final Answer"。
最后提示：ReAct / CoT 是 Agent 思维范式的核心，面试允许说"这块我了解范式但生产经验有限"，但要能讲清楚循环机制、终止策略、反思 + 给出项目设计。诚实 + 思路清晰 > 假装熟练。
