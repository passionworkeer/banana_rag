大模型调优

Prompt 调优、采样参数、结构化输出、推理能力激活 — 不改权重也能大幅提升效果。

一、Prompt 调优维度

  • Prompt 工程：
    • Zero-Shot：直接给指令（"翻译成英文：..."）
    • Few-Shot：给 3-5 个示例（input-output 对），准确率显著提升
    • 角色设定："你是一名资深 X 专家" 改变输出风格
    • 约束条件："用 100 字以内"、"列出 3 点"、"必须用 JSON"
    • 思维链：加 "Let's think step by step" 激活推理
    • 结构化：用 Markdown / XML 标签分层（"### Context / ### Question / ### Answer"）
  • 采样参数：
    • Temperature：高（>0.7）= 发散有创造性，低（<0.3）= 确定保守，T=0 退化为贪心
    • Top-p (nucleus)：按概率累加截断（如 0.9 = 保留累积概率 90% 的 token），动态候选数
    • Top-k：保留 top k 个高概率 token，固定候选数
    • Frequency penalty：抑制重复（按出现频次惩罚），-2 到 2
    • Presence penalty：抑制重复（按是否出现惩罚），鼓励新话题
  • 结构化输出：
    • JSON Mode：OpenAI response_format: {type: "json_object"}，强制 JSON 语法
    • Function Calling：通过 Tool schema 强制结构化（见 tool-use.html）
    • Grammar Constrained Decoding：用 BNF / 正则约束每步生成的 token（Outlines、Guidance、JSONformer）
  • 推理激活：
    • CoT：思维链，让模型先想后答
    • Self-Consistency：采样 N 次投票（多答案 + 多数表决）
    • ReAct：推理 + 行动循环（见 react-cot.html）
    • ToT：Tree of Thoughts，搜索多个推理路径
  • 评估：困惑度（perplexity）、BLEU / ROUGE、人工评估、A/B 测试、LLM-as-Judge
  • 不改权重的边界：复杂任务（垂直领域 / 特定风格 / 新知识）仍需微调（SFT / DPO / RLHF）

二、Prompt 调优决策树

Prompt 调优是循环迭代过程：分析需求 → 选策略（Zero/Few/CoT）→ 选采样参数（Temp/Top-p）→ 跑评估 → 对比基线 → 不达标回循环。关键：每次只改一个变量（控制变量法），记录所有实验（参数 + 指标），最后选最优组合上线。

三、Temperature 缩放

$$P'(x) = \tfrac{P(x)^{1/T}}{\sum_{i} P(x_{i})^{1/T}}$$

Temperature 缩放：对原始概率做幂次缩放再归一化。T 控制分布"尖锐度"：T 越小分布越尖锐（趋向贪心），T 越大分布越平滑（趋向均匀）。

$T = 1$：原始分布，按模型训练时的概率采样

T = 1 是模型"自然"输出，适合通用场景。

$T \to 0$：趋向 one-hot，贪心选最高概率 token（确定性）

适合事实问答、代码生成、抽取等需要确定性的场景。T = 0 实际效果等同 greedy decoding。

$T \to \infty$：趋向均匀分布，完全随机

实际不用，但理解极限有助。T = 2 已经非常发散（top token 概率 < 30%）。

实践：Top-p 通常和 Temperature 配合（同时设）

先调 T（粗粒度控制风格），再用 Top-p（截断长尾）。OpenAI 建议：T=0.7-1.0 + Top-p=0.9-0.95 创作；T=0-0.3 + Top-p=0.95 事实。

三、消息格式

Request（Client → Server）

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "search_products",
    "arguments": { "keyword": "袜子" }
  }
}

Response（Server → Client）

{
  "jsonrpc": "2.0",
  "id": 1,
  "result": { "items": [...] }
}

Error（参数缺失 / 工具不存在）

{
  "jsonrpc": "2.0",
  "id": 1,
  "error": { "code": -32602, "message": "keyword is required" }
}

Notification（Server 主动推送，无需回复）

{
  "jsonrpc": "2.0",
  "method": "notifications/resources/updated",
  "params": { "uri": "file:///orders/2026-06-03.json" }
}

五、面试 FAQ

Q1：Temperature 怎么选？

A：按任务类型。事实问答 / 抽取 / 代码用 0.0-0.3（确定性，避免编造）；数学 / 推理用 0.0-0.3 + CoT；通用对话 0.6-0.8（平衡）；创作写作 0.7-1.0（多样性）；不要超过 1.5（太发散）。生产中常 0.7 起步，效果不满意再微调。

Q2：Top-p 和 Top-k 区别？

A：Top-k 固定候选数（永远保留概率最高的 k 个），简单但分布变化时不够灵活。Top-p 按概率分布动态截断（保留累积概率 ≥ p 的 token），分布尖锐时候选少，分布平坦时候选多。OpenAI 官方推荐 Top-p 而非 Top-k，因为 Top-p 适配不同上下文。建议 Top-p=0.9-0.95 同时配合 Temperature。

Q3：怎么让输出稳定 JSON？

A：四种方法（按推荐度）。① JSON Mode（OpenAI response_format: {type: "json_object"}，强制 JSON 语法，最简单）；② Function Calling（通过 Tool schema 强制结构化，最稳定）；③ Grammar Constrained Decoding（用 BNF / 正则约束每步 token，100% 合规但慢，Outlines / Guidance）；④ Prompt 强约束（"必须用 JSON 输出"，最弱，80% 合规）。生产推荐 ② 或 ③。

Q4：CoT 什么时候用？

A：四类任务适合：① 推理任务（数学 / 逻辑 / 代码）；② 多步规划（"先做 A 再做 B"）；③ 复杂判断（多因素权衡）；④ 解释型问题（"为什么 X"）。不适合：简单事实问答、抽取、翻译（推理链反而拖慢 + 引入噪声）。激活方式：Zero-Shot CoT（"Let's think step by step"）或 Few-Shot CoT（给 3-5 个推理示例）。

Q5：Prompt 调优和微调选哪个？

A：80% 场景用 Prompt 调优（成本低、迭代快、可解释）。需要微调的场景：① 垂直领域知识（医疗 / 法律 / 蕉内内部商品）；② 特定输出风格（按品牌话术）；③ 降低 token 成本（长 prompt → 微调后省 tokens）；④ 推理能力（CoT 难激活的复杂推理）。微调用 LoRA（成本低 + 可回滚），DPO 用于风格对齐。

Q6：怎么评估 Prompt 效果？

A：五个层次。① 困惑度（perplexity，自动化但弱相关）；② 业务指标（准确率 / 召回率 / F1）；③ LLM-as-Judge（用 GPT-4 评估输出质量，规模化但需校准）；④ 人工评估（金标准，成本高）；⑤ A/B 测试（生产环境对比，最真实）。建议组合：自动指标 + LLM-as-Judge 做回归测试，重要版本发版前加人工评估。

选型决策清单

只调 Prompt 的场景

通用任务（问答 / 总结 / 翻译）、风格调整（语气 / 长度 / 格式）、需快速迭代（分钟级）、可解释性要求高。先用 1-2 周把 prompt 调到极限。

加采样参数调优的场景

输出不稳定（同一 prompt 不同答案）、需控制多样性 / 创造性、JSON 抽取等结构化任务。Temperature + Top-p 联合调，是性价比最高的优化手段。

加 CoT / Self-Consistency 的场景

推理任务（数学 / 逻辑 / 代码）、多步规划、复杂判断。Self-Consistency 适合可验证答案（数学题有唯一答案），可多花 3-5 倍 token 换准确率。

上 SFT 微调的场景

垂直领域知识（医疗 / 法律 / 蕉内商品）、特定风格（品牌话术）、长 prompt 成本高、Prompt 调到极限仍不达标。LoRA 微调（成本低 + 可回滚）。
