二、5 大引擎定位

  • vLLM：开源王者，PagedAttention 论文实现，吞吐量 / 易用性平衡好，社区最广
  • SGLang：RadixAttention（更细的 prefix cache）、结构化输出、复杂 prompt 模板
  • TensorRT-LLM：NVIDIA 官方，kernel 级优化最极致，长 context / FP8 强
  • LMDeploy：商汤 TurboMind，针对 LLaMA / InternLM 优化，中文社区常见
  • TGI：HuggingFace 出品，Rust 实现，多模态支持好，工业级稳定性

五、vLLM 实战要点

  • 起步：pip install vllm → vllm serve model_path
  • Continuous Batching：默认开启
  • Prefix Caching：--enable-prefix-caching（多轮对话省 token）
  • 量化：--quantization awq/gptq
  • Speculative Decoding：--speculative-model（需 draft 模型）
  • LoRA 热加载：--enable-lora --lora-modules
  • MoE：原生支持 Mixtral / Qwen-MoE / DeepSeek-MoE

六、SGLang 实战要点

  • RadixAttention：比 vLLM prefix cache 更细，自动复用任意 prefix 树
  • 结构化输出：原生 JSON / regex 约束
  • 复杂 prompt 模板：SGLang DSL 描述控制流（分支 / 循环）
  • 启动：python -m sglang.launch_server --model-path model_path
  • 何时选：Agent 复杂控制 / JSON 输出 / 多轮对话 prefix 复用要求高

七、面试 FAQ

Q1：vLLM 和 SGLang 怎么选？

A：默认 vLLM（生态广、易用、通用）。SGLang 适合 ① 多轮对话 prefix 复用多 / ② Agent 复杂 prompt 模板 / ③ JSON 结构化输出频繁。两者都基于 PagedAttention 系，性能接近，差异在调度和 API 设计。

Q2：TensorRT-LLM 性能最强但为什么不是默认？

A：① 需要 engine 编译（模型 + 硬件绑定，更新成本高）；② 学习曲线陡；③ 调试难（内核问题不好查）；④ 不支持所有模型（部分新模型要等支持）。生产上"通用首选 vLLM、性能极限选 TensorRT-LLM"。

Q3：推理引擎量化选哪个？

A：默认 AWQ（精度好、速度快）；GPTQ 是经典但被 AWQ 超过；SmoothQuant 适合 W8A8；BitsAndBytes NF4 适合 LoRA 训练。生产中 vLLM 配合 AWQ 是甜点组合。

Q4：Continuous Batching 是什么？为什么重要？

A：传统 static batching 等最慢的请求结束才换新批，GPU 严重空转。Continuous Batching 让每个 slot 独立调度：完成的请求立即让位给新请求。vLLM 论文报告提升 14-24x 吞吐。

Q5：推理引擎怎么选 H100 vs A100？

A：H100（Hopper）支持 FP8 / WGMMA / TMA → TensorRT-LLM 极限性能。A100（Ada）FP16 为主 → vLLM 成熟生态。预算紧用 A100 + vLLM；要极致吞吐用 H100 + TensorRT-LLM / SGLang + FP8。

Q6：LMDeploy 适合什么场景？

A：中文 LLM（InternLM / Qwen）部署首选；TurboMind 内核对中文长 prompt 模板优化好；量化生态完善（AWQ / GPTQ / SmoothQuant）。学术 / 国产模型部署常见。

Q7：TGI 在什么时候优于 vLLM？

A：① 多模态场景（TGI 原生支持 VLM）；② HuggingFace 生态集成（Spaces / Inference Endpoints）；③ K8s / 生产稳定性要求高（Rust 内存安全）。吞吐性能 vLLM 通常更优。

Q8：推理引擎 + Agent 框架怎么搭配？

A：LangChain / LlamaIndex 都能接 vLLM / SGLang / TGI 的 OpenAI-compatible API。AutoGen / CrewAI 同理。生产中 vLLM + OpenAI API 兼容层 + Agent 框架是主流组合。

八、回答模板与加分项

30 秒电梯版

5 大引擎：vLLM（开源王者 / 通用）/ SGLang（RadixAttention / Agent 复杂 prompt）/ TensorRT-LLM（NVIDIA 极致 / 长 context）/ LMDeploy（中文 / InternLM）/ TGI（HuggingFace / 多模态）。选型口诀：默认 vLLM，复杂 Agent 用 SGLang，极致性能用 TensorRT-LLM，中文 LLM 用 LMDeploy，多模态用 TGI。

5 分钟深入版

从动机（生产部署要"快 + 省 + 稳"）→ 5 层技术堆叠（模型 / 内存 / 计算 / 调度 / 部署）→ 5 引擎定位 + 性能对比 → 各自杀手锏（PagedAttention / RadixAttention / TensorRT kernel / TurboMind / Rust 多模态）→ 实战要点（启动命令 / 量化 / Prefix Cache / Speculative）→ 选型决策树。能讲清"为什么 SGLang 适合 Agent"、"为什么 TensorRT-LLM 不是默认"，立刻显得懂生产部署。

加分：项目案例

讲一次"推理引擎选型"——比如某业务日均 1M 请求，从 HF Transformers 切 vLLM + AWQ INT4 + Prefix Caching + Continuous Batching 后，GPU 数量减半、单 QPS 涨 4x、成本省 60%。再讲为什么没选 TensorRT-LLM：编译成本 + 团队不熟。

加分：知道局限

推理引擎不是银弹：① 切换成本（不同 API / 部署方式）；② 模型支持有时滞（新模型出来要等引擎适配）；③ 性能调优需要专业知识；④ 不是所有优化都开（量化 + SpD 一起开可能反效果）。诚实说"默认 vLLM，按业务需求局部优化"得分更高。
