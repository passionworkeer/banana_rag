文档解析：把 PDF / 图 / 表格变成 RAG 可用的结构化数据

企业 RAG 的最大瓶颈不是 LLM、不是 Embedding、不是 Vector DB——是"文档进得去、解析得对、结构保留"。PDF 双栏、扫描件、表格、公式、图表都是老大难。MinerU / PaddleOCR / Unstructured / Marker 是主流方案。本页讲清 4 类文档挑战、解析流程、评估、与 VLM 的边界。

一、文档解析 4 大挑战

二、解析流程 5 步

  1. 格式检测：PDF / 图片 / HTML / DOCX
  2. Layout Analysis：识别段落、标题、列表、表格、图片位置
  3. OCR 抽取：图片区段 OCR，文本区直接抽
  4. 结构化输出：Markdown / HTML / JSON 保留结构
  5. Chunking 准备：按章节 / 段落切块，附元数据

五、Chunking 策略

  • 固定长度：简单但会切断段落
  • 按段落：保持语义完整
  • 按章节：适合长文档 / 论文
  • 语义切块：用 Embedding 检测"主题变化"自动切
  • 父子块：检索粗块、生成用细块
  • 结构保留：表格整块、列表整块、代码整块
Chunking 决定 RAG 上限——分得不好，Embedding 再强也救不回来。

六、解析与 VLM 的边界

  • 传统 OCR + Layout：快、便宜、可控，适合结构化文本
  • VLM 端到端：能处理图表、公式、不规则排版，但慢 + 贵 + 不可控
  • 混合方案：传统 OCR 抽文字 + VLM 辅助图表 / 公式（生产常用）
  • VLM 当 Verifier：传统 OCR 后 VLM 复查复杂区域（提精度）
  • 未来：VLM 成本下降 → 端到端 VLM 解析成为主流

七、面试 FAQ

Q1：企业 RAG 解析最常踩的坑？

A：4 大坑：① 双栏 PDF 读序错乱（混了第一栏和第二栏）；② 扫描件未 OCR 全是图片；③ 表格结构丢失（变成"列1\n值1\n值2"乱序）；④ 公式 / 图表当字符串存。生产中 80% 的"回答不对"问题溯源都是这 4 类。

Q2：MinerU / PaddleOCR / Unstructured 选哪个？

A：① 中文 PDF（论文 / 报告 / 合同）→ MinerU；② 中文场景表格多 → PaddleOCR Table；③ 英文 PDF 多 → Marker / Unstructured；④ 工业级生产（速度 + 稳定）→ PaddleOCR。生产中常组合：MinerU 解析 + PaddleOCR 兜底。

Q3：Layout Analysis 怎么工作？

A：通常用目标检测模型（YOLO / DETR）识别文档元素：标题、段落、列表、表格、图片、页眉页脚。然后按"阅读顺序"算法（从左到右、从上到下、列优先）排序，输出结构化结果。MinerU 用的是 YOLO + 自定义读序。

Q4：公式怎么转 LaTeX？

A：3 种方案：① 传统 OCR（Pix2Tex / Nougat）专门训公式识别；② VLM（GPT-4V / Qwen-VL）把公式当图识别并输出 LaTeX；③ MinerU 内置公式识别模块。Nougat 是 Meta 2023 论文，专门从 arXiv 论文 PDF 提 LaTeX。

Q5：表格怎么保留结构存 RAG？

A：3 种格式：① Markdown 表格（人类可读、LLM 友好）；② HTML 表格（结构保留完整）；③ JSON 嵌套（程序化处理）。生产中 Markdown 表格最常用——LLM 能直接理解，且能嵌进 Chunk。复杂表格用 HTML 完整保留。

Q6：解析失败的兜底策略？

A：3 层兜底：① 主解析器失败 → 切备用解析器（如 MinerU 失败用 PaddleOCR）；② 整页失败 → 用 VLM 端到端（GPT-4V 兜底）；③ 全文档失败 → 人工标注关键段落，提示"此文档仅支持部分检索"。

Q7：解析 + Chunking + Embedding 哪个最重要？

A：解析 ≈ 50%、Chunking ≈ 30%、Embedding ≈ 20%。解析错了后面全错；Chunking 不对信息检索不到；Embedding 即使不完美也能用 ReRank 补。优化预算按这个分配。

Q8：解析后的元数据怎么设计？

A：必备 5 类：① 来源（文件名 / 页码 / 章节）；② 类型（文本 / 表格 / 图像描述）；③ 时间（文档日期 / 入库时间）；④ 权限（公开 / 内部 / 机密）；⑤ 业务标签（产品线 / 部门）。元数据用于过滤 + 检索后处理 + 审计。

八、回答模板与加分项

30 秒电梯版

文档解析 = Layout Analysis + OCR + 结构化输出。4 大挑战：Layout 复杂 / 表格抽取 / 扫描件 / 多模态。中文首推 MinerU + PaddleOCR，英文 Marker 表现佳。解析 ≈ RAG 性能的 50%。生产中常组合：传统 OCR 抽文字 + VLM 辅助图表公式。

5 分钟深入版

从动机（企业 RAG 最大瓶颈是"文档进得去"）→ 4 大挑战 → 5 步解析流程 → 4 大方案对比 → Chunking 策略（结构保留）→ 与 VLM 边界（混合方案）→ 3 层兜底策略 → 元数据设计 5 类。能讲清"为什么解析 ≈ 50% 性能"、"为什么结构保留比 Embedding 重要"，立刻显得有 RAG 工程经验。

加分：项目案例

讲一次"解析优化上线"——比如客服 RAG 早期用 PyPDF2 抽文字（双栏错乱、表格丢失），文档 QA 准确率 60%；切 MinerU + 表格 Markdown 保留后准确率 85%。再加 Chunking 优化（按章节 + 父子块）到 90%。讲排查 + 优化过程立刻显得有真经验。

加分：知道局限

文档解析不是银弹：① 扫描件 OCR 错误率仍高（5-10%）；② 复杂排版（多栏 + 表格 + 公式）仍会失真；③ VLM 兜底贵且慢；④ 表格结构保留 + LLM 理解仍是 trade-off。诚实说"解析 80% 问题靠传统工具，剩下 20% 复杂 case 靠 VLM 兜底"得分更高。
