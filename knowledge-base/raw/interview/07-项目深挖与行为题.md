# 07 项目深挖与行为题

## 1. 你更希望做长期实习，那什么样的工作内容会让你更愿意一直做下去？

核心回答：

> 我更愿意长期做两类事情：一类是能持续累积的方法论和能力，比如 Agent、RAG、评测、工具链；另一类是能看到明确业务反馈的工作，比如把一个流程从零做成可用工具，看到真实用户在用。

可以这样答：

- 有明确问题定义。
- 有持续迭代空间。
- 能沉淀成方法或工具。
- 最好能看到真实反馈和结果。

## 2. 讲一个你最熟悉的 Agent / RAG 项目

核心回答模板：

> 这是一个围绕某个业务问题构建的 Agent / RAG 系统。我的角色主要是负责方案设计、检索链路、工具编排或评测。项目最核心的挑战是知识召回和任务执行不稳定，所以我分别从数据、检索、重排、工具调用和评估几个层面去优化。

讲法结构：

1. 业务背景是什么。
2. 用户为什么需要。
3. 你负责什么。
4. 方案怎么搭。
5. 怎么验证效果。

## 3. 项目里数据处理的难点是什么？怎么解决？

核心回答：

> 最大的难点通常不是模型，而是数据格式不统一、脏数据多、边界样本少和标注标准不一致。我一般先做清洗、去重、标准化字段，再把数据拆成训练集、验证集和坏例集。

可以说的点：

- 去重减少重复学习。
- 统一字段减少格式噪声。
- 人工抽检保证质量。
- 难例单独沉淀。

## 4. 这段主要做数学解题方向，这个事情业务上要解决什么问题？

核心回答：

> 业务本质通常是让模型更稳定地识别题目、理解题意、输出解题步骤和标准答案。对于数学题，文本信息往往不够，图文和公式结构也很重要，所以不仅是生成答案，还要解决识别、解析、推理和格式控制。

## 5. 一开始为什么用 OCR + 文本方案？后来为什么觉得不够用了？

核心回答：

> 早期用 OCR + 文本是因为实现快、成本低，能快速验证链路。但当文档出现图表、复杂版式、公式、标注和模糊图时，纯 OCR 会丢结构、丢位置信息，导致召回和理解都不稳定，所以要升级到多模态。

## 6. 多模态方案在哪些场景收益最明显？

核心回答：

> 图纸、表格、截图、标注图、复杂工业文档这些场景收益最明显，因为真正的信息不只在文字里，而在布局、位置关系和视觉特征里。

## 7. 你做的那一整套训练流程，对最终效果提升最大的是哪一块？

核心回答：

> 通常不是单一模型改动，而是数据处理和训练目标一起起作用。很多时候去重、清洗、难例补充、格式统一带来的收益，比盲目调模型结构更大。

可答方向：

- 数据去重。
- 高质量偏好样本。
- 训练格式统一。
- 负样本构造。

## 8. 模糊图效果提升挺多，这块主要解决了什么问题？

核心回答：

> 主要解决的是低质量输入下的鲁棒性问题。模型不能只依赖清晰文字，而要能从模糊视觉特征、上下文关系和局部结构里恢复语义。

## 9. 你们在数据这块做了很多处理，比如去重，这些工作值不值？有没有量化过收益？

核心回答：

> 值不值要看它是否减少了噪声、提高了泛化、降低了过拟合和重复学习。即使没有特别大的显著指标，去重和清洗通常也能明显改善收敛稳定性和评测波动。

量化方式：

- 命中率 / 准确率提升。
- 训练 loss 更稳定。
- 重复错误减少。
- 人工修正次数下降。

## 10. 在强化学习这块具体负责哪一部分？

核心回答：

> 可以按数据、奖励、训练流程、评估四块来答。一般我会说自己负责的是奖励设计、样本构造、训练参数调试或结果评估中的某一部分，不要泛泛地说“都做了”。

## 11. 奖励大概怎么定义？有没有遇到奖励不合理的情况？

核心回答：

> 奖励通常围绕正确性、格式、完整度和安全性来设计。奖励不合理最常见的问题是模型学会钻规则空子，所以需要不断用坏例测试和人工复核来修正。

## 12. 强化学习训练过程中，有没有出现模型“学歪了”？

核心回答：

> 有的话一般是 reward hacking、过拟合某种模板或策略漂移。处理方式通常是降低步长、加强参考约束、调整奖励函数和补充难例。

## 13. 为什么会选 GRPO？

核心回答：

> GRPO 更适合在组内相对比较或偏好优化里使用，工程上也常被拿来做较稳定的策略优化。你可以强调自己选它的原因是训练稳定、实现成本和样本组织方式更贴合任务。

## 14. 小模型能做到 80% 以上效果，核心原因是什么？

核心回答：

> 通常不是模型天生强，而是任务被收窄了、数据质量高、评测目标明确、输入输出格式稳定，再加上合理的训练和蒸馏策略，所以小模型也能做出不错的指标。

## 15. 这个 Agent 推荐和传统推荐最大的区别是什么？

核心回答：

> 传统推荐主要做排序和召回，而 Agent 推荐更像是在多轮交互里理解用户意图、动态调整策略、再综合工具和上下文做决策。它更强调过程控制和可解释的协商，而不只是一次性打分。

## 16. 多代理方案里，哪一部分最关键？

核心回答：

> 最关键的一般不是“Agent 数量多”，而是任务分工、路由规则、状态共享和冲突处理。多 Agent 真正的价值在于把复杂任务拆成可控子问题。

## 17. 你做了 memory，这个东西实际带来的提升是什么？

核心回答：

> memory 的实际价值是减少重复解释、保留长期偏好、降低上下文负担，并让系统在多轮任务里更稳定。它的提升不只是准确率，也包括用户体验和交互连续性。

## 18. 你对现在这种 Agent 框架，比如 OpenClaw，整体怎么看？

核心回答：

> 我会把它看成一类把工具调用、状态管理、计划执行和反馈回路标准化的框架。它的价值是提高复杂任务的可编排性，但框架再强，也不能替代对任务边界和安全边界的设计。

## 19. 如果让你用 OpenClaw 做发券或者运营自动化，第一步怎么设计？

核心回答：

> 我会先做任务拆解和风险分层，再定义哪些步骤可以自动执行，哪些步骤必须人工确认，然后再设计工具接口和状态机，最后才是模型接入。

## 20. 你觉得这种 Agent 在业务里最大的风险点是什么？

核心回答：

> 最大风险通常是错得很自信。尤其在工具调用、权限操作、发券、内容发布这些场景，模型一旦理解错目标，就可能造成实质业务损失，所以必须有校验、审批和回滚机制。

## 21. 你们为什么选择“技术方案驱动”，而不是直接让 AI 从 PRD 出码？

核心回答：

> 因为复杂业务场景里，先把技术方案、边界和流程定清楚，能显著降低 AI 生成错误的概率。直接从 PRD 出码虽然看起来更快，但容易在需求歧义、状态管理和异常处理上出问题。

## 22. .catpaw/rules 这套知识库，和 RAG memory 有什么区别？

核心回答：

> rules 更像稳定的行为约束和执行规范，memory 更像随着交互更新的上下文和偏好记录。前者偏规则，后者偏状态。

## 23. 如果知识库内容过多，AI 上下文压力很大，你们怎么裁剪或命中？

核心回答：

> 通过分层检索、摘要压缩、标签路由和上下文缓存，把“该用的少量内容”喂给模型，而不是把整个库都塞进去。

## 24. 你们有没有做 embedding 检索？

核心回答：

> 如果有，重点讲它解决了什么：语义召回、模糊提问、别名和表达差异。如果没有，也可以答“我们更偏规则或结构化检索，但在语义问题上会考虑 embedding 作为补充”。

## 25. 如果知识库里内容错了或者过期了，会不会误导 AI？怎么治理？

核心回答：

> 会，所以一定要做版本、时间戳、来源和失效策略。高风险知识要人工审核，低风险知识至少要能追溯来源。

## 26. 在一个很大的存量项目里，怎么让 AI 快速理解项目结构？

核心回答：

> 先做目录地图、模块摘要、关键入口索引和调用链，再让 AI 逐层深入。不要一上来就让它读所有文件。

## 27. 你们现在 AI 出码留用率 50%+，剩下 50% 主要问题在哪？

核心回答：

> 常见问题是需求理解偏差、上下文不完整、边界条件缺失、测试不充分和 diff 范围过大。也就是说，很多问题不是“不会写”，而是“没把任务约束好”。

## 28. AI 有没有出现过“看起来对，但逻辑其实错了”？

核心回答：

> 这种情况很常见，所以要靠测试、代码审查、diff 限制和关键路径人工确认来兜底，不能只看表面输出。

## 29. 你们有没有做过代码 diff 级别控制？

核心回答：

> 有的话就强调限制改动范围、只允许修改指定模块、对关键文件设白名单、避免 AI 乱动无关代码。

## 30. 你们基于 Playwright 做自动化测试，那测试用例怎么保证覆盖率？

核心回答：

> 覆盖率不是只看数量，而是覆盖核心路径、边界条件、异常流程和关键交互。可以按业务流程拆分用例矩阵，再结合失败率和回归缺陷来衡量。

## 31. 你们为什么选 Qwen 做裁判？有没有做消融？

核心回答：

> 选裁判模型要看稳定性、一致性、中文能力、指令遵循和成本。消融时可以比较不同模型版本、不同 prompt 和不同温度设置，观察评分一致性。

## 32. 如果没有 reference model 去做 DPO / RL，会怎样？

核心回答：

> 没有 reference model，训练会更容易漂移，模型可能为了偏好信号丢掉原有语言能力，所以 reference 的价值是保底。

## 33. 训练中如果 rollout 一直拿不到正确答案，怎么办？

核心回答：

> 这种情况通常说明探索空间太难或奖励太稀疏。可以先降低任务难度、引入分阶段奖励、做 curriculum learning，或者先用 SFT 打底再上 RL。

## 34. 你怎么处理响应速度与推理精度之间的 tradeoff？

核心回答：

> 我会把任务拆成路由、召回、重排、生成四层，不同层用不同成本的模型。简单任务走轻模型，复杂任务才走重模型，同时用缓存和并行减少整体延迟。

### A2. Agent / RAG 项目讲述模板

可以直接这样讲：

> 这个项目本质上是把非结构化知识转成可检索、可引用、可执行的 Agent 能力。我的重点不是单纯接一个大模型，而是搭建了数据解析、检索召回、重排、工具调用、记忆和评估这一整条链路。

展开：

- 数据：文档清洗、切片、embedding、索引。
- 检索：BM25 + dense + rerank。
- Agent：任务规划、工具调用、状态管理。
- 评估：检索命中率、回答忠实度、工具成功率。

### A3. 被问“业务价值是什么”时怎么答

不要只说“提升效率”，要说清楚：

- 原来谁在什么场景下痛。
- 原流程哪里慢或不稳定。
- 系统替代了哪一步人工动作。
- 最终用什么指标看价值。

模板：

> 原来这个场景主要靠人工查资料和反复沟通，问题是耗时长、口径不一致。我做的方案把资料结构化后接入检索和 Agent，让用户可以直接问，并且能追溯证据。第一阶段可以用响应时间、人工修改率和答案采纳率来评估。

### A4. 被问“你具体负责什么”时怎么答

建议用边界清晰的表达：

> 我主要负责 A、B、C 三块。A 是方案设计，B 是链路实现，C 是评估和问题排查。其他部分比如 UI 或后端基础服务，我是参与协同，不把它说成完全由我主导。

这样答的好处：

- 不夸大。
- 有贡献边界。
- 面试官更容易继续追问细节。

### A5. 被问“最大挑战是什么”时怎么答

好答案结构：

```text
挑战不是泛泛的“时间紧”，而是某个具体技术或业务矛盾。
```

例子：

> 最大挑战是检索召回和生成质量之间的矛盾。Top-K 太小容易漏证据，Top-K 太大又会引入噪声。我当时用混合检索提高召回，再用 rerank 和上下文压缩控制噪声。

### A6. 被问“有没有量化指标”时怎么答

如果没有真实线上指标，不要编。

可以说：

> 这个项目当时还在阶段性验证，没有完整线上指标，所以我会把指标分成离线验证和上线后指标。离线看 Recall@K、Faithfulness、人工评审通过率；上线后看采纳率、人工修改率、响应时间和用户反馈。

### A7. 被问“AI 出错怎么兜底”时怎么答

可以从四层说：

- 生成前：检索证据和参数校验。
- 生成中：工具调用 schema 和权限控制。
- 生成后：事实校验和引用检查。
- 高风险：人工审批。

### A8. 被问“为什么不用某框架”时怎么答

模板：

> 我不是认为框架不好，而是第一阶段更看重可控性和调试成本。框架适合快速搭链路，但如果业务里状态、权限和工具调用比较复杂，我会先把核心链路拆清楚，再决定哪些部分引入框架。

### A9. 长期实习动机更成熟的回答

> 我更看重能不能持续在同一条技术和业务线上积累。短期做 demo 能看到结果，但长期实习能让我把方案从原型、评估、上线到迭代都走一遍。我会更愿意留在有真实业务反馈、能持续做 Agent/RAG/评估工具链沉淀的岗位。

### A10. 反问问题

工程岗：

- 团队现在 Agent 项目最大的瓶颈是效果、数据、工具链还是稳定性？
- 现在怎么评估 Agent 线上效果？
- 实习生第一阶段更偏工程落地还是实验评估？

产品岗：

- 团队判断一个 AI 场景值不值得做，主要看哪些指标？
- 当前 AI 产品是探索期、试点期还是规模化推广期？
- 业务方最担心 Agent 的哪类风险？
