# 08 前端 AI 应用与产品设计

## 1. 如果从零设计一个 AI Agent 工作流可视化编辑器，怎么选型和设计架构？

核心回答：

> 我会把它设计成“画布层 + 节点配置层 + 执行引擎层 + 调试观测层”。前端负责工作流编排、节点编辑、连线和运行状态展示；后端负责保存 DSL、调度执行、工具调用和日志追踪。

架构：

- 画布：React Flow / X6。
- 节点：LLM 节点、工具节点、条件节点、人工审批节点。
- DSL：JSON/YAML 描述节点、边、输入输出。
- 后端：执行状态机。
- 调试：每个节点输入、输出、耗时、错误。

面试表达：

> 我不会只做一个“能拖拽的画布”，而是会重点设计可执行 DSL 和调试链路。因为 Agent 工作流最难的是运行过程可解释、可回放、可定位问题。

## 2. 如何建立一套针对前端 AI 应用的质量监控体系？

核心回答：

> 前端 AI 应用不仅要监控页面性能，还要监控模型响应、流式输出、工具调用状态、用户中断、幻觉反馈和人工接管。指标要覆盖体验、质量和稳定性。

指标：

- 首 token 延迟
- 完整响应耗时
- 中断率
- 重试率
- 工具调用失败率
- 用户采纳率
- 负反馈率
- 错误边界触发次数

## 3. 多模态图片、语音、视频交互中，前端架构如何保持灵活性？

核心回答：

> 前端应该把输入类型抽象成统一消息协议，而不是为每种模态写一套独立流程。消息里保留 type、metadata、upload status、preview 和 processing state。

设计：

- 文本、图片、语音、视频统一成 message。
- 大文件先上传拿 file id。
- 前端只展示状态，不直接耦合模型处理细节。
- 后端按模态路由到不同处理链路。

## 4. 你怎么看端侧模型，比如 WebLLM？前端有哪些应用前景？

核心回答：

> 端侧模型的价值是低延迟、隐私保护、离线可用和降低云端成本。它适合轻量摘要、改写、分类、局部助手和隐私敏感场景，但受限于设备算力、模型大小和浏览器兼容性。

适合：

- 本地文本改写。
- 小规模分类。
- 隐私敏感输入预处理。
- 离线助手。

不适合：

- 超大模型复杂推理。
- 高稳定性企业核心流程。
- 低端设备重计算。

## 5. 如何处理 AI 幻觉在 UI 层的反馈设计？

核心回答：

> UI 层不能假装 AI 永远正确，要把不确定性、引用证据、用户反馈和纠错入口显式设计出来。对高风险输出要加确认和来源展示。

设计方式：

- 展示引用来源。
- 标注“可能不完整”或“需要确认”的状态。
- 提供一键反馈：有误、不相关、缺少依据。
- 高风险动作前二次确认。
- 允许用户查看推理依据或检索证据。

## 6. 对 MiniMax Agent 这类产品有什么理解和优化建议？

核心回答：

> 我会从任务完成率、工具生态、记忆能力、可控性和垂直场景落地看这类 Agent 产品。优化重点不是让它“什么都能做”，而是让典型任务链路更稳定、更可解释、更容易被用户信任。

建议：

- 增强任务模板。
- 提供可视化执行过程。
- 明确工具权限。
- 支持人工确认节点。
- 对高频场景做专门评估集。

## 附录 A：前端 AI 应用详细知识点

### A1. AI 工作流编辑器的架构图

```text
前端画布
  -> 节点配置面板
  -> DSL 生成
  -> 后端执行引擎
  -> 工具调用 / 模型调用
  -> 状态回传
  -> 前端可视化运行日志
```

关键不是拖拽，而是：

- DSL 可执行。
- 节点输入输出可校验。
- 执行过程可回放。
- 错误能定位到节点。

### A2. 节点类型设计

| 节点 | 作用 |
|------|------|
| LLM 节点 | 生成、改写、判断 |
| Tool 节点 | 调外部 API |
| Condition 节点 | 分支判断 |
| Memory 节点 | 读写记忆 |
| Human 节点 | 人工审批 |
| Output 节点 | 格式化结果 |

### A3. 前端 AI 质量监控更详细的指标

体验指标：

- 首 token 延迟。
- 完整响应时间。
- 流式中断率。
- 用户取消率。

质量指标：

- 采纳率。
- 负反馈率。
- 重新生成率。
- 人工修改率。

稳定性指标：

- 工具调用失败率。
- WebSocket 断连率。
- 大文件上传失败率。
- 前端错误边界触发次数。

### A4. 多模态前端消息协议示例

```json
{
  "id": "msg_001",
  "type": "image",
  "status": "uploaded",
  "file_id": "file_abc",
  "metadata": {
    "width": 1024,
    "height": 768,
    "mime": "image/png"
  }
}
```

设计原则：

- 前端关心展示和状态。
- 后端关心解析和模型链路。
- 大文件先上传，消息里只传 file id。

### A5. AI 幻觉的 UI 反馈设计

不要只在底部放一句“AI 可能出错”。更有效的是：

- 展示引用来源。
- 高风险结论标注“需确认”。
- 给用户纠错入口。
- 对无证据内容提示“未找到依据”。
- 工具执行前展示影响范围。

HTML 示例：

<div>
  <strong>需要确认：</strong>
  该回答基于检索结果生成，未找到直接证据支持的部分已标记。执行前请确认影响范围。
</div>
