# 04 多模态与文档解析

## 1. OCR 的原理是什么？为什么一开始常用 OCR + 文本方案？

核心回答：

> OCR 的本质是先定位文字区域，再识别文字内容，把图片转成可检索的文本。OCR + 文本方案之所以常用，是因为它实现简单、成本低、可解释性强，适合先快速打通文字信息流。

典型流程：

- 文本检测
- 文本行/字切分
- 文字识别
- 结果后处理

局限：

- 对图文混排、复杂表格、模糊图片、手写和图纸不够稳。
- 纯 OCR 会丢失空间关系和视觉结构。

## 2. 为什么后面会换成多模态？在哪些场景收益最明显？

核心回答：

> 当文本本身不足以表达信息时，必须引入视觉特征。比如图表、图纸、截图、复杂版面、模糊图片和图文混排场景，多模态通常比 OCR + 文本更能保留真实语义。

收益明显场景：

- 图纸和版面依赖空间布局。
- 公式、表格、标注箭头。
- 图片里没有完整文字描述。
- OCR 错漏多、结构丢失严重。

## 3. 图文模态对齐问题通常怎么解决？

核心回答：

> 图文对齐的核心是让文本和视觉特征进入统一表示空间，或者通过跨注意力把文本查询和视觉区域对齐。常见方式包括对比学习、跨模态编码器、图像 patch 与文本 token 的联合建模。

常见方案：

- 双塔对比学习
- Cross-Attention 融合
- 图文预训练模型
- 检索时统一 embedding 空间

## 4. 如果图纸类视觉内容在文本中没有任何对应描述，模型怎么依托视觉特征精准召回？

核心回答：

> 这种场景不能只靠文本检索，必须让图像本身参与向量化和检索。也就是先用视觉编码器提取图像特征，再和 query 的文本特征映射到同一空间做相似度召回。

做法：

- 图像编码器抽特征。
- 文本 query 编码成向量。
- 图像与文本共享或对齐 embedding 空间。
- 必要时加视觉 rerank。

## 5. 在多模态检索里，文本和图片是如何映射到统一向量空间的？

核心回答：

> 通过图文对比学习或跨模态预训练，让图片和文本在训练目标上靠近语义一致的样本、拉远不相关样本，最终学出一个统一的向量空间。

训练直觉：

- 相关图文距离更近。
- 无关图文距离更远。
- 检索时就可以直接算相似度。

## 6. MinerU 在解析复杂工业文档时，处理逻辑一般是什么？

核心回答：

> 复杂工业文档最重要的不是“识别出字”，而是“恢复结构”。通常要先做版面分析，再识别标题、表格、公式、图注、跨页内容，最后把结果重组成更稳定的中间结构。

常见流程：

- 页面检测
- 版面分析
- 文本、表格、图片分区
- 跨页表格合并
- 结构化输出

## 7. 复杂图文混排文档的核心难点是什么？

核心回答：

> 难点在于文本顺序和视觉布局不总是一致。比如表格跨页、脚注、图注、箭头标注、跨栏排版，单纯按文字顺序会把语义打散。

解决思路：

- 保留空间坐标。
- 保留版面层级。
- 输出结构化块而不是纯文本。
- 在检索前恢复阅读顺序。

## 8. 对专业术语出现语义偏移，除了检索，还能怎么做？

核心回答：

> 可以对术语做标准化映射、领域 embedding 微调、词典增强和多模态证据融合，避免模型只看词面相似却忽略专业语义。

## 9. 在多模态 Agent 里，什么样的输入应该交给图像，什么样的输入交给文本？

核心回答：

> 文字说明清楚、结构简单、规则明确的内容交给文本；涉及布局、视觉特征、颜色、形状、标注、位置关系的内容交给图像或多模态模型。

例子：

- 产品规格表：文本优先。
- 工业图纸：多模态优先。
- 页面截图：多模态优先。
- FAQ：文本优先。

## 10. 图像模糊但效果提升明显，通常说明系统解决了什么问题？

核心回答：

> 一般说明系统在低质量输入、视觉鲁棒性或特征对齐上做了增强。比如去噪、模态融合、数据增强、困难样本训练，让模型更能容忍模糊图和不完整信息。

## 附录 A：多模态与文档解析详细知识点

### A1. OCR 不是一个单点模型，而是一条流水线

完整 OCR 一般包括：

```text
图像预处理 -> 文本检测 -> 文本识别 -> 版面恢复 -> 后处理纠错
```

每一步常见问题：

- 图像预处理：倾斜、噪声、模糊、光照。
- 文本检测：漏框、框错、跨行。
- 文本识别：错字、公式、符号。
- 版面恢复：多栏、表格、图注顺序。
- 后处理：专业术语、单位、编号纠错。

面试展开：

> OCR + 文本方案适合快速打通链路，但它把视觉内容压扁成文本，容易丢掉空间结构。工业文档、图纸、公式和表格里，空间关系本身就是信息。

### A2. 图文对齐的训练目标

多模态检索常用图文对比学习。直觉是让匹配的图文向量相近，不匹配的图文向量远离。

相似度：

```text
s(i, t) = image_embedding_i · text_embedding_t / temperature
```

InfoNCE 风格损失：

```text
L = -log exp(s(i,t+)) / sum_j exp(s(i,t_j))
```

面试表达：

> 统一向量空间不是手工规定出来的，而是通过正负图文对训练出来的。模型看到大量“这张图对应这段文字”的样本后，会把语义一致的图片和文本拉近。

### A3. 图纸没有文本描述时怎么召回

不能只做文本 embedding，要做视觉 embedding：

```text
图纸图片 -> vision encoder -> image vector
用户问题 -> text encoder -> query vector
相似度计算 -> Top-K 图纸/区域召回
```

如果图纸特别复杂，可以进一步：

- 先做版面/区域切块。
- 对局部区域单独向量化。
- 检索后用多模态模型做二次判断。
- 保留坐标，方便回显证据区域。

### A4. MinerU / 复杂文档解析的关键不是 OCR，而是结构恢复

复杂文档解析要保留：

- 标题层级。
- 段落顺序。
- 表格结构。
- 图注关系。
- 跨页连续性。
- 坐标位置。

### A5. 图文混排 RAG 的切片策略

普通文本切片不够，应该按“语义块”切：

- 文本段落作为一个 chunk。
- 表格保留表头和行列关系。
- 图片和图注绑定。
- 跨页表格要合并。
- chunk 元数据保留页码、坐标、标题路径。

面试表达：

> 多模态文档切片不能只看 token 数。比如表格如果切断表头，后续每一行都失去语义；图片如果和图注分离，检索时也会丢上下文。

### A6. 多模态系统评估指标

| 指标 | 含义 |
|------|------|
| OCR 准确率 | 字符或字段识别是否正确 |
| Layout F1 | 版面块识别是否准确 |
| Retrieval Recall@K | 正确图文块是否被召回 |
| Grounding Accuracy | 回答引用区域是否正确 |
| Answer Faithfulness | 答案是否忠于视觉/文本证据 |

### A7. 模糊图提升为什么有价值

模糊图提升通常说明：

- 训练数据覆盖了低质量输入。
- 图像增强提升了鲁棒性。
- 模型不只依赖 OCR 文本。
- 多模态特征补足了文字缺失。

面试答法：

> 模糊图提升本质上是鲁棒性提升。真实业务输入不会都是清晰标准图，所以这类提升比只在干净测试集上提分更有业务价值。
