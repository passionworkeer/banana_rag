# 01 大模型基础

## 1. 请介绍 Transformer 的结构组成及各部分作用

相似问法：

- 你了解 Transformer 架构吗？
- Transformer 和 RNN 的区别是什么？
- Decoder-only 模型为什么能做生成？

核心回答：

> Transformer 的核心是用 Attention 替代 RNN 的顺序递归建模，让模型可以并行处理序列，并通过自注意力直接建模任意两个 token 之间的依赖。标准 Transformer 包括输入嵌入、位置编码、多头注意力、前馈网络、残差连接、LayerNorm，以及 Encoder / Decoder 堆叠结构。现在主流大语言模型多采用 Decoder-only 架构，用自回归方式预测下一个 token。

详细展开：

- **Embedding**：把 token id 映射成连续向量，作为模型可计算的语义表示。
- **Position Encoding / RoPE**：Attention 本身不感知顺序，所以要注入位置信息。早期 Transformer 用正余弦位置编码，现在 LLaMA、Qwen 等常用 RoPE。
- **Multi-Head Self-Attention**：让每个 token 根据 Query、Key、Value 从全序列中聚合信息。多头机制允许不同头关注不同关系，比如语法、指代、局部模式、长程依赖。
- **Feed Forward Network**：对每个 token 独立做非线性变换，相当于扩展模型表达能力。通常是升维再降维，中间接激活函数。
- **Residual Connection**：缓解深层网络训练困难，让梯度更容易传播。
- **LayerNorm**：稳定训练分布，降低梯度爆炸或收敛不稳的风险。
- **Encoder-Decoder**：原始 Transformer 用 Encoder 理解输入、Decoder 生成输出，适合机器翻译。
- **Decoder-only**：只保留带因果 Mask 的 Decoder，适合文本续写、对话、代码生成，是现在 LLM 的主流结构。

面试表达：

> 我会先从“并行建模序列依赖”来讲 Transformer。它不像 RNN 必须一步一步读，而是通过 Self-Attention 让任意 token 直接建立联系。每一层主要由多头注意力和前馈网络组成，外面配残差和归一化保证深层训练稳定。当前大模型通常是 Decoder-only，通过 causal mask 保证只能看当前位置之前的内容，然后做 next token prediction。

## 2. Transformer 中 Attention 的本质是什么？请从数学角度解释

相似问法：

- Self-Attention 的公式是什么？
- 为什么计算 Attention 时需要 Scaling？
- Attention 的时间复杂度是多少？

核心回答：

> Attention 本质是一次基于相似度的加权求和。每个 token 生成 Query、Key、Value，先用 Query 和所有 Key 计算相关性，再经过 softmax 得到权重，最后对 Value 做加权求和。Scaled Dot-Product Attention 的公式是 `softmax(QK^T / sqrt(d_k))V`。

公式：

```text
Q = XWq
K = XWk
V = XWv
Attention(Q, K, V) = softmax(QK^T / sqrt(d_k))V
```

为什么要除以 `sqrt(d_k)`：

- 点积的方差会随着维度 `d_k` 增大而变大。
- 如果不缩放，`QK^T` 的数值可能很大，softmax 会变得非常尖锐。
- softmax 过尖会导致梯度很小，训练不稳定。
- 除以 `sqrt(d_k)` 可以让 logits 分布更平稳。

时间复杂度：

- 序列长度为 `L`，隐藏维度为 `d`。
- 计算 `QK^T` 需要 `O(L^2 d)`。
- 注意力矩阵大小是 `L x L`，显存复杂度约为 `O(L^2)`。
- 这也是长上下文推理和训练成本高的核心原因。

面试表达：

> 我理解 Attention 不是“注意力”这个抽象词，而是一个可微的检索过程。Query 像查询，Key 像索引，Value 像被取出的内容。模型先算 Query 和所有 Key 的相似度，再用 softmax 归一化成权重，最后对 Value 加权求和。Scaling 是为了避免高维点积过大导致 softmax 饱和。

## 3. Self-Attention 和 Cross-Attention 有什么区别？

核心回答：

> Self-Attention 的 Q、K、V 来自同一段序列，用来建模序列内部关系；Cross-Attention 的 Q 通常来自当前生成端，K、V 来自外部输入或另一个模态，用来让当前序列对齐和读取外部信息。

详细对比：

| 维度 | Self-Attention | Cross-Attention |
|------|----------------|-----------------|
| Q 来源 | 当前序列 | 当前序列 |
| K/V 来源 | 当前序列 | 外部序列或另一个模态 |
| 作用 | 建模内部依赖 | 对齐外部信息 |
| 场景 | GPT 文本生成、编码上下文 | 翻译、图文对齐、多模态生成 |

例子：

- 文本续写中，“他”要关联前文的人名，这是 Self-Attention。
- 图文问答中，文本问题作为 Query，图片 patch 表示作为 Key/Value，这是 Cross-Attention 或类似跨模态融合。
- Encoder-Decoder 翻译中，Decoder 生成英文时读取 Encoder 的中文表示，这是 Cross-Attention。

面试表达：

> Self-Attention 解决的是“我这段序列内部哪些 token 互相关联”，Cross-Attention 解决的是“我当前生成时应该从另一段输入或另一种模态里取哪些信息”。所以多模态和 Encoder-Decoder 任务里 Cross-Attention 很常见。

## 4. 为什么要用 Multi-Head Attention？

核心回答：

> Multi-Head Attention 是把隐藏维度拆成多个子空间并行做 Attention，让不同头学习不同类型的关系。它比单头注意力表达能力更强，也能避免所有注意力都挤在一种相似度模式上。

详细展开：

- 单头注意力只有一种相似度空间，容易把多种关系混在一起。
- 多头可以并行关注不同信息：
  - 有的头关注局部语法。
  - 有的头关注长程指代。
  - 有的头关注格式、分隔符或代码结构。
  - 有的头在多模态任务里关注图像区域与文本词的对应关系。
- 每个头通常使用较小维度 `d_head = d_model / n_heads`，最后拼接再线性映射回 `d_model`。

面试表达：

> Multi-head 的价值不是简单堆参数，而是让模型在多个表示子空间里做信息选择。比如同一句话里既有语法关系、实体关系，也有长程依赖，多个 head 可以分别建模，最后再融合。

## 5. 如何降低 Transformer 的计算复杂度？常见稀疏注意力有哪些？

核心回答：

> Transformer 的瓶颈主要来自 Attention 的 `O(L^2)` 序列复杂度。降低复杂度的思路包括稀疏化注意力、滑动窗口、低秩近似、线性注意力、分块计算、FlashAttention 优化显存访问，以及通过检索或摘要减少实际输入长度。

常见方法：

| 方法 | 思路 | 代表场景 |
|------|------|----------|
| Sliding Window Attention | 每个 token 只看附近窗口 | 长文档、代码 |
| Global + Local Attention | 少数全局 token 看全局，其余看局部 | Longformer |
| Block Sparse Attention | 按块稀疏连接 | 超长序列 |
| Linformer | 假设注意力矩阵低秩，压缩 K/V 长度 | 长序列近似 |
| Performer | 用核函数近似 softmax attention | 线性注意力 |
| FlashAttention | 不改变数学结果，优化 IO 和显存访问 | 训练/推理加速 |
| RAG / 摘要压缩 | 不把所有文本塞进上下文，而是先筛选 | 知识问答、Agent |

面试表达：

> 如果从模型结构上看，可以把全量注意力改成局部、稀疏或低秩近似；如果从工程系统上看，可以用 FlashAttention、KV Cache、PagedAttention 这些优化；如果从应用层看，最有效的往往是不要把所有东西都塞给模型，而是先检索、重排、摘要。

## 6. KV Cache 是什么？为什么能提升推理速度？

核心回答：

> KV Cache 是在自回归生成中缓存历史 token 每一层的 Key 和 Value。生成下一个 token 时，只需要计算新 token 的 Q/K/V，并让新 token 的 Query 去 attend 过去缓存的 K/V，避免重复计算历史 token 的表示。

为什么有效：

- 自回归生成一次只新增一个 token。
- 如果没有 KV Cache，每生成一步都要重新计算整个前缀。
- 有 KV Cache 后，历史 K/V 可以复用。
- 单步计算从“重新处理全部上下文”变成“只处理新 token + 读取缓存”。

代价：

- KV Cache 会占显存。
- 显存大致与 `batch_size * seq_len * layer_num * head_num * head_dim * 2(K,V)` 成正比。
- 长上下文、高并发、多 batch 时，KV Cache 会成为推理服务的主要显存压力。

面试表达：

> KV Cache 本质是用空间换时间。它缓存每一层历史 token 的 K/V，下一步生成时不用重新算历史上下文，所以推理速度会明显提升。但它也会占用大量显存，所以 vLLM 的 PagedAttention 这类技术就是在优化 KV Cache 的显存管理。

## 7. 给定模型层数和隐藏层维度，如何估算参数量？如何估算 KV Cache 大小？

核心回答：

> 粗略估算 Transformer 参数量时，每层主要看 Attention 的 Q/K/V/O 四个投影和 FFN 的升降维矩阵。KV Cache 大小则主要看层数、序列长度、batch、KV head 数、head dim 和数据精度。

参数量粗估：

假设：

- `L`：层数
- `d`：hidden size
- `d_ff`：FFN 中间维度，常见约 `4d` 或 `8/3d`

每层大致参数：

```text
Attention: 4 * d * d
FFN: 2 * d * d_ff
每层约: 4d^2 + 2d*d_ff
总量约: L * (4d^2 + 2d*d_ff) + embedding
```

KV Cache 粗估：

```text
KV Cache bytes =
batch * seq_len * layers * kv_heads * head_dim * 2(K,V) * bytes_per_element
```

例子：

- FP16 / BF16 每个元素 2 bytes。
- 如果 GQA/MQA 减少 KV head 数，KV Cache 会显著下降。
- 同样上下文长度下，KV Cache 大小和 batch 成正比。

面试表达：

> 参数量主要和层数、隐藏维度平方、FFN 维度有关；KV Cache 主要和上下文长度、层数、batch、KV head 数有关。推理部署时，模型权重是固定显存，KV Cache 是随请求和上下文动态增长的显存。

## 8. MoE 架构的具体实现原理是什么？Router 是如何工作的？

核心回答：

> MoE 是把 FFN 层替换成多个专家网络，每个 token 只激活其中 Top-K 个专家，从而在增加总参数量的同时控制单次计算量。Router 负责根据 token 表示计算每个专家的概率，并选择最适合的专家处理该 token。

详细展开：

- MoE 通常不替换 Attention，而是替换或扩展 FFN。
- Router 输入 token hidden state，输出对每个 expert 的打分。
- 通过 softmax 得到专家概率。
- 选择 Top-1 或 Top-2 expert。
- token 被分发到对应 expert 计算。
- expert 输出按 router 权重加权合并。

优点：

- 总参数量大，容量强。
- 每个 token 只激活少数专家，计算成本相对可控。
- 不同专家可学习不同类型知识或能力。

挑战：

- 负载均衡：不能让所有 token 都挤到少数专家。
- 通信开销：多卡训练/推理时 token dispatch 成本高。
- 训练稳定性：Router 可能塌缩，需要 auxiliary loss。
- 部署复杂度高于 Dense 模型。

MoE vs Dense：

> 同等激活参数下，MoE 往往有更大知识容量；同等总参数下，Dense 每次用全量参数，MoE 只激活部分参数。MoE 的优势是效率和容量，劣势是路由、通信和稳定性更复杂。

## 9. 长上下文对话中为什么容易信息遗忘？有哪些缓解机制？

核心回答：

> 长上下文“遗忘”不一定是模型真的没有看到，而是注意力分布、位置泛化、上下文噪声和检索竞争导致关键信息没有被有效利用。缓解方式包括摘要压缩、显式记忆、RAG、重要信息置顶、结构化状态、时间衰减和分层上下文管理。

原因：

- **位置衰减**：模型对很早位置的信息利用能力下降。
- **Lost in the Middle**：长文本中间的信息最容易被忽略。
- **噪声竞争**：上下文越长，无关信息越多，关键信息被稀释。
- **训练长度限制**：模型训练时不一定见过极长输入。
- **任务状态缺失**：对话里隐含状态多，但没有结构化维护。

缓解：

- 把关键信息写入结构化 state，而不是只依赖聊天历史。
- 长对话定期摘要，保留目标、约束、已决策、待办。
- 对长期事实进入向量库或数据库，按需检索。
- 对最近几轮保留原文，远期内容保留摘要。
- 对重要约束放在 prompt 靠前位置或单独系统指令中。
- 使用 Rerank、MMR、时间衰减减少旧信息干扰。

面试表达：

> 长上下文不是越长越好，因为模型会受到上下文噪声和位置偏置影响。Agent 系统里我更倾向于把对话历史拆成短期窗口、长期记忆和结构化状态三层，生成前再动态选择相关内容，而不是把所有历史直接塞进去。

## 10. 面对极长序列 Attention 的 `O(L^2)` 问题，目前有哪些主流解决方案？

核心回答：

> 主流方案分为模型结构优化、系统优化和应用层压缩三类。模型结构上用稀疏/线性/局部注意力，系统上用 FlashAttention、PagedAttention、KV Cache 管理，应用层用 RAG、摘要和层级记忆减少输入长度。

更完整回答：

1. **训练/推理算子优化**
   - FlashAttention 减少 HBM 读写，不改变 Attention 结果。
   - PagedAttention 用分页思想管理 KV Cache，提高显存利用率。

2. **注意力模式优化**
   - Sliding window 只看局部窗口。
   - Global token 负责全局信息汇聚。
   - Block sparse 限制注意力连接。
   - Linear attention 用核技巧近似。

3. **上下文组织优化**
   - 用 RAG 找最相关片段。
   - 用摘要压缩历史。
   - 用状态机维护任务状态。
   - 对文档做分层索引和章节级召回。

面试表达：

> 真正落地时我不会只从模型结构看这个问题。长上下文系统通常要模型、推理框架和应用层一起做优化：底层用 FlashAttention / KV Cache 管理，上层用检索和摘要控制输入质量。

## 11. 模型生成过程中出现循环、重复回答，有哪些解决办法？

核心回答：

> 重复生成可能来自解码策略、训练数据、prompt 约束或模型状态退化。解决方式包括调整 decoding 参数、加入 repetition penalty、清洗重复数据、改 prompt 终止条件、加入停止词、限制最大步数，以及在 Agent 中做输出检测和重试。

可落地方法：

- **解码参数**
  - 降低 temperature，减少随机跑偏。
  - 调整 top_p / top_k。
  - 使用 repetition penalty。
  - 使用 no-repeat ngram 限制。

- **Prompt 和停止条件**
  - 明确回答格式和结束标记。
  - 设置 stop sequence。
  - 避免让模型“继续补充直到完整”这类模糊指令。

- **数据层**
  - 清洗训练集中重复段落。
  - 减少模板化、循环式样本。
  - 对长链路任务增加正确终止样本。

- **系统层**
  - 检测重复 ngram 比例。
  - 超过阈值自动截断或重试。
  - Agent 多步执行时设置最大迭代次数。

面试表达：

> 我会先判断是解码问题还是任务控制问题。如果是普通生成，先调 repetition penalty、stop words 和采样参数；如果是 Agent 循环调用工具，就要加最大步数、状态检查和反思终止条件。

## 12. Decoder-only 模型在分类任务上可能比 Encoder-only 做得好吗？

核心回答：

> 有可能，但不是结构天然更适合分类，而是大规模预训练、指令微调和上下文学习能力带来的优势。Encoder-only 模型在纯分类和表征任务上仍然高效稳定，Decoder-only 更适合需要任务泛化、少样本提示、解释生成或多任务统一接口的场景。

对比：

| 维度 | Encoder-only | Decoder-only |
|------|--------------|--------------|
| 代表 | BERT、RoBERTa | GPT、LLaMA、Qwen |
| 优势 | 双向编码，分类高效 | 生成能力强，指令跟随好 |
| 分类方式 | `[CLS]` 表征接分类头 | prompt 后生成类别 token |
| 部署成本 | 通常更低 | 通常更高 |
| 适合 | 固定标签、低延迟分类 | 泛化分类、复杂解释、多任务 |

面试表达：

> 如果只是固定标签分类，Encoder-only 仍然很划算。但如果业务里分类标准经常变化，或者需要模型解释原因、处理开放式标签，Decoder-only 大模型会更有优势。

## 13. 如果关闭模型 think 模式，但 prompt 里仍写 `<think>...</think>` 会怎样？

核心回答：

> 这取决于模型服务端如何实现 think 模式。如果 think 是服务端控制的隐藏推理通道，关闭后 prompt 中的 `<think>` 只是普通文本，模型可能模仿格式输出，但不代表真的启用了隐藏推理。如果模型训练中见过这类标签，它可能被诱导生成类似推理内容，但行为不稳定。

回答要点：

- `<think>` 本身不是魔法开关。
- 真正的 reasoning mode 通常由模型版本、服务端参数或系统策略控制。
- prompt 中写标签可能影响输出风格。
- 如果业务要求不暴露推理过程，应在服务层过滤或禁用相关输出。
- 不能依赖用户 prompt 来稳定控制模型内部推理模式。

面试表达：

> 我会把它理解为控制平面和文本平面的区别。服务端关闭 think 后，prompt 里的标签只是输入文本，最多诱导模型模仿推理格式，但不能等价于打开真实 reasoning 模式。

## 附录 A：大模型基础高频题超详细知识点

### A1. Transformer 结构图可以怎么讲

<details>
<summary>展开：Transformer 的完整数据流</summary>

```text
Token IDs
  -> Token Embedding
  -> Position Encoding / RoPE
  -> [Transformer Block] x N
       -> Multi-Head Attention
       -> Residual + LayerNorm
       -> Feed Forward Network
       -> Residual + LayerNorm
  -> LM Head
  -> logits
  -> softmax
  -> next token
```

</details>

面试时可以这样扩展：

- **为什么不用 RNN**：RNN 顺序计算，长距离依赖容易衰减，难并行；Transformer 用 self-attention 直接建立 token 间关系。
- **为什么需要位置编码**：Attention 只看向量相似度，不知道 token 顺序，所以必须注入位置信息。
- **为什么 Decoder-only 能做对话**：它本质是条件语言模型，每轮对话都被拼成上下文，然后预测下一个 token。
- **为什么大模型多用 Pre-LN**：深层训练更稳定，梯度更容易传。

### A2. Attention 公式的逐步推导

公式：

```text
Q = XWq
K = XWk
V = XWv
S = QK^T / sqrt(d_k)
A = softmax(S)
O = AV
```

解释：

- `Q`：当前位置想查什么。
- `K`：每个位置能提供什么索引。
- `V`：每个位置真正携带的信息。
- `QK^T`：每个 token 对所有 token 的相关性。
- `softmax`：把相关性归一化成权重。
- `AV`：按权重聚合信息。

面试官如果继续问“数学本质是什么”，可以说：

> Attention 是一次内容寻址的加权平均。它用内积计算 query 与 key 的相似度，再用 softmax 得到概率分布，最后对 value 做期望求和。

### A3. 为什么 Attention 要 Scaling

如果 `q` 和 `k` 的每个维度均值为 0、方差为 1，那么点积：

```text
q · k = \sum_{i=1}^{d_k} q_i k_i
```

它的方差大约会随着 `d_k` 增大而增大。维度越高，`QK^T` 的值越容易变大，softmax 越容易饱和。

饱和的后果：

- 最大值接近 1，其它值接近 0。
- 梯度变小。
- 训练不稳定。

所以用：

```text
QK^T / sqrt(d_k)
```

把分布拉回更稳定的尺度。

### A4. Multi-Head Attention 为什么不是简单重复

多头不是“算很多遍同样的注意力”，而是把隐藏维度拆成多个子空间：

```text
d_model = num_heads * d_head
```

每个 head 学到不同关系：

| Head 类型 | 可能关注内容 |
|----------|--------------|
| 局部语法头 | 相邻 token、短语结构 |
| 指代头 | “他/它/这个”指向谁 |
| 分隔符头 | 代码括号、Markdown 标题、JSON 边界 |
| 长程依赖头 | 前文约束、全局主题 |

更高级的回答：

> Multi-head 的价值是把单一注意力分布拆成多个表示子空间，允许模型同时建模多种关系。如果只用一个头，所有关系会竞争同一套注意力权重。

### A5. KV Cache 的显存估算

公式：

```text
KV cache bytes =
batch_size * seq_len * num_layers * num_kv_heads * head_dim * 2 * bytes_per_element
```

其中：

- `2` 表示 K 和 V。
- FP16/BF16 一般是 2 bytes。
- MQA/GQA 会减少 `num_kv_heads`，显著降低缓存。

面试追问可以补：

- Prefill 阶段：一次性处理 prompt。
- Decode 阶段：每次生成一个 token，复用历史 KV。
- 长上下文推理瓶颈通常不是模型权重，而是 KV Cache 动态增长。

### A6. MoE 的 Router 细节

MoE 常见流程：

```text
h_t -> router(h_t) -> expert scores -> top-k experts -> expert outputs -> weighted sum
```

Router 输出：

```text
p_i = softmax(W_r h_t)_i
```

选择 Top-K：

```text
E = TopK(p_i)
```

最终输出：

```text
y_t = \sum_{i in E} p_i * Expert_i(h_t)
```

面试官常追问“MoE 为什么难部署”：

- Token dispatch 带来跨卡通信。
- Expert 负载不均衡会导致部分卡拥塞。
- Router 容易塌缩到少数 expert。
- 推理服务要处理动态路由和批处理。

### A7. 长上下文为什么仍然需要 RAG

即使上下文窗口变大，RAG 仍然有价值：

- **成本**：长上下文推理更贵。
- **噪声**：上下文越长，无关信息越多。
- **更新**：RAG 可以读最新知识，模型参数不能实时更新。
- **可溯源**：RAG 可以给出引用证据。
- **权限**：不同用户能检索的知识不同。

面试表达：

> 长上下文解决“放得下”，RAG 解决“找得准、可更新、可溯源”。两者不是替代关系，而是互补关系。

### A8. 重复生成问题的定位表

| 现象 | 可能原因 | 解决方式 |
|------|----------|----------|
| 不断重复同一句 | repetition penalty 不够、采样参数不稳 | 调整 penalty、top_p、temperature |
| Agent 不断调用同一工具 | 缺少终止条件 | 加最大步数、状态检查 |
| 输出很长但没信息 | prompt 要求不清 | 明确格式和长度 |
| 格式循环 | 训练数据模板重复 | 清洗数据、补多样样本 |
