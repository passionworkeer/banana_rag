# RAG 检索增强生成的本质

## 核心论点

RAG(Retrieval-Augmented Generation)是一种把外部知识库接入大语言模型推理流程的工程模式:用户提问 → 把问题向量化 → 在向量库中找最相似的若干片段 → 把这些片段作为上下文一起喂给 LLM → LLM 生成答案。它要解决 LLM 自身的两个固有限制:一是知识截止在训练数据上,无法获得最新信息;二是企业私有资料无法直接进入模型权重,数据主权和合规要求必须保证"数据不出库"。RAG 在生成阶段把摘要级切片喂给 LLM,从而同时满足时效性和私有性。

工业落地中,传统 RAG 经常跑通但效果不理想,主因有三:向量相似不等于语义相关,检索到的片段可能和用户意图无关,导致 LLM 基于错误上下文"一本正经胡说八道";用户提问往往模糊,缺失上下文,RAG 把模糊问题直接拿去检索,结果跑偏;复杂问题需要多步拆解,而 RAG 是单次流程,无法支持。新一代方向是 Agentic RAG:让 LLM 智能体在检索前先重写问题、规划检索路径,再走传统 RAG 流程,本质上是把 RAG 从"单步管道"升级为"带规划的智能体调用"。
